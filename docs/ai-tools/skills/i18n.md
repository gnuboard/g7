# 다국어 키 추출·언어팩 동기화 (i18n)

## 언제

- `/i18n extract <레이아웃 경로>` — 레이아웃을 작성·수정한 뒤, 사용된 `$t:` 키와 언어 파일(ko/en + 같은 디렉토리의 추가 로케일)을 대조해 누락·미사용·네임스페이스 오류를 보고할 때. **키를 고치는 지점은 소스 `.g7.html` 이고 짝 `.json` 은 `php artisan layout:decompile <경로> --sync` 굽기 산출이다** — 짝만 고치면 다음 굽기에 소실된다.
- `/i18n sync [pkgId|--locale=xx]` — `lang/{ko,en}/**` 또는 확장의 `lang/ko/**`·`lang/partial/ko/**` 수정 후, `module.json`/`plugin.json`/`template.json`/`config/app.php` 의 `version` 변경 후, `lang-packs/_bundled/**` 자체 수정 후, 신규 로케일 추가(`build-language-pack-{locale}.cjs` 신설) 직후.
- 역할 분담: `/validate i18n` 은 코어/확장 ko·en 원본 파일 자체(PHP/JSON 구조, `__()` 사용)를 검증하고, `/i18n sync` 는 `lang-packs/_bundled/**` 파생 패키지의 정합성을 다룬다.

## 입력

| 부명령 | 인자 | 처리 |
| --- | --- | --- |
| extract | 레이아웃 디렉토리 또는 단일 레이아웃 경로(`.g7.html` / 짝 `.json`) | 미지정이면 대상 경로를 사용자에게 문의 |
| sync | 없음 / `g7-core-ja` 같은 pkgId / `--locale=ja` | 없음이면 번들 패키지 전부 검사 |

- extract 대상 경로 유형과 언어 파일 위치

  | 경로 | 언어 파일 |
  | --- | --- |
  | `modules/_bundled/{id}/resources/layouts/**/*.{g7.html,json}` | `modules/_bundled/{id}/resources/lang/*.json` |
  | `plugins/_bundled/{id}/resources/layouts/**/*.{g7.html,json}` | `plugins/_bundled/{id}/resources/lang/*.json` |
  | `templates/_bundled/{id}/layouts/**/*.{g7.html,json}` | `templates/_bundled/{id}/lang/*.json` |
  | `resources/layouts/**/*.{g7.html,json}` | `lang/*.json` |

  활성 디렉토리(`modules/{id}` 등)의 사본도 같은 상대 구조다. 두 확장자는 같은 레이아웃의 소스(`.g7.html`)와 굽기 산출(`.json`) 이며 `$t:` 는 정규식 추출이라 동일 처리된다 — **수정 지점은 언제나 `.g7.html`**.
- sync 빌더는 `ANTHROPIC_API_KEY` 환경변수가 필요하다(PowerShell: `$env:ANTHROPIC_API_KEY="..."`).
- 규정: language-pack-rules.md, [module-i18n.md](../../extension/module-i18n.md), [database-guide.md](../../database-guide.md) 다국어 절.

## 절차

### extract

1. 대상 레이아웃 파일(`.g7.html` + 짝 `.json`)을 수집한다 — 메인 레이아웃, `partials/`, 중첩 디렉토리 전부. `_bundled` 도 대상이다.
2. `$t:namespace.key.path` 와 `$t:defer:namespace.key.path` 를 모두 추출하고 네임스페이스별(모듈 전용 `{id}.*`, `common.*`, `messages.*`, `currency.*`, `validation.*`)로 분류한다.
3. 모듈·플러그인 레이아웃의 키가 해당 확장 식별자로 시작하는지 검증한다. `$t:common.save` 처럼 코어 키를 직접 참조하면 경고하고, 의도적 참조는 명시적으로 확인받는다.
4. 언어 파일의 중첩 키 경로를 전개해 사용 키와 비교한다 — 누락 = 사용 − 존재, 미사용 = 존재 − 사용. ko 만 보지 않고 en 과 같은 디렉토리의 추가 로케일을 각각 비교한다.
5. 보고서(추출 대상·키 요약·언어 파일 현황·누락 키 표·미사용 키)와 누락 키의 ko/en JSON 템플릿을 제시한다. 같은 도메인의 연관 레이아웃과 번들 언어팩 동기화 누락까지 함께 보고한다. 패턴·정규식·보고 양식·스크립트는 references/extract.md(아래 「extract」 절).

### sync

2. issue type 별로 조치한다 — 누락 키만 있으면 증분 빌드, 잉여 키가 있으면 `--force` 재빌드, 버전 incompat 이면 `language-pack.json` 갱신 + 패치 bump + CHANGELOG. 세 축(키/manifest/버전) 중 하나만 맞추고 통과를 단정하지 않는다. 명령·양식은 references/sync.md(아래 「sync」 절).

## 완료 조건

- extract: 대상 경로의 모든 레이아웃 파일(`.g7.html` + 짝 `.json`)이 검사됐고, 전 로케일의 누락 키가 사용 위치와 함께 표로 보고됐으며, 네임스페이스 위반이 목록화됐고, 누락 키 템플릿이 제시됐다.
- sync: 검사 스크립트 exit 0. 코어 키 변경이면 번들 로케일까지, manifest 변경이면 package/composer/CHANGELOG 파생 산출물까지 갱신됐다.
- 두 부명령 모두 record 에 검사 범위(경로·패키지)와 남은 항목을 남긴다.

## 참조

## extract

레이아웃 파일(소스 SSoT `.g7.html` + 런타임 계약 `.json`)에서 사용된 다국어 키를 추출하고 언어 파일과 비교해 누락된 키를 보고하는 세부 절차다.
`$t:` 는 정규식 추출이라 두 포맷을 동일 처리한다 — 하네스 `check-i18n-keys.cjs` 의 `findJsonFiles` 와 같은 규약이다.

### 대상 경로

| 경로 패턴 | 유형 | 언어 파일 위치 |
| --- | --- | --- |
| `modules/**/resources/layouts/**/*.{json,g7.html}` | 모듈 레이아웃 | `modules/**/resources/lang/*.json` |
| `templates/**/layouts/**/*.{json,g7.html}` | 템플릿 레이아웃 | `templates/**/lang/*.json` |
| `plugins/**/resources/layouts/**/*.{json,g7.html}` | 플러그인 레이아웃(`admin/plugin_settings`) | `plugins/**/resources/lang/*.json` |
| `(templates\|modules\|plugins)/**/extensions/**/*.{json,g7.html}` | 확장 주입 fragment | 주입 대상 확장의 `lang/*.json` |
| `resources/layouts/**/*.{json,g7.html}` | 코어 레이아웃 | `lang/{ko,en}.json` (+ `lang/partial/{ko,en}/*.json`) |

> **엔트리 + partial 분할 구조**: 코어와 확장(board·ecommerce·page·두 템플릿)의 프론트엔드 언어 파일은 `{ko,en}.json` 이 얇은 **엔트리**이고 실제 키는 `"$partial": "partial/ko/xxx.json"` 으로 분할돼 있다. 엔트리만 읽으면 분할된 키가 전부 "누락" 으로 잡히므로, 키 존재 확인은 반드시 `$partial` 을 해석한 뒤에 한다(`check-i18n-keys.cjs` 가 재귀 해석한다).

### 추출 패턴

| 패턴 | 설명 | 예시 |
| --- | --- | --- |
| `$t:namespace.key.path` | 즉시 번역 | `$t:sirsoft-ecommerce.admin.product.name` |
| `$t:defer:namespace.key.path` | 지연 번역 | `$t:defer:common.save` |

```javascript
// $t: 패턴 추출 (defer 포함)
const regex = /\$t:(?:defer:)?([a-zA-Z][a-zA-Z0-9_.-]*(?:\.[a-zA-Z0-9_-]+)+)/g;
```

동적 파라미터는 `textParams` 가 아니라 파이프 문법이고 `cellChildren` 안의 row 참조는 `$t:defer:` 가 필수다(i18n-pipe-syntax).

### 키 분류

| 키 패턴 | 분류 | 저장 위치 |
| --- | --- | --- |
| `{id}.*` (예: `sirsoft-ecommerce.*`) | 확장 전용 | `modules/_bundled/{id}/resources/lang/*.json` |
| `common.*`, `messages.*`, `currency.*`, `validation.*` | 공통 | 코어 `lang/*.json` 또는 확장 lang 파일 |

### 네임스페이스 검증

모듈·플러그인 레이아웃의 다국어 키는 확장 식별자 접두사를 포함해야 한다.

| 금지 | 올바른 사용 |
| --- | --- |
| `$t:common.save` (코어 키 직접 참조) | `$t:sirsoft-ecommerce.common.save` |
| `$t:admin.product.name` (네임스페이스 누락) | `$t:sirsoft-ecommerce.admin.product.name` |

- 확장 레이아웃의 `$t:` 키가 해당 식별자로 시작하는지 확인한다.
- `$t:common.*` 형태의 코어 키 직접 참조는 경고한다(확장 lang 이 아닌 코어 lang 에서 찾게 된다). 의도적 참조는 명시적 확인이 필요하다.
- `G7Core.t()` 는 키를 못 찾으면 키 문자열을 돌려주므로 `??` 폴백이 발동하지 않는다(t-key-fallback-is-not-a-fallback) — 누락 키는 화면에 그대로 노출된다.

### 언어 파일 키 전개

```javascript
// 중첩된 객체에서 키 경로 추출
function extractKeys(obj, prefix = '') {
  const keys = [];
  for (const [key, value] of Object.entries(obj)) {
    const path = prefix ? `${prefix}.${key}` : key;
    if (typeof value === 'object' && value !== null) {
      keys.push(...extractKeys(value, path));
    } else {
      keys.push(path);
    }
  }
  return keys;
}
```

`$partial` 디렉티브가 있으면 그 파일을 먼저 읽어 합친 뒤 위 전개를 돌린다 — 엔트리만 전개하면 분할 키가 전부 누락으로 잡힌다.

비교: 누락 키 = 사용된 키 − 존재하는 키, 미사용 키(참고) = 존재하는 키 − 사용된 키. ko/en 과 같은 디렉토리의 추가 로케일(ja 등)을 각각 비교한다.

### 추출 스크립트 (참고)

#### Node.js 추출 스크립트 예시

```javascript
const fs = require('fs');
const path = require('path');

// 디렉토리 내 모든 JSON 파일 찾기
function findJsonFiles(dir, files = []) {
  const items = fs.readdirSync(dir);
  for (const item of items) {
    const fullPath = path.join(dir, item);
    if (fs.statSync(fullPath).isDirectory()) {
      findJsonFiles(fullPath, files);
    } else if (item.endsWith('.json')) {
      files.push(fullPath);
    }
  }
  return files;
}

// $t: 키 추출
function extractI18nKeys(content) {
  const regex = /\$t:(?:defer:)?([a-zA-Z][a-zA-Z0-9_.-]*(?:\.[a-zA-Z0-9_-]+)+)/g;
  const keys = new Set();
  let match;
  while ((match = regex.exec(content)) !== null) {
    keys.add(match[1]);
  }
  return keys;
}

// JSON에서 키 경로 추출
function extractExistingKeys(obj, prefix = '', namespace = '') {
  const keys = new Set();
  for (const [key, value] of Object.entries(obj)) {
    const path = prefix ? `${prefix}.${key}` : key;
    const fullPath = namespace ? `${namespace}.${path}` : path;
    if (typeof value === 'object' && value !== null) {
      const childKeys = extractExistingKeys(value, path, namespace);
      childKeys.forEach(k => keys.add(k));
    } else {
      keys.add(fullPath);
    }
  }
  return keys;
}

// 메인 실행
const layoutDir = process.argv[2] || 'modules/sirsoft-ecommerce/resources/layouts';
const langDir = process.argv[3] || 'modules/sirsoft-ecommerce/resources/lang';
const namespace = process.argv[4] || 'sirsoft-ecommerce';

// 레이아웃에서 사용된 키 추출
const layoutFiles = findJsonFiles(layoutDir);
const usedKeys = new Set();
for (const file of layoutFiles) {
  const content = fs.readFileSync(file, 'utf-8');
  const keys = extractI18nKeys(content);
  keys.forEach(k => usedKeys.add(k));
}

// 필수 ko/en과 같은 디렉토리의 추가 로케일을 각각 비교한다.
const locales = new Set(['ko.json', 'en.json', ...fs.readdirSync(langDir).filter(f => f.endsWith('.json'))]);
for (const localeFile of locales) {
  const languagePath = path.join(langDir, localeFile);
  if (!fs.existsSync(languagePath)) {
    console.log(`${localeFile}: 언어 파일 누락`);
    continue;
  }
  const language = JSON.parse(fs.readFileSync(languagePath, 'utf-8'));
  const existingKeys = extractExistingKeys(language, '', namespace);
  const missingKeys = [...usedKeys].filter(k => !existingKeys.has(k));
  const unusedKeys = [...existingKeys].filter(k => !usedKeys.has(k));
  console.log(`=== ${localeFile} 다국어 키 추출 결과 ===`);
  console.log(`사용된 키: ${usedKeys.size}개 / 존재하는 키: ${existingKeys.size}개`);
  console.log(`누락된 키: ${missingKeys.length}개 / 미사용 키: ${unusedKeys.length}개`);
  missingKeys.sort().forEach(k => console.log(k));
}
```

## sync

`lang-packs/_bundled/g7-{scope}-{target}-{locale}/` 번들 언어팩과 코어/확장 원본 사이의 정합성을 점검·복원한다. 키 누락, manifest drift, 호스트 버전 cascade 세 종류의 어긋남을 한 진입점에서 진단하고 조치까지 한다.

### 인자

```bash
/i18n sync                    # 번들 패키지 전부 검사
/i18n sync g7-core-ja         # 단일 패키지
/i18n sync --locale=ja        # ja 로케일 전체
```

### 1단계: 정합성 검사

```bash
## 키/버전 정합성 (ko 원본 ⇔ 번들 locale + g7_version/target_version 호환성)
```

| Issue Type | 의미 | 1차 조치 |
| --- | --- | --- |
| `key-mismatch` | ko 원본과 번들 locale 의 키 셋이 다름 | 빌더로 누락 키 보충 |
| `ja-file-missing` | ko 원본에는 있는 파일이 번들에 없음 | 빌더 재실행 |
| `g7-version-incompat` | `g7_version` 이 현재 코어와 호환 불가 | manifest 갱신 + 패치 bump |
| `target-version-incompat` | `requires.target_version` 이 호스트 manifest 와 호환 불가 | manifest 갱신 + 패치 bump |

### 2단계: 분기별 조치

#### A. 누락 키만 있음 (`key-mismatch.missing > 0`)

증분 동기화 모드로 누락 키만 번역한다. `--force` 없이 실행하면 기존 번역은 보존되고 새 키만 채워진다.

`ANTHROPIC_API_KEY` 환경변수가 필요하다. PowerShell: `$env:ANTHROPIC_API_KEY="sk-ant-..."`.

#### B. 잉여 키 있음 (`key-mismatch.extra > 0`)

ko 에서 키가 제거됐지만 번들에는 남아 있는 상태다. `--force` 로 전체 재빌드한다.

#### C. 버전 incompat (`g7-version-incompat` / `target-version-incompat`)

`language-pack.json` 의 `g7_version`(top-level) / `requires.target_version` 을 갱신하고 패치 bump 후 CHANGELOG 항목을 추가한다.

```jsonc
{
  "version": "1.0.1",                    // 패치 bump
  "g7_version": ">=7.0.0-beta.5",         // 코어 새 버전 (top-level)
  "requires": {
    "target_version": ">=1.2.0"           // 호스트 새 버전 (해당 시)
  }
}
markdown
### [1.0.1] - 2026-04-28

#### Changed
- g7_version 을 >=7.0.0-beta.5 로 상향
```

### 3단계: 검증

조치 후 다음 명령이 exit 0 으로 끝나야 한다.

### 파생 산출물 전수 갱신

한 변경이 파생하는 산출물을 함께 동기화한다 — 코어 키를 바꾸면 번들 ja 등 모든 로케일, manifest 를 올리면 package/composer/CHANGELOG. 세 종류(키/manifest/버전) 중 한 축만 맞추고 통과를 단정하지 않는다.
