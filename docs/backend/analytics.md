# 방문자 통계

> 코어가 방문·페이지뷰·유입·환경을 직접 기록하고 집계합니다. 외부 분석 도구 없이
> 동작하며 방문 데이터는 사이트 안에만 남습니다.

---

## TL;DR (5초 요약)

```text
1. 세 경로(브라우저 비콘·서버 폴백·내부 검색 훅)가 하나의 적재 파이프라인으로 모인다
2. 개인정보 수집 수준은 세 모드(IP 저장 / 동의 연동 / 익명) 중 운영자가 고른다
3. 수집 실패는 절대 화면에 드러나지 않는다 — 대신 실패 로그와 제외 카운터에 남는다
4. 원장은 보존일이 지나면 지워지고, 일 단위 집계는 영구 보존된다
5. 업데이트 직후부터 「IP 저장」 모드로 수집이 시작되며 언제든 끌 수 있다
6. 확장은 전환(목표)·분류 기준을 **먼저 선언**해야 기록할 수 있다 — 선언 밖의 값은 버리고 사유를 남긴다
```

## 수집 경로

| 경로 | 언제 | 왜 필요한가 |
| --- | --- | --- |
| 브라우저 비콘 | 화면을 열거나 이동할 때 | G7 은 SPA 라 서버 로그로는 페이지뷰가 방문당 1건으로만 찍힌다 |
| 서버 폴백 | SPA 셸 요청을 받을 때 | 자바스크립트가 막힌 환경의 방문자가 통계에서 통째로 사라지지 않게 한다 |
| 내부 검색 훅 | 사이트 검색 응답 직전 | 검색 결과 건수는 서버만 아는 값이라 비콘으로 남길 수 없다 |

서버 폴백과 첫 비콘이 같은 페이지를 알리면 **같은 행을 채웁니다**. 두 경로가 각자
행을 만들면 페이지뷰가 두 배가 되기 때문입니다. 판정은 「같은 방문 · 같은 주소 ·
60초 이내」입니다.

두 경로의 **신원이 어긋나는 전체 로드**도 있습니다. 문서 요청은 웹 세션을, 비콘은 API 토큰을
싣는데 둘의 수명이 다르면(기본 세션 120분 · 토큰 30분) 한쪽만 로그인 상태로 보입니다. 그러면
서버는 페이지를 그 신원의 열린 방문에 적고, 첫 비콘은 다른 신원이라 새 방문을 엽니다. 이때
첫 비콘은 이어받지 않은 방문의 **마지막 액션이 같은 주소 · 제목 없음 · 60초 이내**면 이 로드의
서버 자리표시로 보고 거둡니다(그 방문의 카운터·이탈 페이지도 되돌림). 화면에 보이는 신원은
비콘 쪽이므로 페이지뷰는 비콘 쪽 방문에 한 번만 남습니다. 제목이 있는 기록은 비콘이 남긴
실제 열람이라 건드리지 않습니다.

첫 비콘은 방문 행도 함께 채웁니다 — 문서 요청에는 화면 해상도가 없고, 보던 로케일은
서버가 요청 헤더로 짐작한 값이며, 유입 주소가 빠져 있을 수 있습니다. 브라우저가 알린
값으로 그 자리를 채우고 방문의 출처를 `beacon` 으로 바꿉니다. 그래서 `server_only_visits`
(서버 폴백만 남은 방문)는 **자바스크립트가 끝내 오지 않은 방문**만 셉니다.

## 방문을 묶는 규칙

방문 1건은 「같은 방문자 키의 활동이 끊기지 않고 이어진 구간」입니다. 마지막 활동에서
`analytics.visit_timeout_minutes`(기본 30분)가 지나면 다음 요청은 새 방문이 됩니다.

동시 요청이 방문을 두 개로 쪼개지 않도록, 열린 방문을 찾을 때 그 행을 잠급니다.
탭을 여러 개 연 방문자가 방문 수를 부풀리는 일을 막는 장치입니다.

방문 도중 **로그인·로그아웃하면 그 지점에서 방문이 갈립니다**. 회원 번호가 달라진 뒤의
활동을 앞 구간에 이어 붙이면, 게스트로 들어와 로그인한 관리자의 열람이 게스트 방문으로
남아 「관리자 제외」로 빠지지 않습니다. 방문자 키(쿠키)는 그대로라 같은 사람의 두 방문으로
이어 볼 수 있습니다.

방문자 쿠키(`g7_vid`)는 **암호화하지 않고** 심습니다. 수집 API 는 쿠키를 암호화하는
미들웨어를 지나지 않는데, 화면 요청 쪽은 그 값을 복호화하려다 실패해 쿠키가 없는 것으로
봅니다. 그러면 재방문자의 서버 폴백이 임시 키로 방문을 따로 열어 전체 로드마다 방문이
둘로 갈립니다. 담긴 값은 뜻 없는 난수입니다.

방문의 **진입·이탈 페이지는 페이지뷰로만** 정합니다. 내려받기·검색·외부 링크·이벤트는 방문 안의
행동일 뿐이라 그 이름(파일명·검색어)을 실으면 이탈 페이지 리포트와 실시간 화면의 「보고 있는
페이지」에 파일 이름이 뜹니다. 페이지뷰 없이 시작한 방문(검색 훅이 먼저 닿은 경우 등)은 첫
페이지뷰가 올 때 진입 페이지를 얻고, 끝내 페이지뷰가 없으면 진입·이탈 페이지 리포트에 잡히지
않습니다.

## 개인정보 모드

| 모드 | 방문자 키 | IP | 쿠키 | 재방문 지표 |
| --- | --- | --- | --- | --- |
| **full**(IP 저장) | 브라우저 쿠키 | 설정한 만큼 마스킹해 저장 | 발급 | 집계함 |
| **consent**(동의 연동) | 동의 시 쿠키 | 동의 시 마스킹 저장 | 동의 시 발급 | 동의자만 |
| **anonymous**(익명) | 일자별 해시 | 저장하지 않음 | 없음 | 집계 불가 |

모드와 아래 장치들의 on/off 는 **운영자 재량**입니다. 어느 수준으로 모을지, 그에
따르는 **법적 리스크는 운영자 몫**이며 코어는 세 모드와 장치를 제공할 뿐 어느 쪽이
운영 사이트에 적법한지 판단하지 않습니다.

### 익명 모드의 방문자 키

방문 환경(IP·운영체제·브라우저·언어)과 **그날의 임의 솔트**를 섞어 만든
해시입니다. 언어는 요청의 선호 언어 헤더(`Accept-Language`) 첫 항목의 기본 언어(`ko-KR` →
`ko`)만 씁니다 — 브라우저 비콘과 서버가 직접 기록하는 요청(로그인·회원가입 전환, 스크립트 전
첫 페이지)이 똑같이 가진 값이 이것뿐이라, 같은 사람이 두 키로 갈리지 않게 하기 위해서입니다.
방문에 저장되어 리포트에 보이는 브라우저 언어는 브라우저가 알린 설정 언어 그대로입니다. 솔트는 날마다 새로 만들어지고 며칠 뒤 지워집니다. 그래서 어제의 키와
오늘의 키를 이어 붙일 방법이 원리적으로 없고, 같은 사람을 여러 날에 걸쳐 따라가는
일이 불가능합니다 — 그것이 이 모드의 목적입니다. 대신 재방문 여부를 셀 수 없습니다.

### 동의 관리 플러그인이 쿠키를 막을 때

동의 관리 플러그인(`sirsoft-gdpr`)이 켜진 사이트에서는 방문자가 **기능 쿠키에 동의하기
전까지** 응답의 `Set-Cookie` 가 제거됩니다(EDPB 사전 차단). 그러면 IP 저장 모드라도 방문자
쿠키가 브라우저에 남지 않아 비콘마다 새 방문자 키가 생기고, 한 사람의 이동이 방문 여러
건으로 흩어져 **방문·순방문자가 페이지뷰만큼 부풀고 이탈률이 100% 에 붙습니다**.

그래서 이 조합에서는 **방문자마다** 가릅니다. 분석·기능 쿠키에 **모두 동의한** 방문자는 IP 저장
모드 그대로(IP·방문자 쿠키, 재방문 판정) 모으고, 그렇지 않은 방문자는 **익명 모드**(IP 없음, 일자
회전 해시)로 모읍니다. 기능 동의까지 보는 이유는 그 동의 전에는 플러그인이 방문자 쿠키를 지워,
쿠키 방식으로 세면 위의 부풀림이 그대로 생기기 때문입니다. 동의 여부는 플러그인에 요청마다 묻습니다.

진단 응답의 `collection.effective_mode` 는 `full`(사이트 모드는 IP 저장 그대로),
`collection.anonymous_fallback_reason` 은 `consent_plugin_blocks_cookies` 로 내려가 「동의 전 방문자는
익명」임을 알립니다. 한계: 방문자가 동의하는 순간 그 전(익명 키)과 후(쿠키 키)가 서로 다른 방문으로
나뉘고, 재방문·순방문자 지표는 동의한 방문자와 동의 전 방문자가 섞인 기준이 됩니다. 게스트로 동의한
뒤 로그인하면 동의 조회가 회원 기준으로 바뀌므로, 회원으로 동의한 기록이 없으면 익명으로 모입니다.

### 동의 출처가 없을 때

동의 연동 모드인데 동의를 확인할 곳(동의 관리 플러그인)이 없으면 **익명 모드로
동작합니다**. 아무것도 모으지 않으면 운영자가 이유도 모른 채 데이터를 잃고, 익명
수집은 개인정보를 남기지 않아 법적으로 가장 안전한 쪽이기 때문입니다. 이 상태는
설정·진단 화면과 통계 화면 상단에 안내로 표시됩니다.

### IP 마스킹

`analytics.ip_mask_octets` 가 주소 하위를 몇 칸 지울지 정합니다. 지울수록 개인을
특정하기 어려워지고, 동시에 위치 정확도가 떨어집니다.

| 값 | IPv4 결과 | 지역 정확도 |
| --- | --- | --- |
| 0 | 그대로 | 도시까지 정확 |
| 1 | `198.51.100.0` | 도시가 대체로 유지된다 |
| 2 | `198.51.0.0` | 국가만 신뢰할 수 있다 |
| 3 | `198.0.0.0` | 국가도 부정확하다 |

`analytics.geo_before_mask` 를 켜면 **마스킹 전 주소로** 지역을 조회한 뒤 마스킹해
저장합니다. 위치는 정확해지고 저장되는 주소는 그대로 가려집니다.

### 유입 주소

유입 주소는 **조각(`#…`)과 추적 파라미터(`utm_*`·`fbclid`·`gclid` 등)를 떼고** 저장합니다. 조각은 브라우저가
서버에 보내지 않는 자리라 다른 사이트가 붙인 인증 토큰 같은 값이 실릴 수 있고, 추적 파라미터는 같은 글을
광고 링크마다 다른 주소로 갈라 놓습니다. 나머지 쿼리는 원래 순서 그대로 둡니다. `analytics.anonymize_referrer`
를 `domain_only` 로 두면 경로와 쿼리까지 버리고 도메인만 남깁니다.

## 실패가 드러나는 곳

수집은 방문자가 보던 화면을 절대 망가뜨리지 않습니다 — 예외를 전부 삼키고 응답은
언제나 정상입니다. 그래서 **실패가 조용합니다**. 운영자가 그것을 알 수 있도록 두 곳에
흔적을 남깁니다.

| 남는 곳 | 무엇이 | 어디서 보나 |
| --- | --- | --- |
| 적재 실패 로그 | 형식 오류·상한 초과·DB 오류·선언되지 않은 목표(`unknown_goal`)·분류 기준(dimension, `unknown_dimension`) | 수집 진단 화면 「최근 적재 실패」 |
| 제외 사유 카운터 | 왜 세지 않았는지 (12가지 사유별 건수 + 확장이 등록한 사유) | 진단 화면 「오늘 제외 사유」 |

제외 카운터는 표가 아니라 캐시에 둡니다 — 제외는 방문보다 훨씬 자주 일어나므로 행으로
남기면 봇 트래픽에 원장이 잠식됩니다. 캐시가 비워지면 숫자도 사라지며, 화면이 그 사실을
함께 알립니다.

### 큐 워커가 없을 때

**수집은 큐를 타지 않습니다.** 방문 기록은 언제나 요청 안에서 끝나므로, 워커를 운영하지
않는 설치에서도 방문이 그대로 쌓입니다. 고를 설정도 없습니다.

워커가 없을 때 멈추는 것은 **집계·익명화 같은 배치**입니다 — 구간 재집계, 소급 익명화,
확장 제거 시의 통계 정리가 대기열에 남습니다. 수집은 계속되므로 원장은 늘어나는데 화면의
집계 숫자만 어느 시점에 멈춘 채 그럴듯하게 남습니다. 진단 화면이 큐 대기 건수와 마지막
집계 시각을 보여 줍니다.

### 집계가 도는 방식

화면이 보는 숫자는 원장이 아니라 집계 표입니다. 집계를 일으키는 길은 셋이고, 실행 이력의 `trigger` 로 구분됩니다.

| 길 | `trigger` | 언제 | 무엇을 |
| --- | --- | --- | --- |
| 스케줄러 | `scheduled` | 매시 5분(오늘치), 매일 00:15(어제 확정 + 밀린 날 따라잡기) | `routes/console.php` 등록만 `--scheduled` 를 단다 |
| 화면 열 때 | `on_view` | 관리자가 집계 화면(개요·페이지·유입·환경·지역·행동·패턴·봇, 대시보드 카드 포함)을 열거나 새로고침할 때, 마지막 매시 집계가 1분 넘게 지났으면 | 오늘치 + 밀린 날 따라잡기 |
| 수동 | `manual` | 진단 화면 「지금 집계」·「어제 확정」·구간 재집계, 손으로 돌린 `analytics:archive` | 요청한 범위 |

**같은 날짜는 한 번에 하나만 집계합니다.** 잠금은 날짜 하나에 걸리고(`ArchiveService::lockKey`) 실행 종류(시간
집계·일 집계·구간 재집계·화면 열 때)는 키에 들어가지 않습니다 — 모두 그날의 집계 행을 지우고 다시 쓰므로, 같은 날을
다른 종류가 이미 집계하고 있으면 뒤에 온 실행은 `skipped`(「같은 기간을 이미 집계하고 있어 건너뛰었습니다」)로 남습니다.

**화면 열 때 집계**는 cron 이 없는 설치(공유 호스팅·로컬 개발)에서도 숫자가 멈추지 않게 합니다.
여러 관리자가 동시에 열어도 1분에 한 번만 돌고(잠금으로 문을 닫는다), 권한 확인을 통과한 요청만 일으킵니다.
오늘 방문이 설정 상한(`archive_on_view_max_visits`, 기본 50,000)을 넘으면 요청 안에서 집계하지 않고 화면에
「스케줄러를 등록하세요」 경고를 띄웁니다 — 요청 하나가 과도하게 길어지지 않게 하는 안전장치입니다. 실패는 응답을
깨지 않고 기존 집계로 나갑니다. 실행 이력에는 남지만 활동 로그는 남기지 않습니다(분당 1건이 쌓이므로). 원장을 직접
읽는 실시간·방문자·유입 주소 화면과 사용자 화면의 방문자 카운터는 집계를 일으키지 않습니다. 설정 「방문자 통계 →
보존 → 집계」에서 끌 수 있습니다.

**밀린 날 따라잡기** — 스케줄러가 며칠 멈췄다 돌아오면 그 사이 날은 「어제 확정」이 돌지 않아 미확정으로 남습니다.
매일 00:15 실행과 화면 열 때 집계가 보존기간 안에서 원장 방문이 있는데 확정되지 않은 날을 최근 날부터 최대 7일
확정합니다(화면 열 때는 오늘 방문을 뺀 상한 예산 안에서만).

**스케줄러 판정** — 예약 매시 실행(`trigger=scheduled`)이 성공·실패와 무관하게 최근 120분 안에 시작했으면 살아 있다고
봅니다. 없을 때는 판정 근거(원장 첫 방문·첫 집계 실행 중 이른 시각)가 120분 넘게 쌓였을 때만 「멈춤」으로 보고, 설치
직후처럼 근거가 부족하면 「모름」으로 두어 경고하지 않습니다. 모든 집계 응답의 `data.freshness` 가 이 판정과 마지막 집계
시각을 싣고, 화면은 기간 줄에 「마지막 집계 22:07 · …」을, 상단에 스케줄러 미가동·집계 멈춤·상한 초과 경고를 띄웁니다
(응답 모양은 [API 문서](api/analytics.md#집계-신선도--화면-열-때-집계와-datafreshness)).

### 워커가 실행 도중 죽었을 때

집계·재집계·익명화는 실행 이력 한 행을 「실행 중」으로 열고 스스로 닫습니다. 서버 재시작·메모리
초과·잡 제한시간(1시간) 초과로 워커가 도중에 죽으면 닫을 코드가 돌지 못해 그 행이 남습니다.
진단 화면은 실행 중 행이 있으면 「지금 집계」·「어제 확정」을 잠그므로, 그대로 두면 버튼이 풀리지
않습니다.

- 실패로 끝난 잡은 자기가 연 행을 그 자리에서 **실패**로 닫고 사유를 남깁니다.
- 강제 종료처럼 그조차 못 한 행은 **2시간**(잡 제한시간의 두 배)이 지나면 진단 화면이 진행 중으로
  치지 않고, 매시 집계가 사유와 함께 실패로 닫습니다.

### 프록시 뒤에 있을 때

프록시·로드밸런서 뒤에서 `TRUSTED_PROXIES` 를 설정하지 않으면 모든 방문자의 IP 가
프록시 주소 하나로 보입니다. 방문자 수가 1명으로 뭉치고 지역 통계가 무의미해집니다.
진단 화면이 「전달 헤더가 오는데 신뢰하지 않는 상태」를 경고합니다.

## 봇 방문

봇은 사람 방문과 **섞지 않고** 별도 원장에 기록합니다. 크롤러가 하루 수만 번 오는
사이트도 있어, 섞으면 인기 페이지와 방문자 수가 통째로 뒤집힙니다.

판별은 SEO 기능의 봇 판별기를 재사용합니다 — 같은 요청을 두 기능이 다르게 판정하면
숫자가 갈리기 때문입니다. 다만 SEO 의 봇 감지 토글이 꺼져 있으면 그 판별기는 무조건
「봇 아님」을 돌려주므로, 그때는 통계가 직접 판정합니다. 그 설정은 「봇에게 캐시된
화면을 줄지」를 정하는 것이지 「봇이 아니다」라는 뜻이 아닙니다.

봇 기록에는 그때 SEO 캐시가 쓰였는지(`hit`/`miss`/`bypass`)도 함께 남습니다. 캐시가
듣지 않으면 크롤러 하나가 서버를 계속 갈아 대므로 운영자가 볼 수 있어야 합니다.

봇 원장은 **화면 요청(SPA 셸)만** 기록합니다. API 를 직접 부르는 봇은 대상이 아닙니다 — 판별이 붙는
자리가 화면 요청 미들웨어 묶음이고, API 호출은 페이지를 긁어 가는 크롤링과 성격이 달라 섞으면
「어떤 페이지를 가져갔는가」가 흐려집니다.

## 다른 카운터와의 차이

게시판의 **조회수**와 통계의 **페이지뷰**는 다른 것을 셉니다.

| | 게시판 조회수 | 통계 페이지뷰 |
| --- | --- | --- |
| 세는 대상 | 글 하나가 열린 횟수 | 방문 중 열린 화면 |
| 봇·관리자 제외 | 하지 않음 | 함 |
| 추적 거부 존중 | 하지 않음 | 설정에 따름 |

두 숫자가 다른 것은 정상입니다. 같은 값을 기대하고 비교하면 어느 쪽이 틀렸다고
오해하게 됩니다.

회원의 마지막 로그인 시각·로그인 실패 횟수와 로그인 이력은 **통계가 다루지 않습니다** — 회원 행동은
활동 로그가 담당하고, 통계는 방문이 회원의 것인지(`user_id` 유무)만 봅니다.

SEO 캐시 통계(`seo_cache_stats`)도 봇 요청을 세지만 목적이 다릅니다 — 그쪽은 캐시
효율(응답 시간·적중률)을 보고, 통계의 봇 원장은 「누가 언제 무엇을 가져갔는가」를 봅니다.

### 리포트 열이 세는 것

리포트 한 행의 「방문·조회·이탈률·평균 체류·방문당 페이지」는 리포트 종류가 무엇을 세는지에 따라 뜻이 달라집니다.

| 리포트 묶음 | 방문 | 조회 | 이탈률 |
| --- | --- | --- | --- |
| 페이지·제목 | 그 페이지를 본 방문 | 그 페이지의 페이지뷰 | 그 페이지 하나만 보고 떠난 방문의 비율 |
| 방문 속성(진입·이탈·유입·브라우저·국가 등) | 그 속성의 방문 | 그 방문들이 본 페이지뷰 합 | 한 페이지만 본 방문의 비율 |
| 행동(검색어·검색 탭·이벤트·내려받기·외부 링크·전환·확장) | 그 행동이 있던 방문 | 행동 횟수 | 없음 — 화면에서 열을 숨긴다 |
| 구간(체류시간·본 페이지 수) | 그 구간에 든 방문 | 그 방문들이 본 페이지뷰 합 | 한 페이지만 본 방문의 비율 |

**새 리포트 다섯** — 캠페인 매체(`campaign_medium`, utm_medium 만 붙은 주소도 매체를 남긴다 — 유입 종류 판정은 그대로),
검색 탭(`search_tab`, 사이트 검색을 한 탭), 이벤트(`event_name`, 확장이 `G7Core.analytics.trackEvent()` 로 보낸 이름 —
이름은 액션 이름 사전의 `event` 종류로 저장된다), 체류시간 구간(`visit_duration`), 본 페이지 수 구간(`visit_pages`,
페이지를 한 번이라도 본 방문만). 검색 탭·이벤트는 공개 수집 API 로 들어오는 자유 문자열이라 하루 라벨 수에 상한(50·500)을
두고 방문 수가 많은 것만 남깁니다. 구간 경계는 설정 `duration_bucket_bounds`·`pages_bucket_bounds` 로 바꾸며 저장 라벨이
경계를 담아(`60-180`, `21+`) 바꾼 뒤에도 옛 라벨을 뜻대로 읽습니다 — 바꾼 경계는 그 뒤 집계부터 적용됩니다. 리포트 목록
행 끝의 추이 아이콘은 그 항목의 날짜별 추이를 띄웁니다(92일까지 일, 그 뒤 주 단위).

방문당 페이지는 조회 ÷ 방문입니다. 방문 속성 리포트가 방문마다 조회 1 로 적히면 이 값이 어느 브라우저든
1 이 되고, 페이지 리포트가 이탈을 더하지 않으면 모든 페이지의 이탈률이 0% 가 됩니다. 진입·이탈 수는 진입·이탈
페이지 리포트에서 방문과 같은 값이라 화면에는 두지 않고 CSV 에만 싣습니다.

## 보존과 삭제

| 대상 | 기본 보존 | 설정 키 |
| --- | --- | --- |
| 방문·액션·전환 원장 | 90일 | `analytics.retention_days`(하한 7일) |
| 시간 단위 집계 | 90일 | `analytics.hourly_retention_days` |
| 일 집계·리포트별 집계 | 영구 | — (주·월·년 화면은 일 집계를 합산해 만든다) |
| 봇 요청 | 30일 | `analytics.bot_hits_retention_days` |
| 실패 로그·실행 이력 | 30일 | `analytics.failure_log_retention_days` |
| 일자별 솔트 | 5일 | (코드 상수) |

원장이 지워져도 일 단위 집계가 남으므로 「전체 방문자」는 몇 년이 지나도 말할 수
있습니다. 다만 그 시점의 개별 방문 기록은 되살릴 수 없습니다.

그래서 **재집계는 보존 기간이 지난 날을 건너뜁니다**(`skipped` 이력으로 남습니다).
원장이 없는 날을 다시 계산하면 빈 결과가 영구 집계를 덮어써 과거 숫자가 0 이 됩니다 —
`--force` 도 이 경계는 넘지 못합니다.

보존 정리는 이름 사전(방문했던 주소·검색어·내려받은 파일명)을 건드리지 않습니다 —
집계가 그 이름을 참조하기 때문입니다. 「모든 통계 데이터 삭제」만 사전까지 함께
지웁니다.

**기간을 지정해 지우는 기능은 없습니다.** 지울 수 있는 것은 보존일 정리(자동), 정보주체
단위 삭제, 전체 삭제 세 가지입니다. 기간 삭제를 두면 그 구간의 원장만 사라지고 집계는
남아, 화면 숫자와 원장이 영영 맞지 않게 됩니다.

**확장을 「데이터도 삭제」로 제거하면** 그 확장이 남긴 전환·그 확장 목표의 전환 집계·`ext:` 분류 기준 집계를 함께 지우고
진단 화면 실행 이력에 `extension_purge` 로 남깁니다. 방문·액션 원장은 방문자의 기록이라
지우지 않습니다. 데이터를 보존하고 제거하거나 비활성화만 하면 과거 수치는 그대로 남고
라벨은 원값(`ext:{식별자}:{키}`)으로 보입니다. 보존해 둔 것을 나중에 지우거나, 제거 때의 정리가
실패(실행 이력 「실패」)한 뒤 다시 돌리려면 `php artisan analytics:purge-extension {module|plugin} {식별자} --confirm`
을 씁니다 — 되돌릴 수 없어 예약 실행 대상이 아니고, 실패하면 종료 코드가 실패입니다. 켜져 있는
확장은 `--force` 없이는 지우지 않고(그 확장이 계속 쌓는 수치와 어긋난다), 설치되어 있지 않은
식별자는 확인 질문 전에 경고합니다(오타가 「0건 삭제」 성공으로 끝나지 않게).

### 같은 경고는 하루 한 번

원장 한계 초과·집계 실패·방문당 액션 상한 세 경고는 같은 종류를 하루에 한 번만
보냅니다. 집계는 매시 돌고 액션 상한은 수집 요청마다 판정하므로, 이 제한이 없으면
원인이 고쳐지기 전까지 같은 알림이 끝없이 쌓여 정작 다른 경고가 묻힙니다. 실패
로그와 실행 이력은 제한 없이 매번 남으므로 진단 화면에서는 전체 횟수를 봅니다.

## 알려진 한계

- **익명 모드에서는 재방문을 셀 수 없습니다.** 방문자 키가 날마다 바뀌기 때문입니다. 개요의 신규·재방문 선과
  카드는 그 칸을 「모름」(`null`)으로 두고, 기간 전체가 모름이면 카드가 「구분할 수 없습니다」를 보입니다. 동의 모드처럼
  쿠키 모드와 익명이 섞인 기간은 값이 있는 칸만 더하므로 신규 + 재방문이 순방문자와 다를 수 있습니다.
- **화면 열 때 집계의 1분 문과 잠금은 캐시 저장소를 씁니다.** 여러 서버가 각자 파일 캐시를 쓰면 서버마다 따로 돌 수
  있습니다 — 다중 서버는 공유 캐시(Redis 등)를 쓰거나 스케줄러에 맡깁니다.
- **이벤트 이름을 저장하기 전의 이벤트 행은 이벤트 리포트에 들지 않습니다.** 그 행은 방문 주소를 가리키므로,
  방문자 상세 타임라인에서도 예전 이벤트는 주소로, 새 이벤트는 이름으로 보입니다.
- **여러 날에 걸친 순방문자는 「일별 순방문자의 합」입니다.** 같은 이유로 진짜 순방문자를
  기간 단위로 셀 수 없습니다. 화면도 그렇게 표기합니다.
- **마지막 페이지의 체류 시간은 0초입니다.** 다음 이동이 없으면 언제 떠났는지 알 방법이
  없습니다.
- **검색 키워드는 대부분 비어 옵니다.** 검색엔진이 HTTPS 로 옮겨 가며 검색어를 유입
  주소에 싣지 않게 됐습니다. 판정이 실패한 것이 아닙니다.
- **지역 통계는 GeoIP 데이터베이스가 있어야 정확합니다.** 없으면 브라우저 언어의 지역
  서브태그로 국가만 추정하고 지역·도시는 비웁니다.
- **자정을 넘긴 방문은 두 날에 걸쳐 읽힙니다.** 방문·방문자 수는 방문이 시작한 날의 몫이고,
  시간 표에는 각 활동이 일어난 시각 칸에 들어갑니다. 그래서 하루의 시간 표 합과 그날의 일
  표는 「그날 시작한 방문」 기준으로 볼 때 어긋나 보일 수 있습니다.
- **국가 이름은 코드로 저장하고 화면에서만 번역합니다.** 번역은 코어 국가 이름표(한국어·영어)를 먼저 쓰고,
  없으면 PHP intl 의 지역 이름을 씁니다 — intl 이 없는 서버에서는 표에 없는 나라가 코드(`KR`)로 보입니다.
  도시·지역 이름은 GeoIP 사전에 그 언어가 있을 때만 번역되고(무료 사전에 한국어는 없습니다), 없으면
  영문, 그것도 없으면 코드입니다.
- **지역 조회는 시간대 판정과 같은 캐시를 씁니다.** 사이트가 이미 요청마다 GeoIP 로 방문자 시간대를
  정하므로, 통계의 지역 조회는 같은 캐시 키 정책을 따라 한 IP 를 두 번 조회하지 않습니다.
- **동의 관리 플러그인의 「분석」 쿠키 설명은 바꾸지 않았습니다.** 그 설명은 외부 분석 도구를 예로 들지만
  코어 통계도 「방문을 익명으로 측정한다」는 뜻에 포함됩니다. 문구를 바꾸려면 플러그인 버전과 번역 팩이
  함께 바뀌어야 해 이번 기능에서 떼어 두었습니다.

## 확장 지점

확장은 방문자 통계에 **전환(목표)** 과 **분류 기준** 을 보태고, 판정표·제외 규칙·개인정보
처리·출력 열에 끼어들 수 있습니다. 전환과 분류 기준은 먼저 선언해야 합니다.

| 소유자 | 선언 위치 |
| ------ | ------ |
| 코어 | `config/analytics.php` 의 `goals` 배열 (회원가입·로그인 2건) |
| 모듈 | `module.php` 의 `getAnalyticsGoals()`·`getAnalyticsDimensions()` 오버라이드 |
| 플러그인 | `plugin.php` 의 같은 두 메서드 |

선언은 데이터베이스에 적재하지 않고 **활성 확장에서 매번 모읍니다** — 설치본마다 있는 확장이
다르고, 확장이 꺼지면 그 선언도 함께 사라져야 하기 때문입니다. 목표 키는 `{식별자}.{key}`
(코어는 `core.{key}`), 분류 기준은 원장에 `{식별자}:{key}`, 집계에 `ext:{식별자}:{key}` 로
정규화됩니다.

선언이 잘못된 항목은 **조용히 버리지 않습니다** — 그 항목만 사유와 함께 경고로 남기고 나머지는
살립니다. 선언되지 않은 목표·분류 기준을 보내면 수집 실패 목록에 `unknown_goal`·`unknown_dimension`
으로 남습니다. 확장 개발 안내는 [확장 기여 지점](../extension/analytics-extension-points.md),
브라우저 쪽 API 는 [방문자 통계 트래커](../frontend/analytics-tracker.md) 를 봅니다.

**확장 하나의 결함이 통계를 멈추지 않게 합니다.** 수집 요청 안에서 도는 확장 필터(판정표·등록부)는
`App\Analytics\ExtensionFilter::apply()` 로 부릅니다 — 확장이 던지면 코어 기본값으로 이어 가고,
그 요청의 수집 실패 목록에 `listener_exception` 으로 훅 이름을 남깁니다. 수집 경로에 새 확장
필터를 들일 때도 같은 방식으로 부릅니다. 집계 수집기(`ArchiveCollector`)는 집계 표가 거부할 값을
받지 않습니다 — 열 폭을 넘는 분류 기준 이름·네 값 밖의 방문자 유형은 경고와 함께 버리고, 음수 지표는 0,
열 최댓값(`ArchiveCollector::MAX_COUNTS`)을 넘는 지표는 경고와 함께 최댓값, 추가 값의 깨진 UTF-8 은
대체 문자로 바꾸며(JSON 으로 못 바꾸는 값이면 그 칸만 비움) 같은 라벨은 합칩니다. 분류 기준 이름은
소문자·앞뒤 공백 없는 꼴로 맞춥니다 — 집계 표 `dimension` 열의 대조 규칙이 대소문자·끝 공백을 가리지 않아 표기만
다른 두 이름이 유일키에 걸리기 때문입니다. 확장 행 하나 때문에 그날 집계가 실패하지 않습니다. 선언 등록부도
같은 원칙이라, 선언 항목 하나가 형식 혼동(문자열 자리에 배열 등)으로 던지면 그 항목만 사유와 함께
버립니다.

## 설치 체크리스트

| 확인 | 안 하면 | 어디서 보나 |
| --- | --- | --- |
| 프록시 뒤라면 `TRUSTED_PROXIES` 설정 | 모든 방문자가 프록시 주소 하나로 뭉친다 | 진단 화면 경고 |
| 스케줄러(`schedule:run`) 등록 | 숫자는 관리자가 화면을 열 때 집계로 맞춰지지만(설정에서 끄면 그마저 멈춘다) 어제 확정·정리·메일 보고서가 멈춘다 | 통계 화면 상단 「스케줄러 미가동」 안내, 진단 화면 「스케줄러 마지막 실행」 |
| 큐 워커(집계·익명화 배치용) | 재집계·익명화·확장 정리가 대기열에 남는다 — 수집 자체는 워커 없이 돈다 | 진단 화면 큐 대기 건수 |
| 지역 통계를 쓰면 GeoIP 데이터베이스 | 국가만 추정되고 지역·도시가 빈다 | 진단 화면 GeoIP 상태 |
| 훅 캐시 최신(아래 「업그레이드」) | 수집·검색·전환 기록이 증상 없이 돌지 않는다 | — |

## 업그레이드

기존 사이트는 별도 데이터 변환이 필요 없습니다. 신규 테이블은 마이그레이션이 만들고,
설정 기본값·권한·메뉴·알림 정의는 코어 업데이트 흐름의 비파괴 동기화가 반영합니다.

다만 관리자 메뉴 순서는 기존 행을 밀어야 하므로 업그레이드 스텝이 그 자리를 비웁니다
(운영자가 관리자 화면에서 직접 지정한 순서는 보존합니다).

**관리자 대시보드 레이아웃을 직접 고쳐 쓰고 있다면** 관리자 템플릿을 갱신할 때 주의하십시오. 방문자
통계 카드는 대시보드 레이아웃에 들어 있고, 템플릿 갱신의 레이아웃 처리 기본값은 덮어쓰기입니다 —
고친 대시보드가 번들 본으로 바뀝니다. 고친 것을 지키려면 `--layout-strategy=keep` 으로 갱신한 뒤
카드를 직접 옮겨 넣으십시오(이때는 카드가 자동으로 생기지 않습니다).

**기능은 기본으로 켜져 있습니다.** 업데이트 직후부터 「IP 저장」 모드로 수집이
시작되며, 설정 화면에서 언제든 끄거나 모드를 바꿀 수 있습니다.

**훅 캐시가 최신인지 확인하십시오.** 코어는 훅 리스너를 `bootstrap/cache/hooks.php` 에서
읽습니다(캐시가 있으면 디렉터리를 훑지 않습니다). 표준 업데이트(`core:update`)는 이 캐시를
스스로 다시 굽지만, 파일을 손으로 올리는 등 그 경로를 지나지 않았다면 이 버전이 더한
리스너들이 캐시에 없습니다 — 수집 적재, 내부 검색 기록, 동의 철회 반영, 회원가입·로그인
전환 기록, 확장을 데이터까지 지우며 제거할 때의 통계 정리가 **아무 증상 없이** 돌지 않습니다.
그때는 `php artisan hooks:cache` 를 한 번 돌리십시오.
