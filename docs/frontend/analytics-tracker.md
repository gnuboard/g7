# 방문자 통계 트래커

> 사용자 화면이 방문·페이지뷰·내려받기·외부 링크를 서버에 알리는 브라우저 모듈과, 확장이
> 쓰는 전역 API `G7Core.analytics` 입니다. 서버 쪽 설계는 [방문자 통계](../backend/analytics.md),
> 확장 기여 전반은 [방문자 통계 확장 기여 지점](../extension/analytics-extension-points.md) 을 봅니다.

---

## TL;DR (5초 요약)

```text
1. 트래커는 사용자 템플릿에서만 돈다 — 관리자 화면은 세지 않는다
2. 화면 이동마다 비콘 1건, 전송은 다음 틱에 keepalive fetch(없으면 sendBeacon)
3. G7Core.analytics.* 는 예외를 던지지 않는다 — 다만 수집이 꺼졌거나 관리자 화면이면 전역이 없으니 ?. 로 부른다
4. trackGoal·setDimension 은 확장이 선언한 목표·분류 기준만 서버가 받는다
5. 제외 대상(추적 거부·수집 제외 쿠키 등)이면 메서드는 있어도 아무것도 보내지 않는다
```

---

## 언제 무엇을 보내나

| 계기 | 비콘 `t` | 비고 |
| --- | --- | --- |
| 첫 화면 | `pageview` (`init: true`, `ref` 포함) | 서버 폴백이 먼저 적은 같은 페이지 행을 채운다 — 두 번 세지 않는다 |
| SPA 이동 | `pageview` | 직전 페이지 체류 시간(`prev`)을 함께 싣는다 |
| 파일 링크 클릭 | `download` | `/api/attachment/` 경로 또는 설정의 내려받기 확장자 |
| 다른 사이트 링크 클릭 | `outlink` | 같은 사이트 링크는 세지 않는다 |
| `G7Core.analytics.trackGoal()` | `goal` | 선언된 목표만 기록된다 |
| `G7Core.analytics.trackEvent()` | `event` | 이름을 저장·집계한다(하루 500종) — 아래 「이벤트의 한계」 |

라우터 구독은 `TemplateApp` 이 하고, 핸들러는 **동기로 반환**합니다. 라우터가 핸들러를 기다리므로
여기서 전송을 기다리면 화면 전환이 비콘만큼 늦어집니다. 전송은 다음 틱(`setTimeout(0)`)에서 합니다.

보내기 전에 서버 검증 상한에 맞춥니다 — 제목 512자·이름 255자·분류 값 255자는 글자 단위로 자르고
(이모지가 반쪽 나지 않게), 분류 기준(dimension)은 앞 20개만 싣습니다. 유입 주소(`ref`)·대상 주소(`target`)가 1,024자를
넘으면 주소를 자르는 대신 뺍니다. 넘친 필드 하나 때문에 서버가 비콘 전체를 버리지 않게 하려는
것입니다.

전송은 `fetch(…, {keepalive: true})` 가 먼저입니다. `navigator.sendBeacon` 은 헤더를 실을 수 없어
로그인 토큰을 못 보내고, 그러면 회원·관리자 방문이 전부 비회원으로 세어집니다. 화면을 떠나는 중에도
전송이 보장되는 성질은 둘이 같습니다. 응답은 기다리지도 읽지도 않습니다(서버는 늘 204).

## `G7Core.analytics` API

| 메서드 | 반환 | 설명 |
| --- | --- | --- |
| `trackGoal(key, attrs?)` | `void` | 목표 달성을 알린다. `key` 는 `{확장 식별자}.{목표 키}`. `attrs` 는 그 목표가 선언한 속성 스키마로 서버가 검증한다 |
| `trackEvent(name, attrs?)` | `void` | 사용자 정의 이벤트를 알린다. 이름은 「이벤트」 리포트로 집계되고 속성은 저장하지 않는다 |
| `setDimension(key, value)` | `void` | 이 화면의 다음 비콘부터 분류 값을 싣는다. 다른 화면으로 이동하면 비워지므로 화면마다 다시 부른다(방문 범위 분류 기준은 서버가 방문에 남긴다). `key` 는 `{확장 식별자}:{분류 기준 키}` 또는 짧은 키 |
| `optOut()` · `optIn()` | `Promise<void>` | 이 브라우저를 수집에서 빼거나 되돌린다. 쿠키를 서버가 심어야 해서 요청을 기다린다 — 두 메서드만 Promise 다 |
| `isOptedOut()` | `boolean` | 이 화면이 「수집 제외 쿠키」 때문에 세어지지 않는지. 제외 판정 순서상 앞선 사유(미리 그리기·추적 거부)가 먼저 걸리면 쿠키가 있어도 `false` 다 — 「이 브라우저가 제외를 선택했는가」를 물으려면 쓰지 않는다 |

모든 메서드는 예외를 삼킵니다. 다만 수집이 꺼진 사이트(`analytics.enabled=false`)와 관리자
템플릿에서는 트래커를 만들지 않아 **전역 `G7Core.analytics` 자체가 없습니다** — 확장은 늘
`G7Core.analytics?.trackGoal(...)` 처럼 선택적 호출로 부릅니다.

```ts
// 게시판 글 화면이 뜰 때 — 선언된 분류 기준 `board_id` 에 값을 싣는다
G7Core.analytics?.setDimension('sirsoft-board:board_id', String(board.id));

// 주문 완료 화면에서 — 선언된 목표. 금액·통화는 목표 선언의 스키마로 검증된다
G7Core.analytics?.trackGoal('sirsoft-ecommerce.order_completed', { revenue: 45000, currency: 'KRW' });
```

결제 승인처럼 **서버가 확실히 아는 순간**은 브라우저가 아니라 서버 기록기
(`ConversionRecorderInterface`)를 씁니다 — 브라우저는 응답이 오기 전에 화면을 떠날 수 있습니다.

### 서버가 버리는 것

| 보낸 것 | 결과 | 어디서 보나 |
| --- | --- | --- |
| 선언되지 않은 목표 | 비콘 전체를 버린다 | 수집 진단 화면 「최근 적재 실패」 「미등록 목표」(`unknown_goal`) |
| 목표 속성이 선언 스키마를 어김 | 비콘 전체를 버린다 | 같은 곳 「형식 오류」(`validation`) |
| 코어 목표(`core.user_registered` 등) | 비콘 전체를 버린다 — 코어 목표는 서버가 완료를 확인한 순간에만 남는다 | 같은 곳 「형식 오류」(`validation`) |
| 선언되지 않은 분류 기준·값 종류가 틀린 분류 기준 | 그 분류 기준만 버리고 나머지는 적재 | 같은 곳 「미등록 분류 기준」(`unknown_dimension`) |
| 개인정보(`pii`)로 선언된 분류 기준을 익명 모드에서 | 싣지 않는다(실패 아님) | — |
| 한 번만 세는 목표의 두 번째 | 남기지 않는다(실패 아님) | — |

### 이벤트의 한계

`trackEvent()` 는 **이벤트 이름을 저장하고 집계합니다** — 방문 타임라인에 그 이름으로 한 줄이 남고,
관리자 「검색어·다운로드·전환 → 이벤트」 탭이 이름별 방문·횟수를 셉니다. 공개 수집 API 로 누구나 이름을
바꿔 보낼 수 있어 하루 500종까지만 집계하고(방문 수가 많은 것부터), 이름은 255자에서 자릅니다.
**속성(`attrs`)은 여전히 저장하지 않습니다.** 이름 없이 보낸 이벤트는 예전처럼 그 화면의 주소로 남고
이벤트 탭에는 들지 않습니다.

이벤트는 선언 없이 자유롭게 보내는 기록입니다. 전환율·매출처럼 정해진 뜻으로 세고 싶은 행동은 목표로 선언해
`trackGoal()` 을 쓰고, 행동을 가르는 값은 분류 기준으로 선언해 `setDimension()` 을 씁니다 — 그래야
등록부가 이름을 알고 리포트에 선언한 이름이 붙습니다.

## 보내지 않는 경우

트래커는 보내기 전에 서버와 같은 규칙으로 걸러 냅니다(보내 봤자 버려질 요청을 줄인다). 서버도
같은 판정을 다시 하므로 여기서 놓친 요청이 세어지지는 않습니다.

- 수집이 꺼져 있음 · 관리자 템플릿
- 제외 URL 패턴에 맞음
- 추적 거부(DNT·GPC)를 존중하도록 설정했고 브라우저가 보냄
- 수집 제외 쿠키(`g7_analytics_optout`)가 있음
- 동의 연동 모드에서 분석 동의가 확인되지 않음, 또는 아직 판정 전(아래 「동의 연동」)
- 브라우저가 화면을 미리 그리는 중(prerender). 이때는 보내지 않고 기다렸다가 **실제로 열리면** 그 첫
  화면을 보냅니다 — 미리 그리기만 하고 열지 않은 화면은 세지 않되, 열린 화면의 첫 방문은 잃지 않습니다

제외 URL 패턴은 서버와 같은 규칙입니다 — 끝의 `*` 는 여러 개여도 하나와 같이 「이 경로로 시작」을 뜻하고,
가운데 `*` 는 글자 그대로입니다.

서버 검증 상한을 넘는 필드는 보내기 전에 맞춥니다 — 한 칸이 길다고 비콘 전체가 버려지지 않게 하려는 것입니다.
제목(512자)·이벤트 이름(255자)·분류 값(255자)은 글자 단위로 자르고 분류 기준은 앞 20개만 남깁니다. 주소는 자르면
다른 주소가 되므로 유입 주소·클릭 대상(1024자)은 넘으면 빼고, 페이지 주소(2048자)는 쿼리·조각을 뗀 뒤에도
길 때만 자릅니다.

### 동의 연동

수집 모드가 「동의 연동」이고 사이트에 동의 관리 제공자가 있을 때만 트래커가 동의를 확인합니다. IP 저장 모드와
익명 모드에서는 동의를 기다리지 않습니다.

판정 출처는 코어 동의 런타임([`G7Core.consent`](g7core-api.md#방문자-동의-g7coreconsent))입니다. 트래커는 동의를 따로
조회하지 않고, 생성 옵션 `consentSource` 로 받은 런타임의 스냅샷을 읽습니다. 동의를 관리하는 확장이 무엇인지는 모릅니다.

| 스냅샷 `status` | 트래커 판정 |
| --- | --- |
| `none` | 막지 않는다. 서버가 익명 모드로 받는다 |
| `ready` | `needsRenewal` 이 `false` 이고 `categories.analytics` 가 `true` 일 때만 보낸다 |
| `unknown` | 첫 판정 전이면 비콘을 들고 기다린다. 첫 판정 뒤에도 `unknown` 이면 동의하지 않은 것으로 보고 보내지 않는다 |

첫 판정 전은 부팅 직후와 로그인, 로그아웃 직후입니다. 런타임이 인증 경계마다 다시 조회하므로 트래커도 그때마다
「첫 판정 대기」로 돌아가 비콘을 최대 5건까지 들고 있습니다. 조회가 끝나면(값이 바뀌지 않았어도) 그때의 판정으로
들고 있던 비콘을 보내거나 버립니다. 보내기 직전에 제외 판정을 다시 하므로, 보류 중 수집 제외를 고른 방문자의
비콘은 나가지 않습니다.

브라우저 판정은 버려질 요청을 미리 거르는 용도입니다. 서버가 매 요청에서 동의 제공자에게 같은 규칙으로 다시 묻습니다
([동의 제공자](../extension/consent-provider.md)).

예전의 window 이벤트 `g7:analytics-permission-changed`, export `ANALYTICS_CONSENT_CHANGED_EVENT`, 트래커 자체의 동의
조회는 없어졌습니다. 동의 변경을 알아야 하는 확장은 `G7Core.consent.subscribe()` 나 컴포넌트 이벤트 `consent:changed` 를 씁니다.
