# 게시판 샘플 데이터

`php artisan module:seed sirsoft-board --sample` 이 만드는 샘플 데이터의 구성과, 다시 실행했을 때 무엇이 지워지고 무엇이 남는지 정리합니다.

## 실행 순서

| 단계 | 시더 | 만드는 것 |
| --- | --- | --- |
| 설치 | `BoardTypeSeeder`, `BoardReactionTypeSeeder` | 게시판 유형 3종, 반응 유형(추천·비추천) — `--sample` 없이도 실행 |
| 1 | `Sample\BoardSampleSeeder` | 샘플 게시판 9개 (아래 표) |
| 2 | `Sample\PostSampleSeeder` | 게시글·답글·댓글·첨부 (원글 기본 160건, `--count=posts=` 로 조정) |
| 3 | `Sample\ReactionScrapSampleSeeder` | 게시글·댓글 반응, 스크랩 |
| 4 | `Sample\ReportSampleSeeder` | 신고 케이스 (상태별, 다중 신고자, 재접수, 자동 블라인드) |
| 5 | `Sample\NotificationLogSeeder` | 알림 발송 이력 |
| 6 | `Sample\IdentityVerificationLogSeeder` | 본인인증 이력 |
| 7 | `ActivityLogSampleSeeder` | 이번 실행에서 만든 게시판·글·댓글·첨부·반응·스크랩과 샘플 신고를 따라간 활동 로그 |

작성자·신고자·반응한 회원은 활성 회원 중에서 고릅니다. 새로 설치해 회원이 관리자 한 명뿐이면 게시글은 관리자 이름으로만 만들어지고, 반응·스크랩(활성 회원 2명 이상 필요)과 신고는 건너뜁니다. 샘플 회원이 필요하면 먼저 실행하세요.

```bash
php artisan db:seed --class="Database\Seeders\Sample\DummyUserSeeder"
```

쇼핑몰 샘플 데이터(`module:seed sirsoft-ecommerce --sample`)는 게시판 샘플 **뒤에** 실행합니다. 쇼핑몰 문의 게시판 설정이 비어 있으면 아래 「상품 문의」 게시판을 연결하고 문의 샘플을 그 게시판에 만듭니다.

## 샘플 게시판

모든 샘플 게시판은 관리자 화면에서 새 게시판을 만들 때와 같이 **게시판 환경설정의 기본값**을 먼저 따르고, 게시판마다 시연할 설정만 바꿉니다.

| slug | 시연하는 설정 |
| --- | --- |
| `notice` | 관리자만 글쓰기, 댓글·파일 없음, 반응 끔 |
| `free` | 비회원 글쓰기, 비밀글 선택, 입력 길이 제한 변경, 반응 추천+비추천, 게시판 전용 금지어 |
| `gallery` | 갤러리형, 조회수 정렬, 최신 댓글 위, 반응 추천 |
| `event` | 카드형, 관리자만 글쓰기, 오래된 순 |
| `qna` | 분류, 답글 여러 단계, 회원 비밀글 열람, 반응 추천+비추천·댓글 반응 끔, **답글이 달린 글은 삭제 불가** |
| `members` | 비회원 접근 차단, 항상 비밀글 + 댓글 |
| `inquiry` | 1:1 문의 — 항상 비밀글, 답글 1단, 비회원 문의, 반응 끔 |
| `archive` | 비활성 게시판, 오래된 순, 금지어 = 환경설정 기본 금지어 목록 |
| `product-inquiry` | 쇼핑몰 상품 문의 저장소 — 항상 비밀글, 답글 1단, 댓글·반응·스크랩 끔 (글은 쇼핑몰 샘플이 만듭니다) |

금지어를 지정하지 않은 게시판은 금지어 검사를 하지 않습니다(환경설정 기본 목록으로 대신하지 않습니다).

게시판 이름·설명은 한국어·영어로 만들고, 사이트 기본 언어가 그 둘이 아니면 그 언어 값을 대체 언어(`app.fallback_locale`, 기본 한국어) 값으로 채웁니다. 그 언어의 언어팩이 샘플 게시판 이름 번역을 제공하면 번역을 씁니다.

## 데이터가 지키는 규칙

샘플은 실제 화면에서 같은 동작을 했을 때와 같은 모양으로 만들어집니다.

- 삭제된 글 아래 댓글·첨부·답글은 글 삭제처럼 함께 삭제 상태가 됩니다. 답글이 달린 `qna` 글은 삭제 상태로 만들지 않습니다.
- 공지와 관리자 전용 게시판의 글은 관리자가 씁니다. 작성자·신고자·반응한 회원은 활성 회원입니다.
- 본인 글·본인 댓글에는 반응하지 않고, 본인 글은 신고하지 않습니다. 반응은 게시판에서 켠 유형만 씁니다.
- 게시 중단된 신고의 대상은 블라인드, 삭제된 신고의 대상은 삭제, 자동 블라인드 기준 이상 신고된 대상은 자동 블라인드 상태입니다.
- 시각은 글 → 답글·댓글 → 조치 순서이고, 글·댓글 수와 반응·스크랩 수는 실제 행 수와 같습니다.
- 샘플을 만든 직후 대시보드 그래프를 위해 최근 30일 집계를 한 번 실행합니다.

## 다시 실행할 때

| 데이터 | 다시 실행하면 |
| --- | --- |
| 샘플 게시판 | 같은 slug 가 있으면 건너뜁니다 |
| 게시글·댓글·첨부 | 게시판에 글이 있으면 그 게시판은 건너뜁니다. 운영자가 만든 게시판에는 만들지 않습니다 |
| 반응·스크랩 | 샘플 게시판에 이미 있으면 건너뜁니다 |
| 신고 | 샘플 표시(`metadata.sample`)가 있는 신고만 지우고 다시 만듭니다 |
| 활동 로그 | 이번 실행에서 새로 만든 데이터에만 만듭니다. 이미 있던 게시판·글(운영 글 포함)에는 만들지 않습니다. 다시 만드는 샘플 신고의 로그만 샘플 표시(`properties.seeded_by`)로 찾아 지우고 다시 만듭니다 |

「이번 실행에서 만든 것」은 각 시더가 쓰기 전후의 id 범위로 판정합니다. 시드 도중 같은 게시판에 실제 사용자가 글·댓글·반응을 쓰면 그 행이 범위에 섞일 수 있으니, 운영 중인 사이트에서는 사용자가 적은 시간에 실행하세요.

운영 중인 신고와 활동 로그는 지우지 않고, 운영 중인 글·회원 이름으로 하지 않은 행동의 활동 로그를 만들지 않습니다. 활동 로그의 행위자는 실재하는 회원만 기록합니다(탈퇴한 작성자는 비웁니다). 이전 버전의 샘플 데이터가 만든 신고·활동 로그는 표시가 없어 운영 데이터와 구분할 수 없으므로 그대로 남습니다 — 필요하면 관리자 화면에서 직접 정리하세요.
