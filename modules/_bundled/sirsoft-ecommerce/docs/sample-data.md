# 이커머스 — 샘플 데이터

> 설치 데이터와 시연용 샘플 데이터 · 진입점: [AGENTS.md](../AGENTS.md)

## 설치 데이터 (모듈 설치 때 자동)

모듈을 설치하면 아래 기준 데이터가 채워집니다. 운영 데이터를 지우지 않으며, 운영자가 화면에서 고친 값은 다시 실행해도 보존됩니다.

| 데이터 | 내용 |
|---|---|
| 채번 규칙 | 주문·취소·환불·교환·반품·추가결제·상품 번호 |
| 배송유형 | 택배·직접배송·퀵서비스·화물·매장수령 등 (일부는 기본 꺼짐) |
| 배송사 | 국내·해외 택배사와 배송 조회 주소 |
| 클레임 사유 | 환불·교환·반품 사유와 귀책 구분 |

같은 기준 데이터는 `php artisan module:seed sirsoft-ecommerce` 로 다시 동기화할 수 있습니다. 이 명령은 회원 배송지 같은 운영 데이터를 건드리지 않습니다.

## 샘플 데이터 (`--sample`)

```bash
# 게시판 샘플을 먼저 만들면 상품 문의 샘플이 product-inquiry 게시판에 연결됩니다
php artisan module:seed sirsoft-board --sample
php artisan module:seed sirsoft-ecommerce --sample

# 확인 질문 없이 진행 (자동화·배포 스크립트)
php artisan module:seed sirsoft-ecommerce --sample --force
```

### 실행 전 확인 질문

샘플은 이전 샘플을 지우고 다시 만듭니다. 운영 데이터와 샘플을 구분할 표식이 없는 아래 데이터는 **표의 행 전체가 지워지므로**, 실행 전에 지울 목록과 현재 행 수를 보여 주고 확인을 받습니다. 운영 환경이 아니어도 매번 묻습니다. 대화형 터미널이 아니면(파이프·CI) `--force` 를 주어야 진행합니다.

| 지워지고 다시 만들어지는 데이터 | 비고 |
|---|---|
| 상품 | 옵션·이미지·상품정보제공고시·라벨 연결 포함. **저장소의 상품 이미지 폴더 전체**를 비웁니다 — 샘플이 아닌 상품 이미지 파일도 함께 지워집니다 |
| 상품 문의 | 게시판의 문의 글과 그 글의 답변 포함 (같은 게시판의 다른 글은 그대로) |
| 주문 | 결제·배송·주소·취소·환불·교환·반품·추가결제·클레임 첨부 파일·현금영수증·세금계산서 포함 |
| 쿠폰 | 쿠폰 발급 이력 포함 |
| 장바구니 · 상품 리뷰 | 리뷰 이미지 포함. **저장소의 리뷰 이미지 폴더 전체**를 비웁니다 |
| 마일리지 거래·잔액 | 원장 전체를 샘플 주문 기준으로 다시 만듭니다 |
| 브랜드 · 카테고리 · 상품 라벨 · 상품 공통정보 · 고시 템플릿 · 추가배송비 템플릿 | |
| 배송정책 | 국가별 설정·클레임 회수지 포함 |
| 회원 쇼핑 프로필 | 선호 통화·배송국가 |

지우지 않지만 바꾸는 것:

- **1:1 문의게시판 설정** — 비어 있고 `product-inquiry` 게시판이 있으면 그 게시판을 연결합니다(이미 설정한 값은 그대로).
- **대시보드 통계** — 최근 31일 매출·주문 통계를 다시 집계합니다.

지우지 않는 것:

- **회원 배송지** — 주문이 있고 배송지가 없는 일반 회원에게만 1~3개를 새로 만듭니다.
- **활동 로그** — 이전 샘플이 남긴 로그(샘플 표식이 있는 행)만 지웁니다. 실제 운영 중 쌓인 로그는 남습니다.

### 샘플이 만드는 것

- **주문** — 모든 주문에 결제 행과 배송 행이 있고, 주문 → 결제 → 발송 → 배송완료 → 구매확정 시각이 차례대로 이어집니다. 결제 대기 주문은 입금 대기(입금기한은 미래), 취소 주문은 취소신청서와(결제 후 취소면) 환불신청서를 갖습니다.
- **상품·리뷰 이미지** — 외부 이미지 서비스에서 내려받습니다. 연결이 실패하거나 시간이 초과된 이미지는 건너뛰고 이미지 없이 계속합니다(실행이 중단되지 않습니다).
- **결제** — 켜진 결제 플러그인이 있으면 카드·가상계좌 샘플을 그 결제사로 기록하되, 실제 거래와 구분하도록 결제 정보에 테스트 표식(`is_test_mode`)을 두고 거래번호를 `SAMPLE-` 로 시작합니다. 켜진 결제 플러그인이 없으면 무통장입금 주문만 만듭니다.
- **배송** — 송장이 있는 배송에는 항상 택배사가 있습니다(CJ대한통운 우선). 상품 옵션에 무게·부피가 들어가 무게·부피 배송정책을 시연할 수 있습니다.
- **클레임** — 교환(신청·회수중·재발송중·완료·상위 옵션 교환과 추가결제·선교환 회수 지연), 반품(운영자 대리 신청·완료와 환불·부분 수량·반려), 교환품 반품의 교환 차액 환급, 환불(직접 신청·보류·마일리지로 지급), 교환 철회, 입금 전 취소 주문의 재활성을 한 건씩 만듭니다.
- **마일리지** — 회원마다 시각 순서대로 적립·사용·취소 복원·관리자 지급/차감·소멸을 만듭니다. 사용한 만큼 주문의 결제금액이 줄고, 적립은 설정의 적립 시점(구매확정/배송완료)과 지연일을 따릅니다. 적립률·절사·최대 사용 한도는 설정값을 씁니다.
  - 마일리지 기능이 꺼져 있어도 시연용으로 만듭니다. 이때 실행 결과에 「마일리지가 꺼져 있어 화면에 안 보일 수 있음」을 안내합니다. 화면에서 보려면 이커머스 설정 > 마일리지에서 사용을 켜세요.
- **상품 문의** — 1:1 문의 게시판 설정이 비어 있고 `product-inquiry` 게시판이 있으면 그 게시판을 설정에 연결합니다. 이미 설정한 게시판은 바꾸지 않습니다. 게시판이 없으면 문의 샘플만 건너뜁니다.
  - 문의 샘플만 따로(`--class`) 실행했는데 문의가 이미 있으면, 실제 고객 문의일 수 있어 지우지도 새로 만들지도 않습니다.
- **클레임 샘플만 따로(`--class`) 실행하면 건너뜁니다** — 클레임 샘플은 있는 주문에 신청서를 붙이고 주문 상태·마일리지를 바꾸므로, 샘플 재시드(`--sample`)가 방금 만든 주문에만 만듭니다.
- **알림 발송 이력** — 이커머스 알림 정의마다 한 건 이상, 실제 알림 템플릿 문구로 만듭니다. 관리자 알림은 관리자에게 보낸 이력입니다.
- **통계** — 샘플을 만든 뒤 최근 31일 매출·주문 통계를 집계해 대시보드가 바로 보입니다.

### 건수 조절

`--count=키=값` 으로 건수를 바꿀 수 있습니다.

| 키 | 기본 | 내용 |
|---|---|---|
| `products` | 100 | 상품 수 |
| `orders` | 100 | 주문 수 (상태별 최소 5건 보장) |
| `address_users` | 30 | 배송지를 만들 회원 수 상한 |
| `ecommerce_notification_logs` | 160 | 알림 발송 이력 수 |
| `inquiry_rate` | 3 | 상품당 문의 최대 건수 |
| `review_rate` | 60 | 배송완료·구매확정 상품 중 리뷰 작성 비율 (%) |

```bash
php artisan module:seed sirsoft-ecommerce --sample --count=products=20 --count=orders=50
```
