# Changelog

이 프로젝트의 모든 주요 변경사항을 기록합니다.
형식은 [Keep a Changelog](https://keepachangelog.com/ko/1.1.0/)를 따르며,
[Semantic Versioning](https://semver.org/lang/ko/)을 준수합니다.

## [0.2.0] - 2026-10-10

### Added

- 확장 아이콘을 동봉했습니다. 관리자 확장 관리 화면과 설치 마법사에 표시됩니다.
- 모듈이 화면 컴포넌트를 제공하는 예시로 `MemoCard` 를 추가했습니다. 레이아웃에서는 모듈
  식별자와 점을 앞에 붙인 태그로 씁니다 — `<gnuboard7-hello_module.memo-card data-type="composite" title="..."/>`.
- 관리자 템플릿에서만 다른 모양으로 나오는 `MemoCard` 판본을 함께 넣었습니다. 같은 태그로
  작성하면 어느 템플릿을 쓰는지에 따라 알맞은 판본이 자동으로 선택됩니다.
- 모듈이 자기 컴포넌트를 코어에 등록하는 최소 코드를 프론트엔드 진입 파일에 담았습니다.
- `MemoCard` 를 레이아웃 편집기 팔레트에 등재했습니다. 모듈이 제공하는 컴포넌트를 편집기에서
  꺼내 쓸 수 있게 하는 최소 예시입니다.
- HTML 유사 마크업 형식(`.g7.html`)으로 작성한 관리자 화면 예시(`admin_markup_demo`)를 넣었습니다.
  소스 파일과 그 컴파일 결과가 나란히 설치되는 최소 사례입니다.
- 관리자 메모 목록·작성 화면과 사용자 메모 목록 화면도 `.g7.html` 마크업 형식으로 함께 제공하고 설명 주석을 달았습니다. 화면 동작은 달라지지 않습니다.
- 레이아웃 편집기에서 메모 목록·작성 화면을 열면 빈 화면 대신 예시 메모가 보이도록 편집기 미리보기 표본을 넣었습니다.

### Changed

- 코어 최소 요구 버전을 7.1.0 으로 상향 — 화면 마크업 형식(`.g7.html`)을 읽는 기능이 이 코어부터 제공됩니다.
- 설치 시 `.g7.html` 이 있으면 그것을 우선 사용합니다. 짝이 되는 JSON 과 결과가 같아 화면 동작은 달라지지 않습니다.

### Fixed

- 메모를 저장하기 전에 `gnuboard7-hello_module.memo.title.filter` 필터를 발화합니다. 문서에 있던 확장점이 실제로는 발화되지 않아,
  Hello 플러그인의 제목 접두사 예제가 동작하지 않았습니다.
- 사용자 화면의 공개 메모 목록(`/memos`)이 404 로 열리지 않던 문제를 수정했습니다. 화면 주소를 옛 단일 파일(`resources/routes.json`)에 적어 두어 관리자 화면에만 등록되고 있었습니다.
  - 문서의 구조대로 관리자용(`resources/routes/admin.json`)과 사용자용(`resources/routes/user.json`)으로 나눴고, 옛 파일을 읽을 때 남던 경고 로그도 더 남지 않습니다.
- 메모 목록(사용자 `/memos`, 관리자 메모 관리)을 주소 뒤 쪽 번호 없이 열면 쪽 번호가 빈 값(`page=undefined`)으로 요청돼 422 로 거절되고 메모가 한 건도 보이지 않던 문제를 수정했습니다. 쪽 번호가 없으면 1쪽을 요청합니다.
- 사용자 메모 목록의 쪽 제목과 메모 제목이 관리자 템플릿 전용 서식을 써서 사용자 화면에서는 본문 글자와 같은 크기·굵기로 나오고, 메모 카드가 간격 없이 붙어 보이던 문제를 수정했습니다.
  - Hello 사용자 템플릿에서는 메모 본문이 그 템플릿에 없는 문단 컴포넌트를 써서 빠지고 콘솔 오류가 났습니다.
  - 사용자 화면은 어느 사용자 템플릿에서나 쓰이는 서식과 기본 컴포넌트를 쓰고, 카드 사이에 간격을 둡니다.
  - 관리자 메모 관리 목록의 메모 카드도 같은 이유로 간격 없이 붙어 보이던 것을 함께 고쳤습니다.
- 메모 목록(사용자 `/memos`, 관리자 메모 관리)에 메모가 한 건도 없으면 제목 아래가 비어 불러오는 중인지 메모가 없는지 알 수 없던 문제를 수정했습니다. 이제 「아직 메모가 없습니다.」, 「작성된 메모가 없습니다.」 같은 안내 문구를 보여 줍니다.
- 메모 목록의 「새 메모」와 메모 작성·수정 화면이 권한 없는 관리자에게도 열려 저장할 때에야 거절되던 문제를 고쳤습니다. 이제 버튼이 잠기고 폼은 읽기 전용 안내와 함께 잠깁니다.

## [0.1.2] - 2026-09-06

### Added

- 개발자와 AI 에이전트를 위한 문서를 추가했습니다. 확장 폴더의 `AGENTS.md`(설계 의도·확장점·수정 시 확인할 것)와 `README.md`(도입·운영 안내), `docs/`(상세 문서)로 구성됩니다.
- 확장 문서에 「레이아웃 편집기 스펙」 항목을 추가했습니다. 이 확장이 레이아웃 편집기에 무엇을 선언했는지와, 화면 요소나 데이터를 추가할 때 편집기 쪽에서 함께 해야 할 일을 담습니다.
- 문서의 제품 표기를 「그누보드7」로 통일했습니다.

### Fixed

- 설정 파일의 프론트엔드 자산 항목이 문서화된 형식과 다른 목록형으로 적혀 있어 예제로 삼으면 스크립트가 로드되지 않는 형태였습니다. 선언할 자산이 없어 항목을 제거했습니다.

### Changed

- 확장 문서(README · AGENTS.md · docs/README.md)의 제목에 「그누보드7」과 확장 유형을 함께 표기했습니다. 제목만 보고도 그누보드7의 어떤 종류 확장인지 알 수 있습니다.
- Composer 잠금 파일을 확장 정보와 다시 맞췄습니다. 설치·업데이트 과정에서 잠금 파일이 오래되었다는 경고가 나오지 않습니다.

## [0.1.1] - 2026-08-10

### Fixed

- 관리자 메모 목록 화면에 메모가 하나도 보이지 않던 문제를 수정했습니다. 화면이 부르는 주소와 실제로 열려 있는 주소가 달라 목록을 받아오지 못하고 있었습니다.
- 메모 목록에서 한 페이지에 보여줄 개수를 0·음수·과도하게 큰 값으로 요청하면 오류가 나거나 메모 전체가 한 번에 조회되던 문제를 수정했습니다. 1~100 범위를 벗어나면 요청이 거부됩니다.

## [0.1.0] - 2026-07-01

### Fixed

- 메모 목록에서 작성·수정 화면에 다녀오면 보고 있던 페이지가 사라지고 1페이지로 되돌아가던 문제를 수정했습니다. (#75 @jiwonpapa 님께서 제보해주셨습니다.)
- 메모 목록에서 같은 시각에 등록된 메모가 여러 건일 때 페이지를 넘기면 같은 메모가 두 번 보이던 문제를 수정했습니다.

### Changed

- 메모 관리 화면의 콘텐츠 카드 외형을 sirsoft-admin_basic 표준 시맨틱 (.admin-card) 과 정합 — 다른 관리자 화면과 같은 결로 통일.
- 관리자 화면 좌우 정렬 컨테이너(섹션 헤더 · 액션바 · 카드 상단부 등) 외형을 표준 시맨틱(.flex-between)으로 정리 — 시각 변경 없음, 향후 톤 조정이 한 곳에서 가능.

### Added

- 학습용 최소 샘플 모듈 초기 릴리즈
- Memo 엔티티 Admin CRUD 및 공개 읽기 API
- 훅 발행 데모 (`gnuboard7-hello_module.memo.created`)
- 기본 권한 4종 (read, create, update, delete) 및 관리자 메뉴 등록
- 다국어 지원 (ko, en)
- 레이아웃 편집기 데이터 소스 목록에서 이 확장이 제공하는 데이터 소스가 친화 명칭으로 표시되고, 어느 확장이 제공했는지 출처가 함께 표시됩니다.
