# Changelog

이 프로젝트의 모든 주요 변경사항을 기록합니다.
형식은 [Keep a Changelog](https://keepachangelog.com/ko/1.1.0/)를 따르며,
[Semantic Versioning](https://semver.org/lang/ko/)을 준수합니다.

## [1.1.0] - 2026-10-10

### Added

- 확장 아이콘을 동봉했습니다. 관리자 확장 관리 화면과 설치 마법사에 표시됩니다.
- 환경설정 화면과 주문·결제·영수증 조각을 `.g7.html` 마크업 형식으로도 제공합니다. HTML 에 가까운 문법이라 화면 구조를 눈으로 따라가기 쉽고,
  기존 JSON 레이아웃도 그대로 함께 들어 있어 두 표기를 나란히 비교할 수 있습니다. 설치와 업데이트 뒤 화면 복원은 `.g7.html` 을 우선 읽으며(결과는 짝 JSON 과 같습니다), 그 파일만 고쳐도 화면에 반영됩니다.
- 나이스페이먼츠 간편결제 수단이 「환불 자동 승인 대상인지」를 쇼핑몰에 알려 줍니다. 결제취소가 즉시 처리되는 수단이므로 환불이 운영자 승인 없이 완료됩니다.
- 쇼핑몰 취소/반품/교환 신청의 추가결제(클레임 결제)를 지원합니다. 신청서의 배송비·상품 차액 결제가 주문 결제와 같은 결제창으로 진행되고, 신청 철회·반려 시 자동으로 환급됩니다.
- 영수증 조회 API 응답에 마이페이지 「결제 영수증」 링크가 여는 주소(`payment_receipt_url`)를 추가했습니다. 화면은 결제사 주소를 직접 적지 않고 이 값을 받아 표시하므로, 레이아웃 편집기에서 영수증 조각을 저장할 수 있습니다.
- 가상계좌 입금 안내·영수증·부가세 내역이 주문 상세뿐 아니라 같은 결제 정보 카드를 쓰는 다른 화면(취소·반품·교환 신청서 상세 등)에서도 표시됩니다. 이미 설치된 사이트는 업데이트 시 예전 등록 정보가 정리되어 같은 안내가 두 번 표시되지 않습니다.

### Changed

#### 가상계좌

- 가상계좌 계좌가 발급되면 주문한 상품을 장바구니에서 정리합니다. 종전에는 입금이 확인될 때까지 장바구니에 그대로 남아 있었습니다.
- 마이페이지 「가상계좌 입금 안내」의 입금 금액을 입금할 금액의 기준 필드인 결제예정금액에서 읽도록 맞췄습니다. 입금 대기 중에는 주문금액과 같은 값이라 화면 표시는 바뀌지 않습니다.

#### 환불·취소

- 가상계좌, 에스크로 결제와 결제한 달이 지난 휴대폰 결제는 취소 화면에서 「전액취소만 가능」으로 먼저 안내합니다. 이전에는 수량을 줄여 취소를 누른 뒤에야 결제사가 거절해 원인을 알 수 없는 실패로 보였습니다.
- 관리자 주문취소의 계약이 바뀌었습니다. 이제 쇼핑몰이 환불신청서를 만들고, 환불이 집행되는 시점에 이 플러그인의 환불 처리가 호출됩니다.
  - 가상계좌 환불 화면은 환불을 직접 끝내고 장부만 쇼핑몰에 맡기므로 같은 거래를 두 번 취소하지 않으며, 그 취소도 다른 경로와 같은 활동 이력을 남깁니다.
- 관리자 가상계좌 입금 완료 건 환불은 「환불 실행」 권한이 있어야 합니다(주문 수정 권한만으로는 거절).

#### 화면 조각·다국어

- 주문 완료 화면·마이페이지(비회원 포함) 주문 상세·신청서 상세·관리자 주문 상세의 나이스페이먼츠 표시(영수증·매출전표 링크, 간편결제
  이름)를 화면 주입 스크립트 대신 화면 조각이 그립니다. 종전 스크립트는 화면 주소로 어느 화면인지 알아보고 화면 이동을 가로채 글자를
  직접 고쳐 썼기 때문에, 쇼핑몰 경로 설정을 바꾸거나 다른 확장과 함께 설치하면 표시가 조용히 빠질 수 있었습니다.
  - 간편결제 이름(예: 카카오페이)은 결제수단 칸의 글자를 바꾸지 않고 「간편결제 서비스」 행으로 따로 보입니다.
  - 직접 만든 템플릿은 주문 완료 화면의 결제 금액 요약에 `order_complete_payment_summary` 자리, 결제 정보 카드에 `mypage_order_payment_provider_slot` 슬롯이 있어야 표시가 붙습니다.
- 플러그인 업데이트 뒤 결제 화면 확장을 되살리는 처리가 사용 중단 예정인 훅(`core.plugins.updated`) 대신 정규 훅
  `core.plugins.after_update` 를 구독합니다. 업데이트가 실패로 끝나면 되살리지 않습니다.
- 플러그인 업데이트 후 화면 확장을 복원할 때, 조각 파일 이름을 그대로 조각 식별자로 넘깁니다. 종전에는 식별자 없이
  등록해 대상 화면 이름이 식별자가 됐는데, 설치 경로는 파일 이름을 쓰므로 둘이 갈리면 같은 화면에 조각 행이
  둘 생기고 그 뒤로는 복원이 어느 행인지 가리지 못해 조용히 멈췄습니다. 이제 두 경로가 같은 식별자를 씁니다.
- 영어 화면의 주문 상세 가상계좌 안내 제목을 다른 결제대행사와 같은 「Virtual Account Deposit Guide」로 맞췄습니다.

#### 관리자·설정 화면

- 그누보드7 7.0.x 에서 올린 사이트에서 1.0.x 의 관리자 주문 목록 조각과 주문서 간편결제 조각 파일이 남아 업데이트 때 다시 등록되던 문제를 고쳤습니다. 주문 목록 조각은 관리자 주문 목록의 열을 1.0.x 판으로 통째 덮어 「클레임」 열이 사라지고 결제수단 칸의 결제 배지 자리가 무력화됐고, 간편결제 조각은 붙을 자리 없이 설정 조회만 한 번 더 했습니다. 업데이트가 남은 옛 조각 파일과 그 조각들로 등록된 화면 확장 행을 지웁니다.
- 관리자 쇼핑몰 설정 결제수단 목록의 간편결제 브랜드 마크는 결제수단 정보(브랜드 마크)로 쇼핑몰에 넘기고, 화면을 고쳐 그리던
  스크립트는 걷어냈습니다. 마크를 그리는 것은 쇼핑몰 관리자 화면 몫입니다.
- 관리자 주문 목록의 테스트 결제 표시가 이커머스가 결제수단 칸에 열어 둔 자리에 붙습니다. 표시 모양(주황색 「(테스트 결제)」)은 같고, 플러그인 업데이트 뒤에도 이 표시가 함께 되살아납니다.
  - 종전에는 표시 하나를 얹으려고 주문 목록 컬럼 전체를 복사해 덮었기 때문에, 이커머스가 목록을 고쳐도(부분취소 배지·적립 예정 포인트 등) 이 플러그인을 설치한 사이트에는 반영되지 않았고, 결제수단 칸이 다른 결제 플러그인의 테스트 결제 여부까지 읽었습니다.
- 간편결제로 결제한 주문의 관리자 주문 목록 결제수단 이름(예: 「PAYCO (페이코) (신용카드)」)을 화면이 따로 불러오던 표시 맵 대신 주문 목록 응답에 서버가 채워 보냅니다(이커머스 필터 훅 `sirsoft-ecommerce.order.filter_payment_method_display_label` 구독).
- 환경설정 화면의 안내 글자색(라이브 모드 경고)을 관리자 템플릿의 클래스에 기대지 않고 플러그인이 직접 제공합니다. 관리자 템플릿이 그 클래스의 이름이나 색을 바꿔도 이 화면의 색은 따라 바뀌지 않으며, 다크 모드 색도 함께 갖춥니다.

#### 결제창·주문서

- 결제창을 열 때 결제수단을 화면 상태에서 짐작하지 않고 쇼핑몰이 주문에 저장한 결제수단만 씁니다. 결제수단을 알 수 없으면 결제창을
  열지 않고 오류를 안내합니다.

#### 요구 버전·연동

- 코어 최소 요구 버전을 7.1.0 으로 상향 — 화면 마크업 형식(`.g7.html`)을 읽는 기능이 이 코어부터 제공됩니다.
- sirsoft-ecommerce 최소 버전을 1.3.0 으로 상향 — 주문 목록 결제수단 칸의 표시 자리와 표시 라벨 훅이 1.3.0 에서 도입됐습니다.
- 쇼핑몰(이커머스)이 1.3.0 보다 낮으면 이 플러그인 업데이트를 멈추고 원래 버전으로 되돌립니다. 이커머스를 먼저 업데이트한 뒤 다시 업데이트하세요. 종전에는 이 플러그인만 올라가 결제 화면이 오류로 열리지 않았습니다.
- 영수증 조회 API 응답을 다른 API 와 같은 공통 형식({ success, message, data })으로 바꿨습니다. 영수증 정보는 이제 `data` 안에 들어 있습니다 — 이 API 를 직접 부르던 사용자 정의 화면이나 스크립트는 `data` 에서 값을 읽도록 고쳐야 합니다.

### Removed

- 관리자 주문 목록용 간편결제 표시 맵 API(`GET /api/plugins/sirsoft-pay_nicepayments/admin/orders/easy-pay-display-map`)를 제거했습니다. 주문 목록은 이제 이커머스 주문 목록 응답의 결제수단 표시 이름(`payment.payment_method_display_label`)을 그대로 쓰므로 이 API 를 부르는 화면이 없습니다. 이 API 를 직접 호출하던 외부 연동이 있다면 이커머스 주문 목록 응답의 같은 값을 읽도록 바꿔 주세요.

### Fixed

#### 가상계좌

- 주문자 이름이 한글 6자 이상이면 가상계좌 결제창이 「예금주명 10bytes 이하」로 결제를 거절하던 문제를 고쳤습니다. 가상계좌 결제창에는 이름을 한도(한글 5자) 안으로 줄여 넘기고, 다른 결제수단은 그대로 넘깁니다.
- 결제사가 다른 형식의 입금 기한을 돌려주면 가상계좌가 발급되고도 주문에 기록되지 않고 주문서로 「결제 통화」 오류와 함께 되돌아가던 문제를 고쳤습니다. 이제 기한만 비워 두고 발급은 기록합니다.
- 가상계좌 계좌가 나이스페이먼츠 기본 기한(실측 10일)으로 열려 주문서 안내(쇼핑몰 「주문 자동취소」 기한)와 자동취소 시점이 어긋나던 문제를 고쳤습니다. 이제 주문의 입금 기한까지로 계좌를 엽니다.
- 가상계좌 입금 기한이 실제보다 9시간 늦게 저장되어, 주문완료·주문 상세에 기한이 다음 날 아침으로 보이고 기한 만료 처리도 그만큼 늦어지던 문제를 고쳤습니다. 결제사가 알려 주는 한국 시각의 기한을 서버 시각으로 바꾸지 않고 저장하고 있었습니다. 업데이트 전에 발급된 가상계좌의 기한은 바뀌지 않습니다.
- 입금 전에 취소한 가상계좌 주문의 주문 상세·신청서 상세에 입금 계좌와 입금 기한 안내가 그대로 보이던 문제를 고쳤습니다. 이제 취소된 주문에는 입금 안내가 나오지 않습니다.
- 입금 전에 취소한 주문의 가상계좌를 결제사에서 발급 취소합니다. 이전에는 계좌가 열린 채 남아 고객이 취소 뒤에도 입금할 수 있었습니다.
- 마이페이지 주문 상세에 가상계좌 입금 안내(입금 대기)와 영수증 행(결제 완료)이 두 번 나오던 것을 고칩니다. 이제 조각만 그리고 입금 기한은 쇼핑몰이 사용자 언어·시간대로 서식을 입힌 값을 씁니다.
  - 레이아웃 조각과 주입 스크립트가 같은 내용을 각각 그렸고, 스크립트 쪽은 영어·일본어 화면에서도 한국어 글자와 한국식 날짜였으며
    조각 쪽 입금 기한은 가공 전 값(`2026-09-30T23:59:59+09:00`)이었습니다.
  - 스크립트가 열던 매출전표는 조각 영수증 행의 「매출전표 보기」 링크로 옮겼습니다.

#### 환불·취소

- **전액취소가 부분취소로 잘못 요청되지 않습니다.** 전액취소인데도 부분취소 구분값이 함께 전달되어, 결제사에 원거래가 부분취소로 기록될 수 있었습니다. 이제 전액취소는 부분취소가 아님을 명시해 보내므로 결제사 원거래 상태와 상점 장부가 갈리지 않습니다.
- 환불 금액을 결제 통화 최소 단위로 반올림해 보냅니다. 이전에는 소수점 아래를 잘라, 다른 통화로 환산되는 주문에서 1원 적게 환불될 수 있었습니다(토스페이먼츠와 같은 규칙으로 맞췄습니다).
- 부분취소를 여러 번 하면 환불 기록의 결제사 거래번호에 취소 회차 번호가 붙어 회차별로 구분됩니다. 이전에는 모든 회차가 원거래 번호 하나로 기록됐습니다.

#### 결제창·주문서

- 손님이 결제창을 닫았을 때 결제 상태가 「결제 실패」로 남고 결제 취소 이력이 기록되지 않던 문제를 수정했습니다. 이제 다른 결제 플러그인(KG이니시스·NHN KCP·토스페이먼츠)과 같이 주문·결제·주문 상품이 모두 「취소」가 되고 결제 취소 이력이 1건 남습니다.
  - 결제창을 닫은 주문은 종전처럼 같은 주문으로 다시 결제할 수 있습니다.
- 주문 완료 화면과 마이페이지 주문 내역에서 현금영수증 보기 버튼을 눌러도 영수증이 열리지 않던 문제를 수정했습니다.

#### 화면 조각·다국어

- 주문 완료 화면 영수증 버튼 글자(「영수증 조회」·「로딩 중...」), 결제 실패 알림 2건, 영수증 행의 간편결제 이름(「네이버페이」 등)이
  영어·일본어 화면에서도 한국어로 나오던 것을 화면 언어로 고쳤습니다. 주문 완료 화면의 영수증 버튼은 영수증·매출전표 링크로 바뀌어
  다른 화면의 영수증 링크와 같은 번역 문구를 씁니다.
- 한국어·일본어 화면의 주문 상세·주문 완료와 관리자 주문 상세에 붙는 결제수단 표시 이름(간편결제 이름 포함)이 브라우저 기본 언어로 나올 수 있던 문제를 고쳤습니다. 이 정보를 그리던 화면 스크립트의 조회에 화면 언어가 실리지 않았습니다. 이제 화면 조각이 화면 언어로 조회합니다.
- 영어로 보는 관리자 주문 상세 「결제 조회」 창에서 가상계좌 입금 통지 금액이 「5,000원」으로 보이던 것을, 보는 언어의 원화 표기(영어 「₩5,000」)로 고쳤습니다.
- 관리자 주문 상세·마이페이지(비회원 포함) 주문 상세에서 결제수단 표시·영수증에 쓰는 결제 조회가 응답을 기다리지 않고
  수십 번 반복 호출되던 문제를 고쳤습니다(호출마다 결제대행사 API 까지 갑니다).
  - 이제 한 화면에 들어올 때 주소마다 한 번만 조회하고, 실패해도 다시 부르지 않으며, 다른 주문으로 옮기면 이전 조회를 멈춥니다.
  - 관리자 주문 상세의 결제수단 표시는 같은 화면이 이미 받아 둔 거래 조회 결과를 그대로 써서, 주문 상세를 열 때마다
    결제대행사 거래 조회가 두 번 나가던 것도 한 번으로 줄였습니다.

#### 관리자·설정 화면

- 다른 결제 플러그인과 **함께 설치했을 때** 관리자 주문 목록의 「테스트 결제」 배지가 하나만 보이던 문제를 수정했습니다. 결제사마다 배지를 다는데 나중에 적용되는 쪽이 앞의 것을 덮어써, 우선순위가 가장 높은 한 곳의 배지만 남았습니다. 이제 설치한 결제사 수와 무관하게 각자의 배지가 함께 표시됩니다.
- 관리자 주문 목록에 테스트 결제 배지를 넣는 화면 확장이 목록의 열 전체를 복사해 덮어쓰지 않고 그 열만 덧붙이도록 바뀌었습니다. 종전에는 이 플러그인을 설치하면 쇼핑몰 모듈이 나중에 추가한 열(취소/반품/교환 열 등)이 주문 목록에서 사라졌습니다.
- 다른 결제 플러그인과 함께 설치한 사이트의 관리자 주문 목록에서 이 플러그인으로 간편결제한 주문의 결제수단 이름이 기본 이름(신용카드 등)으로 보이던 문제를 수정했습니다.
- 관리자 주문 상세의 에스크로 배송 등록이 실패하면 이유와 상관없이 「등록에 실패했습니다」만 보이던 문제를 고쳤습니다. 이제 결제대행사가 거절한 사유나 빠진 입력 항목이 그대로 표시되며, 필수 항목을 모두 채우기 전에는 등록 버튼이 눌리지 않습니다.
- 에스크로 배송정보(택배사·송장번호·등록자·주소) 입력값이 저장되지 않아 빈 값으로 등록 요청이 전송되던 문제를 수정했습니다.
- 가상계좌 입금통보 요약(통보 횟수·최초/최근 시각·입금자)이 표시되지 않던 문제를 수정했습니다.
- 가상계좌 입금통보 내역을 불러온 뒤 화면에 반영되지 않던 문제를 수정했습니다.
- 가상계좌 입금통보 요약의 첫·마지막 통보 수신, 입금 확인, 입금 취소 시각과 통보 이력의 시각이 날짜 대신 알아볼 수 없는 문자열로 보이던 문제를 수정했습니다. 이제 `2026-09-28 10:11:12` 형식으로 보이고, 시각이 없으면 「-」로 표시됩니다.
- 관리자 주문 상세의 **결제 조회** 영역에서 아이콘이 빈칸으로 보이던 것을 고쳤습니다. 간편결제 수단의 대체 아이콘
  이름도 Font Awesome 이름으로 바꿨습니다.
- 플러그인 설정의 가상계좌 입금통보 주소 「복사」 버튼을 눌러도 아무 일도 일어나지 않던 문제를 수정했습니다. 없는 동작을 부르고 있었으며, 이제 주소가 클립보드에 복사되고 복사 완료 안내가 뜹니다. 어느 관리자 템플릿을 쓰든 같게 동작합니다.
- 환경설정을 저장하다 실패했을 때 어떤 항목이 잘못됐는지 표시되지 않던 문제를 수정했습니다. 이제 항목별 오류 안내가 나옵니다.
- 환경설정 화면에서 항목 이름·설명과 입력칸이 나란히 놓이지 않고 위아래로 쌓이던 문제와, 섹션 제목이 오류 안내처럼 붉은 작은 글자로
  보이던 문제를 수정했습니다. 저장 오류 상자의 제목과 목록 글자도 각자의 오류 안내 색으로 맞췄습니다.
- 관리자 주문 상세 결제 탭의 에스크로 안내 상자와 환경설정의 다크 모드 입력칸 포커스 테두리가 관리자 템플릿에 따라 색이 바뀌거나 빠지지 않도록 플러그인이 직접 싣습니다.
- 환경설정 「결제 실패 시 이동 주소」 안내가 실제 기본값(상점 주소 설정을 따르는 `{shopBase}`)과 다르게 「상대 경로 또는 전체 URL」 로만 안내되던 문구를 바로잡았습니다.
- 플러그인 설정을 바꿀 권한이 없는 관리자에게 설정 화면이 입력할 수 있는 상태로 열려 저장할 때에야 거절되던 문제를 고쳤습니다. 이제 「읽기 전용」 안내와 함께 입력·저장 버튼이 잠깁니다.
- 관리자 주문 상세의 에스크로 배송 등록 입력·버튼이 주문 수정 권한 없이도 열려 거절되던 문제를 고쳤습니다.

#### 결제 보안

- **취소된 주문이 뒤늦은 가상계좌 입금으로 되살아나지 않습니다.** 만료 자동취소된 주문에 뒤늦게 입금이 들어와도 그 주문을 결제완료로 바꾸지 않으므로, 재고와 마일리지가 한 번 더 차감되지 않습니다. 취소된 주문에 온 입금 통보는 기록하고 운영자에게 알립니다.
- 설정 화면의 결제 후 이동 주소(성공·실패)에 「not a url」 같은 아무 글자나 저장돼, 결제를 마친 구매자가 깨진 주소로 보내지던 문제를 고쳤습니다. 이제 `{shopBase}`·`/`·`http(s)://` 로 시작하지 않거나 공백이 있는 주소, 다른 사이트로 보내는 `//주소`·`javascript:` 는 칸별 오류로 저장되지 않습니다.

### Security

- 결제창을 닫았다는 보고를 주문한 본인만 보낼 수 있게 했습니다. 이전에는 주문번호·결제 금액·주문자 이메일과 전화번호만 알면 로그인 없이도 결제 진행 중인 남의 주문을 취소시킬 수 있었습니다. (KISA 측에서 제보해주셨습니다 — KVE-2026-2434)
  - 이제 회원 주문은 주문한 회원의 로그인으로, 비회원 주문은 주문할 때 브라우저가 받은 조회 확인값으로만 보고를 받으며, 주문자 연락처는 더 이상 보내지도 확인하지도 않습니다.
  - 확인에 실패한 보고는 주문을 전혀 건드리지 않고, 결제를 끝내지 않은 주문은 종전처럼 결제 대기 만료 정리가 처리합니다.
- 결제 인증 결과 처리 중 승인이 거절되거나 오류가 나도 주문을 결제 실패로 바꾸지 않고 승인만 취소하도록 했습니다. 결제사 서명이 주문번호를 포함하지 않아, 자기 결제창에서 받은 인증값에 남의 주문번호를 붙여 보내면 그 주문이 취소될 수 있었습니다. (KISA 측에서 제보해주셨습니다 — KVE-2026-2434)
  - 승인이 성공해도 결제사가 돌려준 주문번호·금액이 다르면 반영하지 않습니다. 결제를 끝내지 못한 주문은 같은 주문으로 다시 결제할 수 있습니다.
- 실패한 주문을 다시 결제할 때 주문을 결제 대기로 되살리는 처리를 주문한 본인에게만 허용합니다. 이전에는 주문자 연락처만 알면 남의 취소된 주문을 되살릴 수 있었습니다. (KISA 측에서 제보해주셨습니다 — KVE-2026-2434)
- 결제를 완료하거나 가상계좌 발급을 기록할 때 브라우저가 보낸 금액이 아니라 나이스페이먼츠가 승인한 금액을 주문 청구액과 대조합니다. 승인 응답에 금액이 없거나 청구액과 다르면 결제를 반영하지 않고 승인을 자동으로 취소합니다.
  - 가상계좌는 가상계좌로 주문한 건에 청구액과 같은 금액으로 발급된 경우에만 기록하며, 입금 통보를 받으면 나이스페이먼츠에 거래를 직접 조회해 입금이 확인된 경우에만 결제완료로 처리합니다.
- 결제 결과 화면으로 보내는 이동 주소와 나이스페이먼츠에 넘기는 복귀 주소를 요청의 Host 헤더가 아니라 사이트 주소로 만듭니다. 결제 인증 콜백의 입력값이 잘못된 경우에도 사이트의 결제 실패 화면으로 이동하고, 영수증 창은 열린 창이 결제 화면을 조작하지 못하게 엽니다. 가상계좌 입금통보·결제 서명 요청에 형식이 틀린 요청이 오면 직전 화면으로 이동시키지 않고 422 오류로 응답합니다.
