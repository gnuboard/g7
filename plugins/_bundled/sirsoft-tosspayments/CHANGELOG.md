# Changelog

이 프로젝트의 모든 주요 변경사항을 기록합니다.
형식은 [Keep a Changelog](https://keepachangelog.com/ko/1.1.0/)를 따르며,
[Semantic Versioning](https://semver.org/lang/ko/)을 준수합니다.

## [1.1.0] - 2026-10-10

### Added

- 확장 아이콘을 동봉했습니다. 관리자 확장 관리 화면과 설치 마법사에 표시됩니다.
- 환경설정 화면과 주문·결제 조각(관리자 주문 상세, 마이페이지 주문 상세, 주문서 오류 안내)을 `.g7.html` 마크업 형식으로도 제공합니다. HTML 에 가까운 문법이라 화면 구조를 눈으로 따라가기 쉽고,
  기존 JSON 레이아웃도 그대로 함께 들어 있어 두 표기를 나란히 비교할 수 있습니다. 설치와 업데이트 뒤 화면 복원은 `.g7.html` 을 우선 읽으며(결과는 짝 JSON 과 같습니다), 그 파일만 고쳐도 화면에 반영됩니다.
- **레이아웃 편집기에서 토스페이먼츠 설정 화면을 볼 수 있습니다.** 편집기 표본이 없어 입력칸이 모두 비어 있던 것을 채우고, 검수/운영 모드와 검증 실패 화면을 상태로 고를 수 있게 했습니다.
- 토스 결제수단이 「환불 자동 승인 대상인지」를 쇼핑몰에 알려 줍니다. 신용카드와 간편결제(토스페이·카카오페이·네이버페이·페이코·삼성페이)는 결제취소가 즉시 처리되므로 환불이 자동으로 완료되고, 가상계좌·계좌이체·휴대폰결제는 환불계좌 확인이 필요하므로 운영자 승인 뒤 처리됩니다.
- 쇼핑몰 취소/반품/교환 신청의 추가결제(클레임 결제)를 지원합니다. 신청서의 배송비·상품 차액 결제가 주문 결제와 같은 결제창으로 진행되고, 신청 철회·반려 시 자동으로 환급됩니다.
  - 결제가 실패하면 결제사가 알려 준 사유 코드가 화면에 그대로 표시되고, 관리자용 상세 사유와 결제사 원본 응답도 결제 건에 함께 남습니다 — 카드사 거절·한도 초과·결제 시간 만료를 구분할 수 있습니다.
  - 결제창을 열어 둔 사이에 청구액이 바뀌면(신청 사유를 바꿔 왕복 배송비 부담이 달라지는 경우 등) 결제가 진행되기 전에 멈추고 다시 시작하도록 안내합니다 — 결제하신 금액이 빠져나갔다가 취소로 되돌아오는 일이 생기지 않습니다.
  - 결제창을 닫으면 신청서 상세로 돌아가 안내가 표시되며, 신청과 결제 건은 그대로 남아 다시 결제할 수 있습니다.
- 가상계좌 입금 안내와 영수증이 주문 상세뿐 아니라 같은 결제 정보 카드를 쓰는 다른 화면(비회원 주문 상세, 취소·반품·교환 신청서 상세 등)에서도 표시됩니다. 이미 설치된 사이트는 업데이트 시 예전 등록 정보가 정리되어 같은 안내가 두 번 표시되지 않습니다.
  - 직접 만든 템플릿은 결제 정보 카드에 `mypage_order_payment_provider_slot` 슬롯이 있어야 표시가 붙습니다.
- 가상계좌로 주문하면 주문 상세(회원·비회원)와 신청서 상세의 결제 정보에 은행·계좌번호·예금주·입금 금액·입금 기한을 안내합니다. 입금 전에는 기한이 지나면 주문이 자동 취소된다는 경고를 함께 보이고, 취소된 주문에는 계좌를 보이지 않습니다. 종전에는 결제 방법만 보였습니다.

### Changed

#### 가상계좌

- 가상계좌 계좌가 발급되면 주문한 상품을 장바구니에서 정리합니다. 종전에는 입금이 확인될 때까지 장바구니에 남아 있었습니다.

#### 환불·취소

- 에스크로 결제와 결제한 달이 지난 휴대폰 결제는 취소 화면에서 「전액취소만 가능」으로 먼저 안내합니다. 이전에는 수량을 줄여 취소를 누른 뒤에야 결제사가 거절해 원인을 알 수 없는 실패로 보였습니다.
- 관리자 주문취소의 계약이 바뀌었습니다. 이제 쇼핑몰이 환불신청서를 만들고, 환불이 집행되는 시점에 이 플러그인의 환불 처리가 호출됩니다.

#### 화면 조각·다국어

- 플러그인 업데이트 뒤 결제 화면 확장을 되살리는 처리가 사용 중단 예정인 훅(`core.plugins.updated`) 대신 정규 훅
  `core.plugins.after_update` 를 구독합니다. 업데이트가 실패로 끝나면 되살리지 않습니다.
- 플러그인 업데이트 후 화면 확장을 복원할 때, 조각 파일 이름을 그대로 조각 식별자로 넘깁니다. 종전에는 식별자 없이
  등록해 대상 화면 이름이 식별자가 됐는데, 설치 경로는 파일 이름을 쓰므로 둘이 갈리면 같은 화면에 조각 행이
  둘 생기고 그 뒤로는 복원이 어느 행인지 가리지 못해 조용히 멈췄습니다. 이제 두 경로가 같은 식별자를 씁니다.

#### 관리자·설정 화면

- 관리자 쇼핑몰 설정의 결제수단 목록에 간편결제 브랜드 배지를 붙이려고 이 플러그인이 쇼핑몰 화면을 직접 고치던 방식을 걷어냈습니다.
  배지 색·글자는 이 플러그인이 결제수단 정보에 실어 알려 주고, 화면은 쇼핑몰이 그립니다. 브라우저의 화면 이동 처리를 덮어쓰지 않으므로
  다른 확장과 부딪쳐 배지가 사라지거나 화면 이동이 엉키는 일이 없어집니다.
- 설정 「웹훅 secret 검증」의 안내에, 끄면 주문번호만 아는 사람도 입금 없이 가상계좌 주문을 결제완료로 만들 수 있고 끈 상태에서 생긴 보안 사고는 운영자 책임이라는 점을 적었습니다. 기본값(켜짐)과 동작은 그대로입니다.

#### 결제창·주문서

- 결제창을 닫거나 결제에 실패하고 돌아왔을 때의 실패 보고가 사이트 공통 요청 경로로 나갑니다. 로그인이 만료됐을 때 다시 로그인하도록
  안내받고, 비회원은 주문 조회 화면과 같은 주문 확인 정보로 본인 주문임을 증명합니다.
- 결제창은 주문서에서 넘긴 결제수단 또는 서버가 주문에 저장한 결제수단으로만 정합니다. 화면에 남아 있던 선택값은 보지 않아, 클레임 추가결제처럼
  주문서가 아닌 화면에서 서버와 다른 수단으로 결제창이 열리지 않습니다.

#### 요구 버전·연동

- 코어 최소 요구 버전을 7.1.0 으로 상향 — 화면 마크업 형식(`.g7.html`)을 읽는 기능이 이 코어부터 제공됩니다.
- 쇼핑몰(sirsoft-ecommerce) 모듈 최소 버전을 1.3.0 으로 상향했습니다.
- 쇼핑몰(이커머스)이 1.3.0 보다 낮으면 이 플러그인 업데이트를 멈추고 원래 버전으로 되돌립니다. 이커머스를 먼저 업데이트한 뒤 다시 업데이트하세요. 종전에는 이 플러그인만 올라가 결제 화면이 오류로 열리지 않았습니다.
- 결제창 복귀 기록(`g7:sirsoft-tosspayments:pendingClose`)을 개인정보 동의 플러그인에 필수 저장 항목으로 직접 제공합니다. 그 플러그인은 동의 전
  방문자의 브라우저에서 목록 밖 항목을 지우는데, 지금까지는 그 플러그인이 이 항목 이름을 대신 들고 있었습니다.
  동의 플러그인의 클래스를 참조하지 않으므로 그 플러그인이 없어도 이 플러그인은 그대로 동작합니다.

### Fixed

#### 가상계좌

- 가상계좌 입금 기한이 실제보다 9시간 늦게 저장되어, 주문완료·주문 상세에 기한이 다음 날 아침으로 보이고 기한 만료 처리도 그만큼 늦어지던 문제를 고쳤습니다. 결제사가 알려 주는 한국 시각의 기한을 서버 시각으로 바꾸지 않고 저장하고 있었습니다. 업데이트 전에 발급된 가상계좌의 기한은 바뀌지 않습니다.
- 입금 전에 취소한 주문의 가상계좌를 결제사에서 발급 취소합니다. 이전에는 계좌가 열린 채 남아 고객이 취소 뒤에도 입금할 수 있었습니다.

#### 환불·취소

- 결제 취소 요청의 멱등키에 취소 금액과 환불계좌를 넣었습니다. 운영자가 금액이나 계좌를 고쳐 같은 환불을 다시 실행하면 토스가 앞 요청의 응답을 그대로 돌려줘, 고친 금액이 취소되지 않았습니다.
- **면세 상품이 섞인 주문을 여러 번 나누어 환불해도 마지막 회차가 거부되지 않습니다.** 이제 남은 면세 한도 안에서만 금액을 보내며, 취소할 때마다 결제사가 기록한 면세 사용량을 함께 갱신해 다음 회차가 정확한 한도를 알 수 있습니다.
  - 과세·면세 상품을 함께 담은 주문을 부분환불할 때, 회차마다 계산한 면세 금액의 합이 결제 승인 때 등록된 면세 금액을 넘어서게 되어, 마지막 환불이 「취소 할 수 없는 금액 입니다.」로 거부되고 잔액이 남은 채 주문을 닫지 못했습니다.
- 주문 환불에서 토스 취소가 성공했는데 내부 기록 저장이 실패해도 환불이 실패로 표시되지 않습니다.

#### 현금영수증

- 현금영수증 발급이 「필수 파라미터가 누락되었습니다」 오류로 실패하던 문제를 수정했습니다. 상점의 토스페이먼츠
  API 버전에 따라 구매자 인증수단을 담는 항목 이름이 달라, 한쪽 버전을 쓰는 상점에서는 발급이 전혀 되지 않았습니다.
- 현금영수증이 발급됐는데 발급번호가 비어 있던 문제를 수정했습니다. 같은 API 버전 차이로 발급번호가 다른 항목으로
  내려오던 경우이며, 이제 어느 버전에서도 발급번호가 주문 내역과 발급 이력에 기록됩니다.

#### 관리자·설정 화면

- **가상계좌·계좌이체·휴대폰 결제수단에 토스페이먼츠를 지정할 수 있습니다.** 이 플러그인이 지원한다고 알리는 결제수단 이름이 쇼핑몰이 쓰는 이름과 달라, 결제수단 설정에서 세 수단에 토스페이먼츠를 고를 수 없었습니다. 카드만 연결되어 나머지 수단은 결제 제공사를 지정하지 못한 채 남았습니다.
- 플러그인 설정의 입금통보 웹훅 주소 「복사」 버튼을 눌러도 아무 일도 일어나지 않던 문제를 수정했습니다. 없는 동작을 부르고 있었으며, 이제 주소가 클립보드에 복사되고 복사 완료 안내가 뜹니다. 어느 관리자 템플릿을 쓰든 같게 동작합니다.
- 플러그인 설정의 입금통보 웹훅 주소가 사이트 주소 없이 경로(`/plugins/sirsoft-tosspayments/webhook/deposit`)로만 표시·복사되던 문제를 수정했습니다. 이제 다른 결제사 플러그인처럼 사이트 주소까지 붙은 전체 주소(예: `https://내도메인/plugins/sirsoft-tosspayments/webhook/deposit`)를 보여 주고 복사하므로 토스 개발자센터에 그대로 붙여 넣으면 됩니다.
- 환경설정 경고 상자 안 링크에 마우스를 올렸을 때 색이 바뀌지 않던 문제를 수정했습니다.

#### 결제 보안

- **취소된 주문이 뒤늦은 가상계좌 입금 통보로 되살아나지 않습니다.** 만료 자동취소된 주문에 뒤늦게 입금 통보가 들어와도 그 주문을 결제완료로 바꾸지 않으므로, 재고와 마일리지가 한 번 더 차감되지 않습니다. 취소된 주문에 온 입금 통보는 기록하고 운영자에게 알립니다.
- 설정 화면의 결제 후 이동 주소(성공·실패)에 「not a url」 같은 아무 글자나 저장돼, 결제를 마친 구매자가 깨진 주소로 보내지던 문제를 고쳤습니다. 이제 `{shopBase}`·`/`·`http(s)://` 로 시작하지 않거나 공백이 있는 주소, 다른 사이트로 보내는 `//주소`·`javascript:` 는 칸별 오류로 저장되지 않습니다.
- 플러그인 설정을 바꿀 권한이 없는 관리자에게 설정 화면이 입력할 수 있는 상태로 열려 저장할 때에야 거절되던 문제를 고쳤습니다. 이제 「읽기 전용」 안내와 함께 입력·저장 버튼이 잠깁니다.

### Security

- 결제창을 닫았다는 보고를 주문한 본인만 보낼 수 있게 했습니다. 이전에는 주문번호·결제 금액·주문자 이메일과 전화번호만 알면 로그인 없이도 결제 진행 중인 남의 주문을 취소시킬 수 있었습니다. (KISA 측에서 제보해주셨습니다 — KVE-2026-2434)
  - 이제 회원 주문은 주문한 회원의 로그인으로, 비회원 주문은 주문할 때 브라우저가 받은 조회 확인값으로만 보고를 받으며, 주문자 연락처는 더 이상 보내지도 확인하지도 않습니다.
  - 확인에 실패한 보고는 주문을 전혀 건드리지 않고, 결제를 끝내지 않은 주문은 종전처럼 결제 대기 만료 정리가 처리합니다.
- 결제를 완료하거나 가상계좌를 발급할 때 브라우저가 전달한 금액이 아니라 주문에 저장된 결제 금액으로 승인을 요청하고, 토스페이먼츠가 실제로 승인한 금액을 그 금액과 대조합니다. 두 금액이 다르거나 확인할 수 없으면 결제를 완료 처리하지 않고 이미 승인되었거나 발급된 결제를 자동으로 취소합니다. (KISA 측에서 제보해주셨습니다 — KVE-2026-2135)
  - 이미 결제가 끝났거나 취소된 주문은 다시 승인하지 않습니다.
  - 가상계좌 입금 알림도 발급 때 확인한 금액, 또는 토스페이먼츠 결제 조회로 확인한 금액이 주문 금액과 같을 때만 결제완료로 처리합니다.
- 결제 승인·취소가 끝났을 때 다른 확장에 알리는 훅에서 가상계좌 입금 알림 검증값을 뺐습니다. 이 값은 입금 알림이 토스페이먼츠에서 온 것인지 확인하는 데 쓰이는데, 그 훅을 백그라운드 작업으로 처리하는 확장이 있으면 작업 기록에 사본이 남을 수 있었습니다.
  - 그 밖의 결제 정보는 종전과 같이 전달됩니다.
  - 확장 개발자 참고: `sirsoft-tosspayments.payment.after_confirm`·`sirsoft-tosspayments.payment.after_cancel` 이 넘기는 토스 응답 배열에 `secret` 키가 더 이상 없습니다 — 입금 알림 대조가 필요하면 결제 정보에 저장된 값을 쓰세요.
- 결제 결과 화면으로 보내는 이동 주소와 토스페이먼츠에 넘기는 성공·실패 주소를 요청의 Host 헤더가 아니라 사이트 주소로 만듭니다. 사이트 주소의 하위 도메인이나 다른 포트로 들어온 요청에서는 결제 결과 화면 대신 그 주소로 이동할 수 있었습니다.
  - 성공·실패 콜백의 입력값이 잘못된 경우에도 직전 화면(Referer)이 아니라 사이트의 결제 실패 화면으로 이동합니다.
  - 입금·결제 상태 웹훅에 형식이 틀린 요청이 오면 직전 화면으로 이동시키지 않고 422 오류로 응답합니다.

### Security

- 결제창 프로그램을 불러오는 주소가 토스페이먼츠의 주소인지 불러오기 직전에 확인합니다. 확인되지 않는 주소면 결제를 진행하지 않고 안내를 표시합니다. 또한 결제창 프로그램이 실제로 준비되었는지를 기준으로 다음 단계를 진행하도록 바꿔, 프로그램이 아직 준비되지 않았는데 결제창이 열리지 않고 멈추던 상황을 없앴습니다.
- 제3자가 남의 주문번호만 알면 주소 하나로 그 주문을 취소시킬 수 있던 문제를 수정했습니다. 결제 실패 안내 주소는 로그인도 서명 확인도 거치지 않고 주문번호와 실패 사유를 주소에 담아 받는 경로여서, 그 주소를 열기만 해도 해당 주문이 결제 실패로 처리되었습니다. 이제 이 주소는 주문 상태를 바꾸지 않고 결제 화면으로 되돌려 보내기만 합니다. 결제 성립은 종전처럼 서버 승인 확인으로, 결제완료 후 취소는 서명이 확인된 입금·취소 통보로 처리됩니다.

### Added

## [1.0.0] - 2026-08-10

### Added

- 레이아웃 편집기 데이터 소스 목록에서 이 확장이 제공하는 데이터 소스가 친화 명칭으로 표시되고, 어느 확장이 제공했는지 출처가 함께 표시됩니다.

#### 결제 방식

- 주문서형 결제 모드를 지원합니다. 켜면 체크아웃에서 카드·가상계좌·계좌이체·휴대폰·간편결제(토스페이·카카오페이·네이버페이·페이코·삼성페이) 중 원하는 결제수단을 직접 선택할 수 있고, 끄면 기존처럼 통합결제창 하나로 결제합니다.
- 설정 화면에서 노출할 결제수단을 개별로 켜고 끌 수 있습니다.
- 원화(KRW) 외 통화 주문에서는 카드 결제만 허용하고 국내 전용 수단은 자동으로 차단합니다.

#### 가상계좌

- 가상계좌 결제를 지원합니다. 입금 기한(시간)과 발급 시 자동 현금영수증 유형을 설정할 수 있습니다.
- 입금이 완료되면 토스 입금통보를 받아 주문을 자동으로 결제완료 처리합니다. 위조 요청을 막기 위한 secret 검증을 제공하며, 설정 화면에서 등록할 웹훅 URL을 복사할 수 있습니다.
- 가상계좌 입금기한과 에스크로 사용 설정을 저장할 때 허용 범위를 서버에서 검증합니다. 입금기한이 1~2160시간(최대 90일)을 벗어나면 저장되지 않고 안내 메시지가 표시됩니다 — 잘못된 값이 저장되어 결제창 호출이 실패하는 것을 막습니다.

#### 에스크로

- 가상계좌·계좌이체 결제에 에스크로(구매안전서비스)를 적용할 수 있습니다. 사용 안 함 / 강제 사용 / 구매자 선택 중에서 고를 수 있습니다.
- 에스크로 결제 시 결제창에 상품 정보(상품명·단가·수량)를 함께 전달합니다. 가상계좌와 계좌이체 모두에 적용됩니다.
- 에스크로를 켜면 설정 화면에 운영 안내가 표시됩니다 — 에스크로 주문은 부분취소가 불가하다는 점과, 배송정보는 토스 상점관리자에서 등록해야 한다는 점을 안내하며 상점관리자로 바로 이동할 수 있습니다.
- 에스크로로 결제된 주문은 관리자 주문 상세와 구매자 주문 상세에 에스크로 거래임이 표시됩니다.

#### 현금영수증

- 현금영수증을 토스페이먼츠로 발급할 수 있습니다. 결제는 다른 PG로 받으면서 현금영수증만 토스페이먼츠로 발급하는 구성도 가능합니다.
- 부분환불 등으로 주문 금액이 바뀌면 기존 영수증을 취소하고 새 금액으로 다시 발급합니다. 재발급 시에도 중복 없이 처리됩니다.

#### 영수증 확인

- 주문상세(구매자·관리자)에서 토스페이먼츠 영수증을 바로 열어볼 수 있습니다. 관리자 화면에서는 가상계좌 입금 정보와 에스크로 여부도 함께 확인할 수 있습니다.

### Changed
