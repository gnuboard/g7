# Changelog

이 프로젝트의 모든 주요 변경사항을 기록합니다.
형식은 [Keep a Changelog](https://keepachangelog.com/ko/1.1.0/)를 따르며,
[Semantic Versioning](https://semver.org/lang/ko/)을 준수합니다.

## [1.2.0] - 2026-10-10

### Added

- 확장 아이콘을 동봉했습니다. 관리자 확장 관리 화면과 설치 마법사에 표시됩니다.
- 환경설정 화면과 주문·결제 조각을 `.g7.html` 마크업 형식으로도 제공합니다. HTML 에 가까운 문법이라 화면 구조를 눈으로 따라가기 쉽고,
  기존 JSON 레이아웃도 그대로 함께 들어 있어 두 표기를 나란히 비교할 수 있습니다. 설치와 업데이트 뒤 화면 복원은 `.g7.html` 을 우선 읽으며(결과는 짝 JSON 과 같습니다), 그 파일만 고쳐도 화면에 반영됩니다.
- 쇼핑몰의 개인정보 보유기간 처리가 주문을 익명화하면, 그 주문의 에스크로 배송 등록에 남아 있던
  **수령인 이름·주소도 함께 지웁니다**(쇼핑몰 1.3.0 이상). 송장번호·택배사 기록은 남습니다.
- KG이니시스 결제수단이 「환불 자동 승인 대상인지」를 쇼핑몰에 알려 줍니다. 간편결제는 결제취소가 즉시 처리되므로 환불이 자동으로 완료되고, 편의점 결제는 현금으로 받은 금액이라 운영자가 승인 뒤 계좌로 송금해 처리합니다.
- 쇼핑몰 취소/반품/교환 신청의 추가결제(클레임 결제)를 지원합니다. 신청서의 배송비·상품 차액 결제가 주문 결제와 같은 결제창으로 진행되고, 신청 철회·반려 시 자동으로 환급됩니다.
- 가상계좌 입금 안내·영수증·부가세 내역이 주문 상세뿐 아니라 같은 결제 정보 카드를 쓰는 다른 화면(취소·반품·교환 신청서 상세 등)에서도 표시됩니다. 이미 설치된 사이트는 업데이트 시 예전 등록 정보가 정리되어 같은 안내가 두 번 표시되지 않습니다.
  - 직접 만든 템플릿은 결제 정보 카드에 `mypage_order_payment_provider_slot` 슬롯이 있어야 표시가 붙습니다.
- 엔화(JPY) 기준 상점에서도 취소/반품/교환 신청의 추가결제를 일본 결제(CBT) 결제창으로 받을 수 있습니다. 결제 결과는 주문 완료 화면이 아니라 그 신청서 상세로 돌아가며, 신청 철회·반려 시 환급도 같은 일본 결제 경로로 처리됩니다.
  - 편의점(CVS)처럼 입금을 기다리는 방식은 추가결제로 받을 수 없어 거절하고 발급분을 되돌립니다. 원화로 청구되는 추가결제가 이 경로로 오면 국내 결제로 안내합니다.

### Changed

#### 가상계좌

- 가상계좌 계좌가 발급되면 주문한 상품을 장바구니에서 정리합니다. 종전에는 입금이 확인될 때까지 장바구니에 그대로 남아 있었습니다.
- 영수증 조회 API 응답에 가상계좌 은행코드(`vbank_bank_code`)를 담습니다. 주문 상세 입금 안내에서 관리자에게만 보입니다.

#### 환불·취소

- 에스크로 결제와 결제한 달이 지난 휴대폰 결제는 취소 화면에서 「전액취소만 가능」으로 먼저 안내합니다. 이전에는 수량을 줄여 취소를 누른 뒤에야 결제사가 거절했습니다.
- 관리자 주문취소의 계약이 바뀌었습니다. 이제 쇼핑몰이 환불신청서를 만들고, 환불이 집행되는 시점에 이 플러그인의 환불 처리가 호출됩니다. 가상계좌 환불 화면처럼 플러그인이 환불을 직접 끝내는 경로는 장부만 쇼핑몰에 맡기며, 같은 거래를 두 번 취소하지 않습니다.
- 관리자 주문 상세의 CBT [환불 재시도]는 「환불 실행」 권한이 있어야 합니다. 권한이 없으면 버튼이 잠기고 서버도 거절합니다.

#### 화면 조각·다국어

- 주문 상세·신청서 상세(회원·비회원)·주문 완료·관리자 주문 상세의 KG이니시스 결제 정보(간편결제 이름, 가상계좌·일본 편의점 입금 안내,
  영수증·결제확인서 버튼)를 화면 조각이 그립니다. 종전에는 화면 스크립트가 주소 글자(`/shop/…`·`/mypage/…`)를 보고 화면에 끼워 넣어,
  쇼핑몰 경로를 바꾼 사이트에서는 이 정보가 조용히 빠졌습니다.
  - 간편결제 이름은 결제 방법 값을 덮어쓰지 않고 「간편결제」 한 줄로 따로 보이며, 관리자 주문 상세에서는 결제수단 칸 아래에 「간편결제: 카카오페이」처럼 덧붙습니다.
  - 주문 완료 화면의 영수증 버튼은 결제 금액 요약 아래로 옮겼습니다(템플릿이 그 자리에 `order_complete_payment_summary` id 를 달아야 보입니다).
- 플러그인 업데이트 뒤 결제 화면 확장을 되살리는 처리가 사용 중단 예정인 훅(`core.plugins.updated`) 대신 정규 훅
  `core.plugins.after_update` 를 구독합니다. 업데이트가 실패로 끝나면 되살리지 않습니다.
- 플러그인 업데이트 후 화면 확장을 복원할 때, 조각 파일 이름을 그대로 조각 식별자로 넘깁니다. 종전에는 식별자 없이
  등록해 대상 화면 이름이 식별자가 됐는데, 설치 경로는 파일 이름을 쓰므로 둘이 갈리면 같은 화면에 조각 행이
  둘 생기고 그 뒤로는 복원이 어느 행인지 가리지 못해 조용히 멈췄습니다. 이제 두 경로가 같은 식별자를 씁니다.
- 영어 화면의 주문 상세 가상계좌 안내 제목을 다른 결제대행사와 같은 「Virtual Account Deposit Guide」로 맞췄습니다.

#### 관리자·설정 화면

- 그누보드7 7.0.x 에서 올린 사이트에서 1.1.x 의 관리자 주문 목록 조각 파일이 남아 업데이트 때 다시 등록되고, 관리자 주문 목록의 열을 1.1.x 판으로 통째 덮어 「클레임」 열이 사라지고 결제수단 칸의 결제 배지 자리가 무력화되던 문제를 고쳤습니다. 업데이트가 남은 옛 조각 파일과 그 조각으로 등록된 화면 확장 행을 지웁니다.
- 관리자 쇼핑몰 설정 결제수단 목록의 간편결제 브랜드 마크는 결제수단 목록 정보에 실린 로고를 그대로 씁니다(화면 스크립트가 아이콘을
  바꿔 끼우던 방식을 없앴습니다).
- 관리자 주문 목록의 테스트 결제 표시가 이커머스가 결제수단 칸에 열어 둔 자리에 붙습니다. 표시 모양(주황색 「(테스트 결제)」)은 같고, 플러그인 업데이트 뒤에도 이 표시가 함께 되살아납니다.
  - 종전에는 표시 하나를 얹으려고 주문 목록 컬럼 전체를 복사해 덮었기 때문에, 이커머스가 목록을 고쳐도(부분취소 배지·적립 예정 포인트 등) 이 플러그인을 설치한 사이트에는 반영되지 않았고, 결제수단 칸이 다른 결제 플러그인의 테스트 결제 여부까지 읽었습니다.
- 환경설정 화면의 안내 글자색(라이브 모드 경고, 일본 결제(CBT) 테스트 도우미와 연결 진단 안내, 점검 결과)을 관리자 템플릿의 클래스에 기대지 않고 플러그인이 직접 제공합니다. 관리자 템플릿이 그 클래스의 이름이나 색을 바꿔도 이 화면의 색은 따라 바뀌지 않으며, 다크 모드 색도 함께 갖춥니다.
- 편의점 결제 [재확인]은 결제 기록에 재확인 시각을 남기므로 주문 수정 권한이 있어야 합니다.
- 설정 화면의 [CBT 연결 진단]은 플러그인 설정 수정 권한으로도 쓸 수 있습니다.

#### 결제창·주문서

- 엔화 결제수단 제한을 서버가 판정합니다. 주문서에 보이는 결제수단과 주문 접수 검증이 같은 판정을 쓰므로, 화면을 거치지 않은 주문
  요청으로도 제한을 넘을 수 없습니다. 쇼핑몰 경로가 `/shop` 이 아닌 사이트에서도 동작합니다.
- 결제창을 닫았을 때 주문서 결제 버튼의 잠금 해제를 쇼핑몰 경로 설정에 맞춰 판정합니다. 쇼핑몰 경로를 바꾼 사이트에서 결제창을 닫으면
  버튼이 잠긴 채 남던 문제가 사라집니다.
- 결제창 진입은 서버가 주문에 저장한 결제수단으로만 결제창을 엽니다. 결제수단 정보가 없으면 다른 수단으로 대신 열지 않고 결제 오류 안내를 띄웁니다.

#### 요구 버전·연동

- 코어 최소 요구 버전을 7.1.0 으로 상향 — 화면 마크업 형식(`.g7.html`)을 읽는 기능이 이 코어부터 제공됩니다.
- sirsoft-ecommerce 최소 버전을 1.3.0 으로 상향 — 주문 목록 결제수단 칸의 표시 자리, 클레임 추가결제, 가상계좌 발급 후속 처리가 1.3.0 에서 도입됐습니다.
- 쇼핑몰(이커머스)이 1.3.0 보다 낮으면 이 플러그인 업데이트를 멈추고 원래 버전으로 되돌립니다. 이커머스를 먼저 업데이트한 뒤 다시 업데이트하세요. 종전에는 이 플러그인만 올라가 결제 화면이 오류로 열리지 않았습니다.
- 영수증 조회 API 응답을 다른 API 와 같은 공통 형식({ success, message, data })으로 바꿨습니다. 영수증 정보는 이제 `data` 안에 들어 있습니다 — 이 API 를 직접 부르던 사용자 정의 화면이나 스크립트는 `data` 에서 값을 읽도록 고쳐야 합니다.
- 결제창 복귀 기록(`g7:sirsoft-pay_kginicis:pendingClose` · `__sirsoftKginicisMobilePaymentReturnPending`)을 개인정보 동의 플러그인에 필수 저장 항목으로 직접 제공합니다. 그 플러그인은 동의 전
  방문자의 브라우저에서 목록 밖 항목을 지우는데, 지금까지는 그 플러그인이 이 항목 이름을 대신 들고 있었습니다.
  동의 플러그인의 클래스를 참조하지 않으므로 그 플러그인이 없어도 이 플러그인은 그대로 동작합니다.

### Fixed

#### 가상계좌

- 마이페이지·비회원 주문 상세의 「가상계좌 입금 안내」에 입금 금액과 「입금 기한 내에 입금하지 않으시면 주문이 자동 취소됩니다」 안내가 빠져 있던 것을 다른 결제사와 같이 보완했습니다. 입금 금액은 마일리지를 뺀 실제 입금액으로 보여 줍니다.
- **비회원 주문 상세에서도 가상계좌 입금 안내가 표시됩니다.** 회원 주문 상세에서만 입금 계좌·기한 안내를 붙여, 비회원이 가상계좌로 주문한 뒤 주문 상세를 열면 결제 정보 카드는 뜨는데 입금 안내만 빠져 있었습니다.
- 가상계좌 계좌가 KG이니시스 기본 기한(실측 30일)으로 열려 주문서 안내(쇼핑몰 「주문 자동취소」 기한)와 자동취소 시점이 어긋나던 문제를 고쳤습니다. 이제 PC·모바일 결제창 모두 주문의 입금 기한까지로 계좌를 엽니다.
- 가상계좌 입금 기한이 실제보다 9시간 늦게 저장되어, 주문완료·주문 상세에 기한이 다음 날 아침으로 보이고 기한 만료 처리도 그만큼 늦어지던 문제를 고쳤습니다. 결제사가 알려 주는 한국 시각의 기한을 서버 시각으로 바꾸지 않고 저장하고 있었습니다. 업데이트 전에 발급된 가상계좌의 기한은 바뀌지 않습니다.
- 입금 전에 취소한 주문의 가상계좌를 결제사에서 발급 취소합니다. 이전에는 계좌가 열린 채 남아 고객이 취소 뒤에도 입금할 수 있었습니다.

#### 환불·취소

- 입금이 끝난 가상계좌 주문을 KG이니시스 가상계좌 환불 경로로 환불하며, 환불받을 계좌번호는 결제사 규격대로 암호화해 보냅니다. 이전에는 환불 계좌가 결제사로 전달되지 않아 입금완료된 가상계좌 주문의 취소가 거절됐습니다.
- 환불 금액을 결제 통화 최소 단위로 반올림해 보냅니다. 이전에는 소수점 아래를 잘라, 다른 통화로 환산되는 주문에서 1원 적게 환불될 수 있었습니다(토스페이먼츠와 같은 규칙으로 맞췄습니다).
- 부분취소를 여러 번 하면 환불 기록에 회차별 결제사 거래번호가 남습니다. 이전에는 모든 회차가 원거래 번호로 기록됐습니다.

#### 에스크로

- 「에스크로 사용」 을 켜고 받은 결제(카드·가상계좌, PC·모바일)가 에스크로 결제로 기록되지 않아, 마이페이지 [구매결정] 버튼과 관리자 에스크로 배송 등록·구매결정 확인·에스크로 환불이 그 결제를 일반 결제로 다루던 문제를 고쳤습니다. 이제 승인·가상계좌 발급 때 에스크로 결제로 표시합니다(PC 결제창은 간편결제도 에스크로로 결제하므로 포함하고, 간편결제에서 에스크로를 빼는 모바일 결제창만 제외).
- 에스크로로 결제한 주문의 마이페이지 주문 상세에서 [구매결정]을 누르면 주문번호 없는 주소로 이동해 구매결정 창이 열리지 않던 문제를 수정했습니다.
- 주문 상세의 [구매결정] 창에서 구매결정을 진행할 수 없던 문제를 고쳤습니다. 이제 영수증 조회가 본인에게만 10분짜리 서명 주소를 내려 주고 [구매결정] 은 그 주소로 엽니다.
- 에스크로 구매결정 창을 닫으면 창이 닫히지 않고 오류 화면이 나오던 문제를 고쳤습니다.
- 관리자 주문 상세의 에스크로 배송 등록이 실패하면 이유와 상관없이 「등록에 실패했습니다」만 보이던 문제를 고쳤습니다. 이제 결제대행사가 거절한 사유나 빠진 입력 항목이 그대로 표시되며, 필수 항목을 모두 채우기 전에는 등록 버튼이 눌리지 않습니다.

#### 화면 조각·다국어

- 에스크로 구매결정 창(PC·모바일)의 제목·안내 문구가 화면 언어와 무관하게 한국어로 나오던 문제를 고쳤습니다. 이제 영어·일본어 화면에서는 그 언어로 나옵니다.
- 관리자 취소·현금영수증 발행 취소·구매거절 확인을 사유 없이 보낼 때 결제사로 넘기는 기본 문구가 화면 언어와 무관하게 한국어였던 것을 화면 언어 문구로 고쳤습니다.
- 영수증 버튼을 누른 뒤 조회 중 글자 「로딩 중...」이 영어·일본어 화면에서도 한국어로 나오던 것을 화면 언어로 나오게 고쳤습니다.
- 영어·일본어 화면의 주문 상세·주문 완료에서 **「영수증 조회」 버튼과 일본 결제 확인서·편의점 입금 안내가
  한국어로 나오던 문제**를 수정했습니다. 버튼 이름, 확인서 제목·안내·항목 이름, 입금 상태, 결제수단·간편결제 이름이 화면
  언어로 표시됩니다. 영수증 조회 API 의 확인서 항목에는 언어와 무관한 고정 이름(`key`)이 함께 실립니다.
- 영어·일본어 화면의 가상계좌 입금 안내에서 **입금 기한이 한국식 날짜·한국 시간으로 나오던 문제**를 수정했습니다. 쇼핑몰이 화면
  언어와 시간대에 맞춰 준 날짜를 그대로 표시합니다. 주문 완료 화면의 날짜 글자를 한국식으로 바꿔 쓰던 동작도 없앴습니다.
- 한국어·일본어 화면의 주문 상세·신청서 상세·주문 완료와 관리자 주문 상세에서 영수증 줄 이름·버튼, 결제수단 표시 이름이 브라우저 기본 언어(예: 영어 「Receipt / View Receipt」)로 붙던 문제를 고쳤습니다.
  - 이 정보를 그리던 화면 스크립트의 조회에 화면 언어가 실리지 않았습니다. 이제 화면 조각이 화면 언어로 조회합니다.
  - 결제를 마친 주문 상세·신청서 상세에 영수증 줄이 두 개 보이던 것도 하나로 줄였습니다.
- 관리자 주문 상세·마이페이지(비회원 포함) 주문 상세에서 결제수단 표시·영수증·가상계좌 안내에 쓰는 결제 조회가 응답을
  기다리지 않고 수십 번 반복 호출되던 문제를 고쳤습니다(호출마다 결제대행사 API 까지 갑니다).
  - 이제 한 화면에 들어올 때 주소마다 한 번만 조회하고, 실패해도 다시 부르지 않으며, 다른 주문으로 옮기면 이전 조회를 멈춥니다.
  - 관리자 주문 상세의 결제수단 표시는 같은 화면이 이미 받아 둔 거래 조회 결과를 그대로 써서, 주문 상세를 열 때마다
    결제대행사 거래 조회가 두 번 나가던 것도 한 번으로 줄였습니다.
- 비회원 주문 상세에서 주문을 불러오는 도중 영수증 조회가 먼저 나가, 다른 결제대행사 주문에도 영수증을 찾지 못했다는 404 오류가 나던 문제를 고쳤습니다. 이제 주문을 다 불러온 뒤 KG이니시스 결제일 때만 조회합니다.

#### 관리자·설정 화면

- 다른 결제 플러그인과 **함께 설치했을 때** 관리자 주문 목록의 「테스트 결제」 배지가 하나만 보이던 문제를 수정했습니다. 결제사마다 배지를 다는데 나중에 적용되는 쪽이 앞의 것을 덮어써, 우선순위가 가장 높은 한 곳의 배지만 남았습니다. 이제 설치한 결제사 수와 무관하게 각자의 배지가 함께 표시됩니다.
- 관리자 주문 목록의 **「테스트 결제」 배지가 다른 결제사로 결제한 주문에도 붙던** 문제를 수정했습니다. 이제 KG이니시스로 결제한 주문만 봅니다.
  - 이 플러그인의 배지가 자기 결제분뿐 아니라 나이스페이먼츠·NHN KCP 의 테스트 결제까지 함께 보고 있어, 그 결제사로 낸 테스트 주문에도 「KG이니시스」 이름의 배지가 달렸습니다. 반대로 이 플러그인만 설치한 사이트에서는 없는 정보를 찾는 셈이라 판정 자체가 불안정했습니다.
- 관리자 주문 목록에 테스트 결제 배지를 넣는 화면 확장이 목록의 열 전체를 복사해 덮어쓰지 않고 그 열만 덧붙이도록 바뀌었습니다. 종전에는 이 플러그인을 설치하면 쇼핑몰 모듈이 나중에 추가한 열(취소/반품/교환 열 등)이 주문 목록에서 사라졌습니다.
- 관리자 주문 상세의 **결제 조회** 영역과 플러그인 설정의 테스트 모드 표시에서 아이콘이 빈칸으로 보이던 것을
  고쳤습니다. Font Awesome 에 없는 이름을 쓰고 있었습니다.
- 결제 조회의 상태 배지·부분취소 금액과 플러그인 설정의 연결 점검 경고 문구에 **빨간 강조와 굵기·여백이 빠져** 보이던
  것을 고쳤습니다(스타일 이름 사이 공백 누락).
- 결제 조회의 에스크로 배송 등록 택배사 「기타」와 구매거절 「일시」가 언어를 바꿔도 한국어로 나오던 것을 번역 문구로
  바꿨습니다.
- 영어 관리자 화면의 플러그인 설정에서 「일반 결제 옵션」 구역 제목과 신용카드 포인트 결제 항목·안내가 번역 없이 키 이름으로
  나오던 문제를 수정했습니다.
- 플러그인 설정의 가상계좌 입금통보 주소 「복사」 버튼을 눌러도 아무 일도 일어나지 않던 문제를 수정했습니다. 없는 동작을 부르고 있었으며, 이제 주소가 클립보드에 복사되고 복사 완료 안내가 뜹니다. 어느 관리자 템플릿을 쓰든 같게 동작합니다.
- 설정 화면의 키 보기/숨기기 단추에 화면 읽기용 이름과 상태를 달았습니다.
- 환경설정 화면에서 항목 이름·설명과 입력칸이 나란히 놓이지 않고 위아래로 쌓이던 문제와, 섹션 제목이 오류 안내처럼 붉은 작은 글자로
  보이던 문제를 수정했습니다. 저장 오류 상자의 제목과 목록 글자도 각자의 오류 안내 색으로 맞췄습니다.
- 환경설정 화면의 안내 색이 뒤바뀌어 보이던 문제를 고쳤습니다. 라이브 모드 경고 본문이 초록으로, 일본 결제(CBT) 연결 점검의 「정상」이 노랑으로,
  파란 테스트 도우미 안내가 노랑으로, 주황 연결 진단 안내가 파랑으로 보였습니다. 이제 경고는 주황, 정상은 초록, 확인 필요는 빨강, 도우미 안내는 파랑으로 보입니다.
- 일본 결제(CBT) 연결 진단 결과에서 콜백 주소 점검 표의 항목 이름과 결과가 두 칸으로 놓이지 않고 한 줄씩 쌓이던 문제와, 나가는 IP 라벨 폭과 안내 들여쓰기가
  사라지던 문제를 고쳤습니다. 좁은 화면에서는 한 칸으로 놓입니다.
- 관리자 주문 상세의 일본 CBT 편의점 결제 패널에서 설명과 통보 이력이 파란 안내색이 아니라 빨간색으로 보이던 문제를 수정했습니다. 다크 모드의 입력칸 포커스 테두리·회색 안내 패널 배경·파란 버튼 호버 색도 관리자 템플릿에 따라 빠지지 않습니다.
- 환경설정 「결제 실패 시 이동 주소」 안내가 실제 기본값(상점 주소 설정을 따르는 `{shopBase}`)과 다르게 「상대 경로 또는 전체 URL」 로만 안내되던 문구를 바로잡았습니다.
- 플러그인 설정을 바꿀 권한이 없는 관리자에게 설정 화면이 입력할 수 있는 상태로 열려 저장할 때에야 거절되던 문제를 고쳤습니다. 이제 「읽기 전용」 안내와 함께 입력·저장 버튼이 잠깁니다.
- 설정 화면의 [CBT 테스트 상품 만들기]가 상품 등록 권한 없이도 눌려 거절되던 문제를 고쳤습니다.
- 관리자 주문 상세 결제 영역의 입금 시뮬레이트·만료·에스크로 배송 등록·구매거절 확정 버튼이 주문 수정 권한 없이도 열려 거절되던 문제를 고쳤습니다.

#### 결제 보안

- **취소된 주문이 뒤늦은 입금·승인으로 되살아나지 않습니다.** 이제 취소된 주문의 통보는 주문을 건드리지 않으며, 카드 승인이 이미 이루어진 경우에는 그 승인까지 자동으로 취소합니다.
  - 편의점 입금통보와 모바일 카드 결제 콜백에 취소 확인 절차가 없어, 만료 자동취소된 주문에 뒤늦게 입금·승인이 들어오면 그 주문이 결제완료로 되살아나면서 재고와 마일리지가 한 번 더 차감되었습니다.
  - 취소된 주문에 온 입금 통보는 기록하고 운영자에게 알립니다.
- 설정 화면의 결제 후 이동 주소(성공·실패)에 「not a url」 같은 아무 글자나 저장돼, 결제를 마친 구매자가 깨진 주소로 보내지던 문제를 고쳤습니다. 이제 `{shopBase}`·`/`·`http(s)://` 로 시작하지 않거나 공백이 있는 주소, 다른 사이트로 보내는 `//주소`·`javascript:` 는 칸별 오류로 저장되지 않습니다.

### Security

- 결제창을 닫았다는 보고를 주문한 본인만 보낼 수 있게 했습니다. 이전에는 주문번호·결제 금액·주문자 이메일과 전화번호만 알면 로그인 없이도 결제 진행 중인 남의 주문을 취소시킬 수 있었습니다. (KISA 측에서 제보해주셨습니다 — KVE-2026-2434)
  - 이제 회원 주문은 주문한 회원의 로그인으로, 비회원 주문은 주문할 때 브라우저가 받은 조회 확인값으로만 보고를 받으며, 주문자 연락처는 더 이상 보내지도 확인하지도 않습니다.
  - 확인에 실패한 보고는 주문을 전혀 건드리지 않고, 결제를 끝내지 않은 주문은 종전처럼 결제 대기 만료 정리가 처리합니다.
- 결제 인증 결과를 결제사가 승인해 준 주문번호·금액과 대조한 뒤에만 주문에 반영합니다. 이전에는 브라우저가 보낸 주문번호와 금액을 그대로 믿어, 싼 주문의 결제 승인에 비싼 주문번호를 붙여 보내면 비싼 주문이 싼 금액으로 결제 완료되거나, 이미 결제된 주문의 결제 정보가 다른 가상계좌로 덮어써질 수 있었습니다. 이제 어긋나는 승인은 즉시 취소하고 주문을 건드리지 않으며, 가상계좌 발급은 결제 대기 중인 주문에만 기록합니다. (KISA 측에서 제보해주셨습니다 — KVE-2026-2434)
- 일반 주문 결제도 승인 금액을 결제창 복귀 값이 아니라 KG 이니시스 승인 응답으로 확인하고, 다르거나 없으면 결제를 취소합니다.
- 엔화 주문의 편의점 결제번호 발급을 승인 응답만으로 판별해, 입금 전 주문이 결제완료로 처리되지 않게 했습니다.
- 카드, 계좌이체, 간편결제와 PC 및 모바일 가상계좌 발급에서 승인 결과에 금액이 없거나 주문 금액과 다르면 승인을 취소하고 결제를 반영하지 않습니다. 이전에는 승인 결과에 금액이 없으면 가상계좌 발급의 금액 대조를 건너뛰었습니다. 또 이미 결제완료됐거나 취소된 주문에 새 결제 승인이 도착하면 주문을 바꾸지 않고 그 승인을 취소해, 결제된 금액이 PG 에 남지 않도록 했습니다.
- 결제 결과 화면으로 보내는 이동 주소와 KG이니시스에 넘기는 복귀·통보 주소를 요청의 Host 헤더가 아니라 사이트 주소로 만듭니다. PC·모바일·CBT 결제 콜백의 입력값이 잘못된 경우 직전 화면(Referer)이 아니라 사이트의 결제 실패 화면으로 이동합니다.
  - 결제창 폼은 KG이니시스의 https 주소로만 제출되고, 영수증 창은 열린 창이 결제 화면을 조작하지 못하게 엽니다.
  - PC·모바일 가상계좌·CBT 편의점 입금통보에 형식이 틀린 요청이 오면 직전 화면으로 이동시키지 않고 422 오류로 응답합니다.
- 에스크로 구매결정·거절 결과는 확인창을 연 본인의 요청에서 받은 것만 기록합니다. 확인창을 열 때마다 일회용 증표를 발급해 복귀 주소에 넣고, 로그인하지 않은 상태에서는 확인창을 열 수 없다는 안내를 보여 줍니다. 증표가 없는 종전 복귀 주소로 들어온 결과는 기록하지 않습니다.
- 내 주문 상세의 가상계좌 은행코드를 화면에서만 숨기고 응답에는 누구에게나 싣던 문제를 고쳤습니다. 이제 주문 조회 권한이 있는 관리자에게만 실립니다.

- 결제 서명 요청의 timestamp 신선도(±5분) 검증 추가 — PC/모바일/일본결제(CBT) 모든 서명 발급 경로에서 과거에 캡처된 timestamp 로 동일 서명을 재사용하는 replay 공격을 차단
- 결제 콜백 중복 처리 방어 추가 — 동일 거래번호로 콜백이 두 번 도착해도 결제완료/마일리지 적립 등이 중복 실행되지 않도록 멱등 응답 처리 (PC 카드/가상계좌/모바일 카드/모바일 가상계좌/일본결제 5개 경로)
- 모바일 카드 결제 처리 중 오류 발생 시 결제 자동 취소 추가 — 승인 후 후속 처리(금액 검증 등) 실패 시 PG 측 결제도 자동 취소하여 사용자 환불 누락 방지
- 일본결제(CBT) 처리 중 오류 발생 시 운영자 수동 정산 신호 강화 — 승인 후 후속 처리 실패가 운영 로그에 즉시 드러나도록 표시

### Added

- 가상계좌 결제 시 PG 응답의 은행코드를 저장하도록 개선 — 운영자가 입금 확인/대사 작업 시 은행 식별이 가능하도록 함
- 마이페이지 가상계좌 입금 안내에 관리자에게만 은행코드 행 노출 — 동일 페이지를 일반 사용자에게는 종전과 동일하게 표시
