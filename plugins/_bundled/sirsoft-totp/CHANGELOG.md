# Changelog

이 플러그인의 모든 주요 변경사항을 기록합니다.
형식은 [Keep a Changelog](https://keepachangelog.com/ko/1.1.0/)를 따르며,
[Semantic Versioning](https://semver.org/lang/ko/)을 준수합니다.

## [1.1.1] - 2026-11-21

### Added

- 사용자 화면 마이페이지 > 내 정보의 보안 카드에 2단계 인증(인증 앱) 칸이 보입니다. 회원이 직접 등록·해제하고 백업 코드를 다시 받을 수 있습니다. 비밀번호 없이 가입한 회원(소셜 로그인 전용)에게는 비밀번호를 먼저 설정하라는 안내와 설정 화면 링크가 보입니다.
- **사용자 템플릿 안내**: 이 칸은 내 정보 화면의 보안 카드(`data-ref="profile_security_card"`) 뒤에 붙습니다. 복사했거나 다른 사용자 템플릿이라 이 요소가 없으면 칸이 보이지 않으니(오류는 없음), 내 정보 화면에 같은 `data-ref` 를 단 요소를 두세요.

### Changed

- 관리자 화면의 주 버튼(저장·등록 등)을 관리자 템플릿과 같은 검정(다크 모드 흰색) 모양으로 통일했습니다. 파랑으로 보이던 버튼이 검정으로 바뀝니다. 버튼 글자의 줄 높이가 글자 크기에 맞춰져(21px → 20px) 버튼 높이가 1px 낮아집니다.
- 관리자 화면의 테두리 버튼 모양을 하나로 맞췄습니다. 바탕이 비어 있던 버튼은 흰색(다크 모드 짙은 회색)으로 채워지고, 글자가 가늘던 버튼은 조금 굵어집니다. 버튼 글자의 줄 높이가 글자 크기에 맞춰져(21px → 20px) 버튼 높이가 1px 낮아집니다.
- 화면마다 따로 적던 흐린 글자, 버튼, 카드 모양을 이 확장 CSS 의 공통 클래스로 모았습니다. 위에 적은 것 외에는 화면 모양이 같습니다.

### Fixed

- 2단계 인증 알림의 「보안 설정」 링크가 일반 회원에게도 관리자 화면 주소로 가던 문제를 고쳤습니다. 이제 회원은 마이페이지 내 정보로, 관리자는 플러그인 설정 화면으로 갑니다.

## [1.1.0] - 2026-11-20

### Added

- 운영자가 회원 항목에 「기존 회원에게도 입력 요구」를 켜 추가 정보 입력이 필요한 회원도 인증 앱 등록 시작, 확인, 해제와 백업 코드 재발급은 그대로 할 수 있습니다. 코어가 그런 회원의 쓰기 요청을 막지만, 로그인 2단계 인증 수단을 다루는 이 요청들은 코어 필터 `core.required_fields.filter_exempt_routes` 로 열어 둡니다.

### Changed

- 화면 스타일을 플러그인 자체 CSS 로 제공합니다 — 템플릿의 CSS 라이브러리와 무관하게 표시됩니다. 플러그인 설정 화면과 회원 상세의 2단계 인증 카드의 클래스가 모두 이 플러그인 앞글자(`totp:`·`totp-`)로 바뀌었고, 다크 모드는 코어의 중립 표식을 따릅니다. 화면 모양은 이전과 같습니다.
- 코어 최소 요구 버전을 7.2.0 으로 상향했습니다(`g7_version >=7.2.0`). 다크 모드 중립 표식과 확장 CSS 칸 선언을 코어 7.2.0 이 제공합니다.
- 관리자의 인증 앱 강제 해제 활동 기록에 남는 회원 이름이 코어 환경설정 > 회원의 표시 이름 설정에서 관리자 화면 영역의 이름을 따릅니다(관리자 화면을 닉네임으로 둔 사이트는 닉네임). 이미 남은 기록은 바꾸지 않고, 표시 이름 설정을 바꾸지 않은 사이트는 종전과 같은 이름이 남습니다.
- 화면 폭 분기를 Tailwind 반응형 접두와 폭 미디어를 품은 관리자 화면 의미 클래스(`totp-page-title`·`totp-page-header` 등) 대신 엔진 responsive 로 바꿨습니다(화면 변화 없음). 옛 클래스 정의는 사이트에서 직접 고친 레이아웃의 호환을 위해 폐지 예정으로 남기며 다음 출시 이후 제거합니다.
- 플러그인을 제거할 때 「데이터도 함께 삭제」를 고르지 않으면 관리자 메뉴를 지우지 않습니다. 다시 설치하면 운영자가 고친 메뉴 이름·순서가 그대로 남습니다(코어 7.2.0).

### Fixed

- 알림 설정 조회 권한(환경설정 읽기)이 없는 운영자가 설정 화면에 들어올 때마다 「해당 권한이 없습니다」 알림이 뜨던 문제를 고쳤습니다. 이제 알림 없이 보안 알림 카드에 「권한 없음」 안내만 보입니다.

## [1.0.3] - 2026-11-15

### Security

- 같은 인증 앱 코드나 같은 백업 코드를 동시에 여러 번 보내면 모두 로그인되던 문제를 막았습니다. 한 코드는 동시에 보내도 한 번만 통과하고, 백업 코드도 한 번 쓰면 바로 사라집니다. (KISA 측에서 제보해주셨습니다 — KVE-2026-3193)
- 로그인된 탭만 있으면 비밀번호를 몰라도 인증 앱을 새로 등록하고 백업 코드를 받을 수 있던 문제를 막았습니다. 인증 앱 설정 화면의 [등록 시작] 은 현재 비밀번호를 다시 확인하고, 비밀번호를 여러 번 틀리면 잠시 후 다시 시도하라고 안내합니다(코어 환경설정 > 보안의 로그인 시도 횟수·잠금 시간을 따름). (KISA 측에서 제보해주셨습니다 — KVE-2026-3194)
- 인증 앱이 등록·해제되거나 백업 코드가 재발급되면 계정 이메일로 알림을 보냅니다(관리자의 강제 해제와 서버 명령 해제도 포함). 본인이 아니면 바로 비밀번호를 바꾸라고 안내하고 요청 IP 를 함께 적습니다. 비밀번호를 재설정해도 인증 앱 등록은 그대로 남습니다.
- 인증 앱 2단계 로그인에서 「다시 보내기」로 시도 횟수를 매번 처음으로 되돌려 코드를 끝없이 맞혀 볼 수 있던 문제를 막았습니다. 인증 앱은 코드를 보내지 않으므로 다시 보내기를 받지 않고, 2단계 코드 오답은 코어의 로그인 실패 횟수에 더해져 계정 잠금 기준을 따릅니다. 동시에 여러 코드를 보내 5회 제한을 넘기던 문제도 함께 막았습니다. (KISA 측에서 제보해주셨습니다 — KVE-2026-3195)
- 로그인된 탭으로 인증 앱 해제·백업 코드 재발급의 확인 코드를 제한 없이 맞혀 볼 수 있던 문제를 막았습니다. 코드를 여러 번 틀리면 잠시 후 다시 시도하라고 안내합니다. 코드를 대조하기 전에 시도를 먼저 세어 동시에 보내도 횟수 제한을 넘기지 못합니다.
- 일반 운영자가 회원 상세 화면에서 슈퍼 관리자의 인증 앱을 강제 해제할 수 있던 문제를 막았습니다.
- 두 화면에서 동시에 등록을 확정하면 화면에 보인 백업 코드와 저장된 백업 코드가 달라질 수 있던 문제를 고쳤습니다. 늦게 확정한 화면은 「다른 화면에서 등록이 먼저 완료되었습니다」 안내를 받습니다.

### Added

- 인증 앱 설정 화면에 「보안 알림」 카드를 추가했습니다. 운영자가 인증 앱 등록·해제·백업 코드 재발급 알림을 각각 끄고 켜고, 메일 문구를 편집·미리 보고, 기본값으로 되돌릴 수 있습니다.
- 인증 앱 설정 화면의 현재 비밀번호 칸, 시도 제한·동시 확정 안내, 보안 알림 카드·알림 문구의 다국어(ko·en) 문구를 추가했습니다. 일본어는 일본어 언어팩 1.0.3 에 있습니다.
- 확장 개발자용: 인증 앱 등록 확정·본인 해제·백업 코드 재발급 직후 발행되는 훅 `sirsoft-totp.credential.enrolled`·`sirsoft-totp.credential.disabled`·`sirsoft-totp.backup_codes.regenerated` 를 추가했습니다(인자: 회원, `ip_address`·`user_agent`·`occurred_at` 문맥). 문서: `docs/extension-points.md`
- API: `POST /api/plugins/sirsoft-totp/enrollment` 는 현재 비밀번호(`current_password`, 필수)를 받습니다 — 틀리면 422, 시도 제한을 넘으면 429(`Retry-After`). 등록 확정은 다른 화면이 먼저 확정했으면 409, 해제·백업 코드 재발급은 시도 제한을 넘으면 429 입니다.
- 코어 7.1.6 이상이 필요합니다(비밀번호 재확인·본인인증 상태 조건부 갱신 기능을 씁니다).

### Changed

- Composer 잠금 파일을 확장 정보와 다시 맞췄습니다. 설치·업데이트 과정에서 잠금 파일이 오래되었다는 경고가 나오지 않습니다.

### Fixed

- 엄격한 스타일 보안 정책(CSP `style-src-attr 'none'`)을 건 사이트에서 인증 앱 등록 화면의 QR 코드에 크기(최대 220px)와 가운데 배치가 적용되지 않던 문제를 고쳤습니다. QR 그림에 직접 써 넣던 스타일을 플러그인 CSS 파일로 옮겼습니다.
- 인증 앱 등록을 시작만 하고 마치지 않은 기록이 남은 채 사이트 암호화 키가 바뀌면, [등록 시작] 을 눌러도 서버 오류가 나 등록할 수 없던 문제를 고쳤습니다. 읽을 수 없는 미완료 기록은 버리고 새로 시작합니다.

- 일본어·영어 사이트에서 2단계 인증 초기화 명령의 콘솔 출력이 한국어로 나오던 문제를 고쳤습니다.

## [1.0.0] - 2026-10-10

### Added

- 인증 앱(TOTP) 2단계 인증 플러그인 최초 릴리즈. 그누보드7 코어 7.1.0 이상이 필요하며, 한국어와 영어를 기본 제공하고 일본어는 번들 언어팩으로 제공합니다.

#### 로그인과 등록

- **인증 앱으로 로그인 2단계 인증을 받을 수 있습니다.** Google Authenticator·Authy·1Password 등
  표준 인증 앱이 만드는 6자리 코드로 로그인을 마칩니다. 종전에는 2단계 인증을 켜면 인증번호가
  이메일로만 왔고, 메일이 늦거나 막히면 로그인도 함께 막혔습니다.
- **등록 화면에서 QR 코드와 수동 입력 키를 함께 제공합니다.** 카메라를 쓸 수 없는 환경에서도
  키를 직접 옮겨 적어 등록할 수 있습니다. 등록 화면은 「플러그인 관리 → 설정」에서 엽니다.
- **백업 코드 10개를 발급합니다.** 휴대폰을 잃어버려도 백업 코드로 로그인할 수 있습니다.
  - 한 번 쓴 코드는 사라지며, 언제든 새로 발급해 이전 코드를 모두 무효로 만들 수 있습니다.
  - 발급 화면에서 「전체 복사」로 열 개를 한 번에 가져갈 수 있습니다 — 이 코드는 그 자리에서만 보이므로, 옮겨 적다 놓치면 휴대폰을 잃었을 때 로그인할 길이 사라집니다.
- **인증 앱을 등록하지 않은 회원은 종전처럼 이메일로 인증번호를 받습니다.** 등록하지 않았다는
  이유로 로그인이 막히지 않습니다. 이 동작은 플러그인 설정에서 끌 수 있으며, 끄면 등록을
  마칠 때까지 로그인이 차단됩니다.

#### 관리자 해제

- **관리자가 회원의 인증 앱 등록을 해제할 수 있습니다.** 휴대폰과 백업 코드를 모두 잃은 회원을 구제하는 경로이며, 전용 권한(인증 앱 운영자)을 가진 관리자만 할 수 있습니다.
  - 회원 상세 화면의 「인증 앱」 카드에서 해제하며, 관리자 화면에 들어갈 수 없는 상황을 위해 서버에서 실행하는 `totp:reset` 명령도 제공합니다.
- 회원 상세 「인증 앱」 카드가 그 회원의 등록 여부(등록됨·미등록)를 보여 주고, [인증 앱 등록 해제] 단추는 등록된
  회원에게만 보입니다(미등록 회원에게는 「해제할 것이 없습니다」 안내). 등록 여부는 해제 권한이 있는 관리자에게만
  보이며, 강제 해제는 활동 로그에 「관리자」 유형으로 남습니다.
- **강제 해제는 활동 로그에 남습니다.** 누가 누구의 인증 앱 등록을 언제 풀었는지, 그때의 접속 IP 와 함께 기록됩니다.
  - 코드 확인 없이 남의 2단계 인증을 푸는 경로이므로 추적할 수 없으면 이 경로 자체가 권한 상승 수단이 됩니다.
  - 서버 명령 `totp:reset` 으로 풀어도 같은 기록이 남습니다.

#### 설정과 레이아웃 편집기

- **인증 앱 목록에 표시될 사이트 이름을 설정할 수 있습니다.** 비워 두면 사이트 이름을 씁니다. 「플러그인 관리 → 설정」의 「사이트 설정」 카드에서 이 이름과 미등록 회원의 이메일 인증번호 허용 여부를 바꾸며, 이메일 허용을 끄면 저장 전에 그 결과(미등록 회원은 로그인할 수 없음)를 경고합니다. 이 카드는 플러그인 설정 수정 권한이 있는 관리자만 입력할 수 있고, 권한이 없으면 입력이 잠긴 채로 보입니다.
- **레이아웃 편집기에서 인증 앱 등록 화면의 단계별 카드를 볼 수 있습니다.** 미등록 안내·발급(QR·확인 코드)·백업 코드·등록 완료·코드 오류가 서로 배타 조건이라 편집기에서는 한 가지만 보였는데, 이제 상태로 골라 각각 편집할 수 있습니다. 표본의 시크릿·백업 코드는 실제 값이 아닌 고정 placeholder 입니다.

#### 보안과 데이터 보관

- 같은 코드를 두 번 쓸 수 없습니다. 어깨너머로 본 코드가 30초 동안 재사용되는 경로를 막습니다.
- 시크릿은 암호화해 저장하고 백업 코드는 해시로만 보관합니다. 데이터베이스만으로는 코드를
  만들 수 없습니다. 발급된 평문은 화면에 한 번만 보여 주고 다시 조회되지 않습니다.
- 회원이 탈퇴하거나 삭제되면 인증 앱 등록 정보를 함께 파기합니다.
