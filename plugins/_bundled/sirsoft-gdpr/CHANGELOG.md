# Changelog

이 프로젝트의 모든 주요 변경사항을 기록합니다.
형식은 [Keep a Changelog](https://keepachangelog.com/ko/1.1.0/)를 따르며,
[Semantic Versioning](https://semver.org/lang/ko/)을 준수합니다.

## [1.1.0] - 2026-08-20

### Added

- 개인정보 이용내역을 활성 회원에게 연 1회 안내하는 자동 통지를 추가했습니다. 실행당 상한·채널·다국어 서문을 설정하고 본인에게 시험 발송할 수 있습니다. 접수와 채널별 발송 결과를 이력 화면에서 구분합니다. 언어팩을 끈 뒤에도 그 언어로 써 둔 서문이 설정 저장을 막지 않으며, 서문은 지워지지 않고 남아 언어팩을 다시 켜면 그대로 쓰입니다.
- 연간 통지 카드에 **이번 주기 대상 인원**이 보입니다. 자동 발송이 꺼져 있어도 켜면 통지할 인원을 미리 보여 주고, 「대상 보기」를 누르면 그 회원 명단(이름·이메일·가입일)이 창으로 열립니다 — 20명씩 보이고 아래로 스크롤하면 이어서 불러옵니다. 회원 조회 권한이 있는 관리자에게만 버튼이 보입니다.
- 연간 통지 카드의 「개인정보 이용내역 연간 통지」 줄(이번 주기 대상 인원 · 「대상 보기」 · 마지막 발송 결과)에 있는 **「지금 실행」**으로 정기 발송일을 기다리지 않고 지금 통지를 접수할 수 있습니다. 자동 발송을 꺼 둔 채로도 저장된 채널·문구로 접수하며, 실행당 상한만큼만 접수하고 남은 인원은 다시 누르면 이어서 접수합니다. 이번 주기에 이미 받은 회원에게는 다시 보내지 않습니다. 끝나면 「마지막 직권 발송: 일시 · 실행자 · N명 접수 · 남은 대상 N명」이 카드에 남습니다. 개인정보 설정 수정 권한이 있어야 버튼이 보입니다.
- 확장 아이콘을 동봉했습니다. 관리자 확장 관리 화면과 설치 마법사에 표시됩니다.
- 개인정보 연간 통지의 알림 템플릿을 플러그인 설정 화면 「알림 템플릿」 카드에서 직접 편집합니다. 채널별 제목·본문·수신자를 고치고 미리보기로 치환 결과를 확인하며 기본값으로 되돌릴 수 있습니다.
- 관리자 확장 관리 화면의 보기 방식 저장 항목(g7_view_mode_*)이 필수 저장 허용 목록
  기본값에 들어갑니다. 이미 설치된 사이트는 업그레이드 시 목록에 추가되며, 운영자가
  직접 편집한 목록은 그대로 둡니다.
- 방문자 통계의 수집 거부 쿠키(g7_analytics_optout)가 필수 저장 허용 목록 기본값에
  들어갑니다. 목록에 없으면 쿠키 동의 전 상태에서 「내 방문은 세지 않기」를 눌러도
  쿠키가 제거되어 아무 일도 일어나지 않았습니다 — 수집을 거부하는 기록 자체는 추적이
  아니라 추적을 막는 의사 표시입니다. 이미 설치된 사이트는 업그레이드 시 목록에
  추가되며, 운영자가 직접 편집한 목록은 그대로 둡니다.
- 동의 기록·환경설정 화면과 쿠키 배너·마이페이지 개인정보 탭을 `.g7.html` 마크업 형식으로도 제공합니다. HTML 에 가까운 문법이라 화면 구조를 눈으로 따라가기 쉽고,
  기존 JSON 레이아웃도 그대로 함께 들어 있어 두 표기를 나란히 비교할 수 있습니다.
- **레이아웃 편집기에서 GDPR 설정 화면을 상태별로 볼 수 있습니다.** 정책 버전 이력 펼침·쿠키 분류 상세 펼침과 알림 템플릿 편집·미리보기, 정책 스냅샷 창의 내용을 상태로 열 수 있고, 동의 로그의 검색 필터가 걸린 화면도 고를 수 있습니다.

- 코어 방문자 통계가 동의 연동 모드에서 게스트 동의를 확인할 수 있게, 게스트 동의 식별자(`gdpr_session`)를
  코어에 알려 줍니다(`core.analytics.consent_session_id` 필터). 지금까지는 코어가 다른 값으로 물어 배너에서
  「모두 동의」를 눌러도 게스트 방문이 한 건도 세어지지 않았습니다. 회원은 회원 번호로 찾으므로 그대로입니다.
- 게스트 동의 식별 쿠키(`gdpr_session`)를 쿠키 암호화 대상에서 뺍니다. 이 쿠키는 서명으로 위변조를
  검증하는데, 화면 요청 쪽의 쿠키 암호화가 그 값을 읽지 못해 동의한 게스트도 화면을 새로 열거나
  새로고침할 때마다 「미동의」로 판정됐습니다 — 방문자 통계가 동의 연동 모드에서 동의자의 첫 화면을
  빠뜨리던 원인 중 하나입니다.

### Changed

- 코어 방문자 통계의 동의 질문에 코어 훅으로 답합니다 — 식별자 추적 허용(`core.analytics.tracking_permission`,
  분석·기능 쿠키 둘 다 동의해야 허용), 동의 모드의 분석 동의(`core.analytics.visitor_has_consent`), 동의 철회
  (`core.analytics.consent_revoked` 액션으로 중계). 동의를 저장하면 코어 이벤트 `g7:analytics-permission-changed` 를
  발행하고, 스크립트를 막을 때 코어 속성 `data-g7-script-deferred` 를 함께 붙입니다. 지금까지는 코어가 이 플러그인의
  이름·클래스·경로를 직접 알고 있었습니다.

- 확장이 쓰는 필수 저장 항목(결제창 복귀 기록, 본인인증 입력 보관, 비회원 장바구니·주문 조회 토큰)을
  이 플러그인이 목록으로 들고 있지 않고, **각 확장이 스스로 제공**합니다. 확장은 이 플러그인이 정한 필터 훅
  (`sirsoft-gdpr.necessary_storage.filter_provided_keys`)에 자기 항목을 덧붙이고, 판정할 때마다 활성 확장의
  항목을 모읍니다. 확장을 켜면 다음 요청부터 그 항목이 허용되고 끄면 빠집니다. 환경설정 화면 「필수 저장 항목」
  카드에 「확장 제공 항목 (자동)」으로 읽기 전용 표시되며 여기서 편집하지 않습니다. 확장이 돌려준 항목도 운영자
  입력과 같은 형식 규칙을 통과한 것만 받습니다(`*` 단독 등은 버립니다).
- 1.0.4 가 필수 저장 항목 목록에 적어 둔 확장 항목을 업그레이드 시 목록에서 걷어냅니다. 그 항목은 이제 해당
  확장이 제공하므로, 목록에 남겨 두면 확장을 지워도 허용된 채로 남습니다. 1.0.4 가 넣은 항목만 지우며 운영자가
  추가한 항목은 그대로 둡니다. 결제·본인인증·쇼핑 확장도 함께 갱신하세요 — 그 확장이 옛 버전이면 걷어낸 항목을
  제공하지 않습니다.

- 동의를 저장한 직후 화면 전체에 동의 변경을 알립니다(`gdpr:consent-changed`). 이 알림만
  바라보는 기능(코어 방문자 통계 트래커 등)이 지금까지는 알림을 받지 못해, 배너에서 동의해도
  새로고침 전까지 옛 동의 판정을 그대로 썼습니다.

- 코어 최소 요구 버전을 7.1.0 으로 상향 — 화면 마크업 형식(`.g7.html`)을 읽는 기능이 이 코어부터 제공됩니다.

- 설치 시 `.g7.html` 이 있으면 그것을 우선 사용합니다. 짝이 되는 JSON 과 결과가 완전히 같으므로 화면 동작은
  달라지지 않으며, JSON 만 쓰던 환경에서도 종전과 동일하게 설치됩니다.

- 개인정보처리방침 링크를 **운영자가 주소로 직접 입력**합니다(환경설정 「개인정보처리방침 주소」). 지금까지는
  페이지 슬러그를 적으면 이 플러그인이 페이지 모듈의 주소 규칙(`/page/슬러그`)으로 링크를 만들어, 페이지 모듈이
  없거나 처리방침을 다른 곳에 게시한 사이트에서는 링크가 없는 페이지로 이어졌습니다. 이제 `/` 로 시작하는 사이트
  경로(예: `/page/privacy`) 또는 `https://` 로 시작하는 주소를 적고, 그 주소가 쿠키 배너의 정책 링크와 개인정보
  연간 통지의 처리방침 링크에 그대로 쓰입니다. 비워 두면 배너의 정책 링크를 숨기고, 연간 통지 메일에서도 처리방침
  링크 줄을 빼고 보냅니다(누를 수 없는 링크가 가지 않도록). 새로 설치하면 비어 있습니다.
  `javascript:` 같은 다른 형식, `http://`, `//` 로 시작하는 주소, 백슬래시·공백이 섞인 주소는 저장할 때 거부되고,
  설정 파일을 직접 고쳐 넣은 값도 링크로 쓰이지 않습니다. 공개 설정 응답의 `privacy_policy_slug` 는
  `privacy_policy_url` 로 바뀌었습니다.
- 업그레이드하면 기존 슬러그가 같은 링크 경로(`/page/슬러그`)로 옮겨져, 배너와 통지의 링크가 업그레이드 전과
  똑같이 동작합니다. 슬러그를 비워 두었던 사이트는 계속 링크가 숨겨집니다. 이전 버전에서 발행한 정책 버전의
  본문 보기 창은 당시 슬러그를 같은 경로로 풀어 보여 주고 이전 형식으로 기록된 버전임을 함께 표시합니다.
  슬러그가 주소로 옮겨졌다는 이유만으로 정책 변경으로 판정되어 재동의가 요구되지는 않습니다.

### Fixed

- 레이아웃 편집기의 모달 목록에서 **연간 통지 대상 회원·직권 발송 창이 제목 식 원문으로 보이던 것**을 고쳤습니다.
  두 창에 편집기 전용 이름을 붙였습니다.
- 설정 화면의 카드마다 상하 여백이 달라 간격이 들쭉날쭉하던 것을 통일했습니다.
- 자동 통지를 끈 상태에서도 발송 채널·실행당 상한을 입력하라고 막아 설정을 저장할 수 없던 문제를 수정했습니다. 통지를 끄면 그 아래 입력이 함께 비활성화되고, 저장해 둔 채널·상한 값은 그대로 유지됩니다.
- 설정 저장 오류 문구에 화면 라벨 대신 내부 필드 이름이 그대로 나오던 문제를 수정했습니다(예: "annual notice.batch size" → "1회 실행당 발송 상한"). 쿠키 카테고리·차단 도메인·필수 저장 항목 문구에도 같은 교정을 적용했습니다.

- 정책 버전 스냅샷 창의 발행일시·발행자·변경 종류·메모가 라벨 폭마다 값이 들쭉날쭉 시작하던 것을, 라벨 칸을 맞춰
  값이 한 줄로 시작하도록 고쳤습니다.
- 운영자가 개인정보 메뉴에서 개인정보 담당 역할을 뺐는데, 플러그인을 다시 활성화하거나 업데이트하면 그 역할이 다시 붙던 문제를 수정했습니다.
- 플러그인을 비활성화했다가 다시 활성화하면 운영자가 관리자 메뉴에 지정해 둔 역할이 사라지던 문제를 수정했습니다. 비활성화할 때 메뉴를 지우지 않고(비활성 동안은 사이드바에 보이지 않습니다), 메뉴는 플러그인을 제거할 때 지웁니다.
- 연간 개인정보 이용내역 통지에 넣는 개인정보 처리방침 링크가 통지를 만든 요청의 주소가 아니라 사이트 주소를 쓰도록 고쳤습니다. 백그라운드 작업에서 만들면 `http://localhost` 주소가 전 회원 통지에 들어갈 수 있었습니다.

## [1.0.4] - 2026-09-06

### Added

- 개발자와 AI 에이전트를 위한 문서를 추가했습니다. 확장 폴더의 `AGENTS.md`(설계 의도·확장점·수정 시 확인할 것)와 `README.md`(도입·운영 안내), `docs/`(상세 문서)로 구성됩니다.
- 확장 문서에 「레이아웃 편집기 스펙」 항목을 추가했습니다. 이 확장이 레이아웃 편집기에 무엇을 선언했는지와, 화면 요소나 데이터를 추가할 때 편집기 쪽에서 함께 해야 할 일을 담습니다.
- 문서의 제품 표기를 「그누보드7」로 통일했습니다.
- GDPR 설정 화면에 「필수 저장 항목」 카드를 추가했습니다. 기능 쿠키에 동의하지 않은 방문자에게도 저장이 허용되는 항목을 브라우저 저장소·세션 저장소·쿠키로 나누어 직접 편집할 수 있습니다. 새로 설치한 확장이 저장하는 항목이 동의 전에 지워진다면, 이제 이 화면에서 추가하면 됩니다.
- 항목 이름 끝에 `*` 를 붙이면 앞부분이 같은 항목을 모두 포함합니다. 예를 들어 `g7_filters_*` 는 `g7_filters_orders_1` 을 함께 포함합니다.
- 사이트 동작에 반드시 필요한 항목(로그인 토큰, CSRF 토큰, 세션 쿠키, 쿠키 동의 기록)은 「잠금 항목」으로 카드 위쪽에 표시되며 삭제할 수 없습니다.
- 잠금 항목의 정의는 플러그인 진입 파일이 소유합니다. 설정 기본값을 만드는 시점에 다른 클래스를 불러오지 않으므로, 새로 설치하는 사이트에서도 설치가 중단되지 않습니다.
- 이미 설치된 사이트는 업데이트 시 현재 기본 목록이 설정으로 옮겨집니다. 이미 편집한 값이 있으면 그대로 둡니다.

### Fixed

- `sudo` 로 코어를 업데이트할 때 업그레이드 단계가 저장하는 설정 파일이 root 소유로 남을 수 있던 문제를 수정했습니다. 저장 뒤 폴더 소유자와 같게 맞춥니다.
- 회원탈퇴로 자동 철회된 동의 이력이 관리자 「GDPR 동의 이력」 화면의 출처 필터로 걸러지지 않던 문제를 수정했습니다.
- 쿠키 동의 저장 요청이 서버만 기록해야 하는 출처(회원가입 시 동의)를 직접 지정할 수 있던 문제를 수정했습니다 — 동의 이력의 출처가 실제 동의 경로와 일치합니다.
- 쿠키 동의 배너의 항목 이름과 설명이 접속 언어와 상관없이 항상 한국어로 표시되던 문제를 수정했습니다. 이제 보고 있는 언어의 문구가 있으면 그것을 먼저 사용하고, 없을 때만 한국어·영어 순으로 대체합니다.
- 정책 버전 스냅샷 보기에서도 같은 이유로 항목 이름이 한국어로 고정되던 문제를 함께 수정했습니다.
- 화면 테마(밝게/어둡게/시스템 설정) 선택이 저장되지 않던 문제를 수정했습니다. 기능 쿠키에 동의하기 전에는 테마를 바꿔도 새로고침하면 원래대로 돌아갔고, 관리자·사용자 화면 모두 같았습니다. 테마는 사용자가 화면에서 직접 고른 표시 환경이므로 언어 설정과 같은 필수 항목으로 분류해 동의 여부와 무관하게 저장합니다.
- 이에 맞춰 쿠키 동의 안내 문구를 정정했습니다 — 필수 항목 설명에 화면 테마가 포함되고, 기능 쿠키 설명에서는 빠집니다. 이미 설치된 사이트의 저장된 안내 문구도 업데이트 시 함께 정정됩니다(운영자가 직접 고친 문구는 그대로 둡니다).
- 화면 테마와 같은 이유로 사라지던 나머지 항목도 함께 필수로 분류했습니다. 비회원이 주문 후 주문내역을 조회할 때 쓰는 정보, 결제창에서 돌아왔을 때 결제 중단 사유를 서버에 알리는 기록, 본인인증을 마치고 원래 화면·입력 내용으로 복귀하는 데 쓰는 기록, 관리자 화면의 메뉴 접기·목록 필터 표시·닫은 경고·레이아웃 편집기 작업 상태, 그리고 사이트가 자산 주소 형식을 기억해 두는 내부 캐시가 해당합니다. 기능 쿠키 동의 여부와 무관하게 유지됩니다.
- 자동 차단 정책 화면의 차단 도메인 입력칸에 추천 도메인이 나타나지 않던 문제를 수정했습니다. 이미 선택한 도메인만 목록에 다시 보여 추천이 동작하는 것처럼 보였습니다.
- 세션 쿠키 이름을 기본값(`laravel_session`)에서 바꾼 사이트에서, 브라우저 쪽 필수 목록의 세션 쿠키 항목이 실제 쿠키와 이름이 달라 동작하지 않던 문제를 수정했습니다. 이제 서버 설정에서 이름을 읽습니다.
- 쿠키 목록에서는 `이름_*` 형태의 앞부분 매칭이 동작하지 않던 문제를 수정했습니다. 브라우저 저장소 목록과 동일하게 동작합니다.

### Added

- 레이아웃 편집기에서 쿠키 배너를 미리보고 편집할 수 있도록 "쿠키 배너 표시" 화면 상태를 추가했습니다 (배너는 미동의 방문자에게만 나타나 편집기 기본 화면에서는 보이지 않던 영역).
- 오픈 베타 릴리즈
- 쿠키 동의 배너 추가 — 필수/기능/분석/마케팅 4분류, 동의 전 외부 추적 스크립트·iframe 자동 차단 + 기능 카테고리 1st-party 저장소(localStorage·sessionStorage·1st-party 쿠키) 게이팅
- 마이페이지 「쿠키 동의 관리」 카드 추가 — 회원이 자신의 동의 현황을 조회·개별 철회·재동의·전체 일괄 재동의를 한 화면에서 처리
- 동의 이력 영구 저장 — 정책 버전·출처·카테고리 스냅샷을 함께 기록 (GDPR Art.7(1) 입증 자료)
- 관리자 「GDPR 동의 이력」 메뉴 추가 — 회원/게스트 동의 변경 이력 조회 (이메일·세션 검색, 필수/기능/분석/마케팅 카테고리·출처 다중 필터)
- 관리자 정책 버전 수동 발행 — 정책 본문 변경 시 「+ 새 버전 발행」 클릭으로 모든 회원이 다음 방문 시 재동의 진행
- 사용자 노출 영역(쿠키 배너 푸터·마이페이지 동의 카드)에 운영 주체·데이터 저장 위치 한 줄 안내 노출
- 레이아웃 편집기에서 동의 이력 화면을 데이터 있음/없음 상태로 전환해 미리볼 수 있도록 했습니다.
- 레이아웃 편집기 데이터 소스 목록에서 이 확장이 제공하는 데이터 소스가 친화 명칭으로 표시되고, 어느 확장이 제공했는지 출처가 함께 표시됩니다.

### Security

- 동의 전 외부 추적 사전 차단 — 플러그인 로드 직후 즉시 가로채기를 등록하여 동의 정책 응답이 도착하기 전에 추적 스크립트가 외부 로드되는 회귀 방지
- 사용자 완전 삭제 시 동의 이력의 user_id·IP·UA 만 NULL 익명화하여 행 보존 (GDPR Art.17 + Art.7(1) 양립)
- 데이터 저장 위치 입력 시 보안 식별자(IP·CIDR·클라우드 리전 코드) 자동 거부
