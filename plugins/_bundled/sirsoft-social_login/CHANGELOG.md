# Changelog

이 플러그인의 모든 주요 변경사항을 기록합니다.
형식은 [Keep a Changelog](https://keepachangelog.com/ko/1.1.0/)를 따르며,
[Semantic Versioning](https://semver.org/lang/ko/)을 준수합니다.

## [1.0.1] - 2026-11-21

### Changed

- 알림 초기화 확인 창의 [취소] 버튼 글자가 조금 굵어졌습니다. 다른 테두리 버튼과 같은 모양입니다.
- 화면마다 따로 적던 흐린 글자, 버튼, 카드 모양을 이 확장 CSS 의 공통 클래스로 모았습니다. 위에 적은 것 외에는 화면 모양이 같습니다.
- 화면 폭별로 바뀐 클래스만 적는 방식(class-merge)으로 레이아웃을 정리했습니다. 코어 7.2.1 이상이 필요합니다.

## [1.0.0] - 2026-11-20

### Added

- 소셜 로그인 플러그인 최초 릴리즈. 기본 언어는 한국어·영어이고 일본어는 번들 언어팩으로 제공한다. 코어 7.2.0 이상이 필요하다(`g7_version >=7.2.0`)

#### 기본과 제공자

- 소셜 가입 완료 창이 운영자가 환경설정 > 회원에서 정한 가입 항목(연락처, 추가 항목 등)을 코어 가입 화면과 같게 받을 수 있습니다. 가입 창이 항목을 그렸으면 받은 정의 버전(`fields_version`)을 가입 요청에 싣고, 그 요청에는 항목 규칙(필수 포함)이 걸리며 받은 값이 회원에 저장됩니다. 제공자가 준 이름과 닉네임은 항목의 초기값으로 채워집니다(가입 항목 조회 `GET /api/auth/register/fields` 에 `pending_source=sirsoft-social_login`, `pending_token` 을 넘깁니다). 창을 연 뒤 운영자가 항목을 바꿨으면 409(`fields_changed`)로 알립니다. 기본 사용자 템플릿(sirsoft-basic 1.4.0)이 이 창을 그립니다.
- `fields_version` 을 싣지 않는 가입 요청(플러그인에 든 이름, 닉네임, 약관만 받는 창)은 종전과 같은 본문으로 가입됩니다.
- 가입 대기 조회(`GET signup/pending`)의 `missing` 에 운영자가 가입 필수로 둔 회원 항목 가운데 제공자 값으로 채울 수 없는 항목의 키가 함께 실립니다.
- 운영자가 환경설정 > 회원에서 필수로 둔 회원 항목 가운데 가입 완료 창이 받지 않는 항목이 있어도 소셜 가입이 막히지 않습니다. 그렇게 가입한 회원에는 표시가 남아, 처음 로그인했을 때 빠진 항목을 입력하는 화면으로 안내됩니다.
- 소셜 가입의 닉네임이 사이트의 닉네임 정책(중복 금지, 금지어)을 따릅니다. 가입 창에 적은 닉네임과 제공자가 준 닉네임 모두 판정하며, 걸리면 닉네임 칸의 오류로 돌아와 다른 닉네임을 적어 다시 가입할 수 있습니다.
- 운영자가 회원 항목에 「기존 회원에게도 입력 요구」를 켜 추가 정보 입력이 필요한 회원도 소셜 계정 연결 시작과 해제, 본인 재확인(소셜 재로그인)의 시작과 결과 수령은 그대로 할 수 있습니다. 코어가 그런 회원의 쓰기 요청을 막지만, 로그인 수단을 다루는 이 요청들은 코어 필터 `core.required_fields.filter_exempt_routes` 로 열어 둡니다.
- 사이트를 문서 루트 하위 폴더(예: `https://example.com/g7/`)에 설치해도 로그인/가입 버튼의 시작 주소가 설치 폴더 안을 가리키고, 본인 재확인의 복귀 경로는 설치 폴더 기준 화면 경로로 실립니다.
- 화면 폭에 따라 바뀌는 모양은 엔진 responsive 로 정합니다(Tailwind 반응형 접두와 폭 미디어를 품은 의미 클래스를 쓰지 않습니다). 화면 모양은 같습니다.
- 카카오, 네이버, 구글, 페이스북, 일반 OIDC 제공자 연동. 다른 확장은 필터 훅 `sirsoft-social_login.provider.filter_registered` 로 새 제공자를 더할 수 있다(내장 제공자 덮어쓰기는 무시)
- id_token 서명 검증(RS256 고정, JWKS `kid` 선택과 1회 재조회, 발급자·수신자·만료·nonce 검사)
- OAuth 왕복: state 1회성 보관(PKCE, nonce), 같은 출처 복귀 주소만 허용, 콜백 뒤 세션 ID 재발급. 관리자 연결 테스트는 로그인하지 않고 일회용 결과 화면(받은 항목·가입에 빠진 항목·제공자 원본 키 이름, 60초 안에 한 번)을 보여 준다
- 제공자 설정, 회원 연결, 시도 기록, 웹훅 수신 기록 테이블 4종과 내장 제공자 4행 시딩(처음에는 모두 꺼짐)
- 모의 제공자(카카오, 네이버, 구글, 페이스북, OIDC 응답 모양과 변종 9종) — `php artisan sirsoft-social_login:mock --enable --minutes=N` 으로만 켠다(최대 240분). 명령이 알리는 만료 시각은 서버 시간대(UTC)가 아니라 사이트 시간대로 보인다

#### 회원 화면

- 소셜 로그인과 가입: 연결된 회원은 코어 로그인 인계로 비밀번호 로그인과 같은 관문(회원 상태, 2단계 인증, 비밀번호 변경 강제)을 지나 로그인한다. 연결이 없으면 가입 화면의 모달에서 이메일 확인과 약관 동의를 받고 비밀번호 없이 가입한다. 제공자가 이메일을 주지 않으면 인증번호로 확인하거나 메일을 받지 않는 대체 주소로 가입한다(제공자별 설정). 「로그인 거부」로 둔 제공자에서 이메일 제공을 거절한 회원은 로그인 화면의 [이메일 제공 다시 동의하기] 단추로 제공자 동의 화면을 다시 연다(네이버 `auth_type=reprompt`, 페이스북 `auth_type=rerequest`, 구글과 일반 OIDC `prompt=consent`, 카카오는 이메일 동의 항목 추가 요청). 이메일 검증 표시를 주지 않는 네이버와 페이스북은 「항상 믿음」이 기본이라 가입자마다 인증번호를 받지 않는다
- 같은 이메일의 기존 계정이 있으면 비밀번호 또는 그 계정 메일로 받은 인증번호로 확인한 뒤 연결한다(5번 틀리면 처음부터). 사이트 정책을 「검증된 이메일 자동 연결」로 바꾸고 제공자가 확인한 이메일을 믿도록 설정한 제공자에서 그 이메일이 확인된 경우에만 확인 없이 연결한다(기본은 본인확인 후 연결). 「연결하지 않음」 정책이면 다른 이메일로 새로 가입한다
- 로그인, 가입 화면의 제공자 버튼(카카오, 네이버, 구글, 페이스북 브랜드 색과 기호, 카카오는 디자인 가이드대로 가입 화면과 마이페이지 연결, 본인 재확인 버튼에서도 「카카오 로그인」)과 마이페이지 「연결된 소셜 계정」 카드(줄마다 제공자 기호, 연결, 해제). 비밀번호도 없고 연결이 하나뿐이면 해제를 막고 비밀번호 설정을 안내한다(설정으로 허용)
- 마지막 로그인 수단 해제를 사이트가 허용한 경우, 비밀번호 없이 연결이 하나뿐인 회원이 해제하려 하면 확인 창에서 「로그아웃한 뒤에는 비밀번호 찾기로만 다시 들어올 수 있다」고 먼저 알린다. 가입 모달 제목은 제공자 이름을 받지 못해도 「소셜 계정으로 가입」으로 보인다
- 대체 이메일로 가입해 메일도 받을 수 없고 비밀번호도 없는 회원은 연결된 제공자로 다시 로그인해 정보 수정과 비밀번호 첫 설정의 본인 재확인을 통과한다. 정보 수정 화면의 「본인 확인 계속하기」는 먼저 연결한 제공자로 보내고, 소셜 계정을 연결하지 않은 회원에게는 소셜 안내 대신 사이트 기본 안내가 보인다. 코어 본인인증 수단으로 붙고 확인 토큰은 주소에 싣지 않는다. 회사 계정과 소셜 계정을 함께 연결한 회원은 실제 본인 확인 방법이 회사 계정이므로 「소셜 계정으로 다시 로그인」 안내를 보이지 않는다
- 7.1.x 화면으로 만든 옛 템플릿을 쓰는 사이트에서도 로그인, 가입 화면에 제공자 버튼이 보이고 소셜 로그인이 끝난다(코어가 그 화면에 빠진 확장 자리와 로그인 인계를 채운다). 정보 수정과 비밀번호 첫 설정의 재확인 안내는 템플릿 문구 대신 코어 문구(`core.compat.*`)를 써서 옛 템플릿에서도 키 그대로 보이지 않는다
- 소셜 가입에서 인증번호로 확인한 이메일과 제공자가 검증했다고 알린 이메일은 가입 회원의 이메일 인증으로 기록해, 관리자 회원 상세에 「인증」으로 보인다(검증 표시 없이 믿기만 한 이메일과 대체 이메일은 기록하지 않는다)
- 가입 완료와 기존 계정 연결 확인 응답이 코어의 로그인 인계 묶음 쿠키를 함께 보내, 인계 코드는 그 응답을 받은 브라우저에서만 로그인으로 바뀐다(다른 브라우저에 주소를 붙여 넣어도 로그인되지 않는다)
- 사이트 환경설정 「일반 회원가입 받기」를 끄면 소셜 신규 가입도 받지 않는다. 처음 보는 소셜 계정은 로그인 화면에서 「지금은 회원가입을 받지 않습니다」 안내를 보고, 가입 화면을 열어 둔 채 닫혔으면 가입 완료가 거절된다. 이미 연결된 회원의 로그인과 같은 이메일 기존 회원의 연결은 그대로다
- 가입 모달에서 제공자가 확인한 이메일(바꿀 수 없는 줄)이 길어도 좁은 휴대폰 화면에서 줄을 바꿔 보여, 모달 본문이 가로로 밀리지 않는다
- 마이페이지 「다른 계정 연결하기」 제공자 단추가 로그인 화면과 같은 높이(44px)로 보이고, 가입 모달과 기존 계정 확인의 이름, 닉네임, 이메일, 비밀번호 칸은 라벨과 이어져 화면 낭독기가 칸 이름을 읽는다

#### 관리자

- 사이트 전체 정책 설정 화면과 권한 4종(설정 열람·변경, 회원 연결 열람·해제)
- 관리자 설정 화면 「알림」 탭에서 이 플러그인이 보내는 알림 5종을 관리한다. 알림마다 사용 여부와 발송 수단을 정하고, 수단별 제목, 본문, 받는 사람을 편집해 미리 보고 저장하며, 기본값으로 되돌린다. 이 알림들은 사이트 환경설정 「알림 설정」 탭에는 나오지 않으므로 여기가 유일한 관리 화면이다. 「정책」 탭의 가입 급증, 제공자 연속 실패 알림 기준 칸 아래에 알림 탭으로 가는 링크가 있다. 알림 설정 권한이 없는 관리자에게는 권한 안내가 보인다
- 알림 탭에서 템플릿이 없던 발송 수단(예: 관리자 알림의 문자)을 켜고 저장하면 빈 템플릿이 만들어져 [템플릿 편집]으로 채울 수 있고, 채우기 전에는 「채운 뒤 켜야 발송된다」는 안내가 보입니다. 켜기가 거절된 템플릿 스위치는 저장된 상태로 돌아옵니다
- 알림 탭의 템플릿 편집 창에서 제목, 본문, 이동 주소에 지금 없는 회원 항목 변수를 쓰고 저장하면, 저장은 되고 창이 닫히지 않은 채 위쪽 경고 상자에 그 변수가 보입니다. 경고가 보이는 동안 취소 단추는 「닫기」로 바뀌고, 고쳐 다시 저장하면 지난 경고가 지워집니다. 경고가 없으면 창이 닫힙니다. 변수 안내는 이 알림의 변수와 접힌 「회원 항목」 묶음(표시 이름, 회원 항목, 운영자가 더한 항목)으로 나뉩니다
- 관리자 설정 화면이 「제공자」 「정책」 두 탭으로 나뉜다. 제공자 카드마다 Redirect URI 와 웹훅 주소 복사, 자격증명 저장(비밀값은 화면과 응답에 마스크로만 보이고 마스크를 그대로 두면 유지), 연결 테스트(자격증명 오류, 콜백 주소 불일치, 연결 불가를 나눠 안내), 브라우저 로그인 테스트, 표시 순서, 일반 OIDC 추가와 삭제(discovery 주소로 칸 채우기)를 둔다. 켜진 제공자를 끄거나 자격증명을 바꾸면 이 제공자로만 로그인하는 회원 수를 먼저 보이고 확인을 받는다. 자격증명 없이 켜면 막는다
- 제공자 카드 주의사항에 카카오 콘솔 위치(클라이언트 시크릿과 Redirect URI 는 [앱] > [플랫폼 키] > [REST API 키] 화면), 이메일 동의 항목이 없는 카카오 앱에서 「로그인 거부」를 고르면 재동의 단추가 카카오 오류(KOE205)로 끝난다는 안내, 카카오 웹훅 주소 제약(https, 443 포트만)과 네이버 검수 조건(승인 전 테스트 아이디만 로그인, 가입 때 별도 비밀번호를 물으면 반려)을 싣는다. 네이버 프로필 조회가 실패하면 네이버가 준 사유 코드(`024`, `403` 등)를 진단 시도 기록에 남긴다
- 네이버처럼 테스트 요청으로는 자격증명이 맞는지 알려 주지 않는 제공자는 연결 테스트 결과를 「확인할 수 없음」으로 보이고 브라우저 로그인 테스트를 안내한다. 설정 열람 권한만 있는 관리자도 설정 화면을 읽기 전용으로 볼 수 있다. 관리자 회원 상세 「소셜 로그인」 탭은 휴대폰 폭에서 연결마다 세로 카드로 보인다
- 앱 키가 바뀌어 저장된 비밀값을 풀 수 없을 때 화면 전체가 오류로 멈추지 않고 그 제공자 카드에 「다시 입력」 안내가 뜬다. 다시 입력하기 전까지 그 제공자의 로그인과 연결 테스트는 비밀값 없이 요청하지 않고 「비밀값을 풀 수 없음」으로 끝난다. 안내대로 [설정 편집]에서 비밀값을 다시 입력해 저장하면 새 값으로 바뀌고 안내가 사라진다. 다른 칸만 바꿔 저장해도 오류 없이 저장되고, 이미 연결된 회원은 앱 키가 바뀐 뒤에도 그대로 다시 로그인할 수 있다
- 관리자 메뉴 「소셜 로그인」 아래 진단(제공자 상태, 큐, 메일 발송 가능 여부와 최근 실패, 모의 제공자, 연결 회원 수, 최근 웹훅, 시도 기록과 웹훅 이력 필터)과 통계(7, 30, 90일 제공자별 가입, 로그인, 연결, 실패) 화면
- 관리자 회원 상세 「소셜 로그인」 탭(연결 열람, 제공자 사용자 ID 앞 6자만, 마지막 로그인 수단이어도 강제 해제)과 회원 목록 가입경로 필터, 「소셜 연결」 열(열 선택기로 켬). 회원 연결 열람과 해제 권한으로 나뉜다. 회원 주소가 잘못된 상세(없는 회원, 회원 식별자가 아닌 주소)는 찾을 수 없음 화면만 보이고 소셜 연결 목록의 오류 알림을 겹쳐 띄우지 않는다

#### 웹훅과 운영

- 제공자 웹훅 수신: 카카오 연결 끊기(어드민 키, 발신 IP, 관리자 화면에서 넣는 앱 ID 대조), 네이버 연동 해제, 페이스북 권한 해제와 데이터 삭제 요청(확인 코드와 진행 상태 페이지). 서명과 키를 검증하고 같은 알림은 한 번만 처리하며, 연결 해제와 정책별 탈퇴(`webhook_unlink_policy`)는 큐 작업이 맡는다
- 알림 5종(마지막 로그인 수단 해제, 관리자가 연결 해제, 제공자 연속 실패, 가입 급증, 웹훅 처리 실패. 메일 제목에 사이트명이 들어가고, 알림 편집 화면 「사용 가능한 변수」 설명은 화면 언어로 보인다)과 제공자 연속 실패 감시(최근 10분 안 실패가 설정 기준 이상이면 하루 1회 알림, 사이에 성공이 섞여도 셈)
- 보존 기간 정리 배치 `sirsoft-social_login:prune`(매일, `--dry-run` 지원) — 원본 프로필 사본, 시도 기록, 웹훅 이력, 만료된 모의 제공자 표지
- 관리자 계정의 소셜 로그인 차단 설정, 시간당 소셜 가입 급증 알림(`sirsoft-social_login.signup.surge`), 회원 삭제와 탈퇴 시 연결 정리, 회원 응답의 연결 제공자 목록(`social_providers`), 연결, 해제, 가입 활동 기록
- 연결, 해제, 가입 활동 기록의 회원 이름은 코어 환경설정 > 회원의 표시 이름 설정에서 관리자 화면 영역의 이름으로 남습니다(관리자 화면을 닉네임으로 둔 사이트는 닉네임). 이미 남은 기록은 바꾸지 않습니다. 회원에게 가는 알림 2종(마지막 로그인 수단 해제, 관리자가 연결 해제)의 받는 사람 이름(`{name}`)은 코어가 받는 사람과 발송 수단마다 알림 영역의 표시 이름으로 채웁니다. 표시 이름 설정을 바꾸지 않은 사이트는 종전과 같은 이름이 남고 나갑니다

#### 확장과 API

- 확장 훅: 제공자 응답 정규화 필터 `profile.filter_normalized`, 가입 데이터 필터 `signup.filter_registration_data`, 연결 전후 `account.after_link`, `account.before_unlink`, `account.after_unlink`, 로그인과 가입 완료 `auth.after_social_login`, `auth.after_social_signup`
- 제공자 변경과 정책 저장 활동 기록, 확장 훅 `provider.after_create` `provider.after_update` `provider.after_delete` `provider.failing` `account.unlinked_by_admin` `account.unlinked_last_method` `webhook.after_receive` `webhook.failed`(인자에 비밀값 없음)
- 공개 API 와 마이페이지 API 13종, 관리자 API 16종([docs/api/social-login.md](docs/api/social-login.md)). 요청 제한은 라우트마다 따로 센다
- 화면 스타일은 플러그인 자체 CSS 로 싣는다 — 템플릿의 CSS 라이브러리와 무관하게 표시되고, 다크 모드는 템플릿이 선언한 다크 방식을 따른다
- 알림 템플릿 편집 창의 받는 사람에 「사이트 관리자 이메일」(코어 환경설정 > 일반의 관리자 이메일, 메일만)을 고를 수 있습니다(코어 7.2.0).
