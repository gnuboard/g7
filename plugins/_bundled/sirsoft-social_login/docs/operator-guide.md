# 소셜 로그인 — 운영자 가이드

> 제공자 콘솔 등록, 비밀값 관리, 개인정보 처리방침, 상표 고지 · 진입점: [README.md](../README.md)

이 문서는 사이트 운영자가 제공자 앱을 만들고 플러그인을 켜기까지, 그리고 켠 뒤 운영하며 알아야 할 것을 적습니다. 설정 키 하나하나의 의미는 [설정 스키마](settings.md#설정-스키마) 에, 화면 사용 순서는 [README 의 사용 방법](../README.md#사용-방법) 에 있습니다.

## 1. 등록 전에 확인할 것

- 제공자 콘솔에 넣는 주소는 모두 사이트 주소(`.env` 의 `APP_URL`)에서 만들어집니다. 관리자 화면 「플러그인 관리 → 소셜 로그인 설정 → 제공자」 카드에 보이는 주소를 복사해 그대로 붙여 넣으세요. 주소를 손으로 고쳐 적으면 끝의 `/`, `http`/`https`, `www` 차이만으로도 로그인이 실패합니다.
- 운영 사이트는 `https` 여야 합니다. 구글, 페이스북, 일반 OIDC 는 `https` 가 아닌 콜백 주소를 받지 않습니다(개발용 `localhost` 예외는 제공자마다 다릅니다).
- 호스트 이름에 밑줄(`_`)이 들어간 주소는 일부 제공자 콘솔이 거부합니다. 개발 사이트를 실제 제공자와 붙여 볼 때는 밑줄 없는 호스트를 쓰세요.
- **제공자 웹훅(연결 끊기, 연동 해제, 승인 취소, 데이터 삭제 요청)은 큐 워커가 돌아야 처리됩니다.** 웹훅은 받은 즉시 기록만 하고, 회원 연결 정리는 사이트 기본 큐의 작업으로 넘깁니다. 큐 연결(`.env` 의 `QUEUE_CONNECTION`)이 `sync` 가 아니면 `php artisan queue:work` 가 늘 떠 있어야 합니다. 워커가 멈추면 제공자에는 정상 응답(카카오 200, 네이버 204, 페이스북 200)이 나가는데 회원의 연결은 그대로 남습니다. 관리자 「소셜 로그인 → 진단」의 「큐」 카드에서 대기 작업과 이 플러그인 실패 작업 수를, 웹훅 이력에서 「받음」에 멈춘 행을 확인하세요. 처리하다 실패한 웹훅은 처음 시도를 포함해 5번까지 처리합니다. 다시 시도는 30초, 2분, 10분, 30분 간격으로 4번이고, 5번째도 실패하면(처음 실패 뒤 약 43분) 「실패」로 남고 관리자에게 알림이 갑니다.
- 실제 제공자 앱 없이 화면과 흐름을 먼저 보고 싶으면 개발 환경에서 모의 제공자를 켭니다: `php artisan sirsoft-social_login:mock --enable --minutes=30`. 모의 제공자는 서버 명령으로만 켜지고 정한 시간이 지나면 저절로 꺼집니다.

## 2. 제공자별 콘솔 등록

각 카드의 [설정 편집]에서 클라이언트 ID 와 비밀값을 저장한 뒤 [연결 테스트]와 [브라우저로 로그인 테스트]로 확인하고 나서 제공자를 켭니다. 테스트는 로그인하지 않습니다.

### 카카오 (Kakao Developers)

| 항목 | 콘솔에서 할 일 |
|---|---|
| Redirect URI | 카카오 로그인 설정의 Redirect URI 에 카드의 콜백 주소(`…/plugins/sirsoft-social_login/oauth/kakao/callback`)를 등록합니다. 다르면 `KOE006` 이 납니다. |
| Client Secret | 카카오는 Client Secret 을 기본으로 켭니다. 보안 메뉴에서 코드를 발급해 비밀값 칸에 넣으세요(없으면 `KOE010`). |
| 동의 항목 | 닉네임(`profile_nickname`)과 이메일(`account_email`)을 켭니다. 비워 두면 콘솔의 동의 항목 설정을 그대로 씁니다. |
| 비즈 앱 | 이메일을 받으려면 앱을 비즈 앱으로 전환하고 이메일 동의 항목을 설정해야 합니다. 비즈 앱이 아니면 이메일이 오지 않으므로, 카드의 「이메일을 주지 않을 때」 처리를 정해 두세요. |
| 연결 끊기 웹훅 | 연결 끊기 알림 주소에 카드의 웹훅 주소(`…/plugins/sirsoft-social_login/webhooks/kakao`)를 넣고, 카드에 어드민 키와 앱 ID 를 저장합니다. 어드민 키는 웹훅 검증과 회원 연결 해제(권한 회수)에, 앱 ID 는 다른 앱이 보낸 알림을 거르는 데 씁니다. 카카오는 웹훅 주소로 `https`·443 포트만 받으므로, 다른 포트로 운영하는 사이트는 443 으로 받는 주소(리버스 프록시 등)를 따로 두세요. 「웹훅 발신 IP 확인」을 켜면 카카오가 공개한 발신 IP 대역 밖의 요청을 무시합니다(리버스 프록시 뒤라면 신뢰 프록시를 먼저 설정하세요). |

### 네이버 (NAVER Developers)

| 항목 | 콘솔에서 할 일 |
|---|---|
| 서비스 URL, Callback URL | 서비스 URL 은 사이트 주소, Callback URL 은 카드의 콜백 주소를 그대로 등록합니다. |
| 제공 정보 | 이메일, 이름(또는 별명)을 필수나 추가로 고릅니다. 회원이 동의하지 않으면 이메일 없이 돌아옵니다. |
| 검수 | 개발 중 상태에서는 등록한 테스트 아이디만 로그인됩니다. 가입할 때 서비스 고유의 비밀번호를 따로 요구하면 검수에서 반려됩니다 — 이 플러그인은 소셜 가입에서 비밀번호를 묻지 않습니다. |
| 연동 해제 알림 | 연동 해제 알림 주소에 카드의 웹훅 주소(`…/plugins/sirsoft-social_login/webhooks/naver`)를 넣습니다. 서명은 저장한 비밀값으로 검증합니다. |
| 연결 테스트 | 네이버는 틀린 클라이언트 ID·비밀값과 테스트용 가짜 인가 코드를 같은 응답으로 거절해, [연결 테스트]는 「판별할 수 없음」으로 끝납니다. 자격증명은 [브라우저로 로그인 테스트]로 확인하세요. |

### 구글 (Google Cloud Console)

| 항목 | 콘솔에서 할 일 |
|---|---|
| 승인된 리디렉션 URI | OAuth 클라이언트(웹 애플리케이션)의 승인된 리디렉션 URI 에 카드의 콜백 주소를 넣습니다. 글자 하나까지(끝의 `/` 포함) 같아야 합니다. |
| 범위 | `openid`, `email`, `profile` 이 기본입니다. |
| 앱 게시 | 동의 화면이 테스트 상태이면 테스트 사용자로 등록한 계정만 로그인됩니다. 운영 전에 앱을 게시하세요. |
| 웹훅 | 구글은 이 플러그인이 받는 연결 해제 알림이 없습니다. |

### 페이스북 (Meta for Developers)

| 항목 | 콘솔에서 할 일 |
|---|---|
| 유효한 OAuth 리디렉션 URI | 페이스북 로그인 설정에 카드의 콜백 주소를 넣고 Strict Mode 를 켠 채로 둡니다. |
| 권한 | `email`, `public_profile` 이 기본입니다. 이메일 권한은 앱 검수(고급 접근)가 필요할 수 있습니다. |
| 승인 취소 콜백 URL | 카드의 승인 취소 주소(`…/webhooks/facebook/deauthorize`)를 넣습니다. |
| 데이터 삭제 콜백 URL | 앱 기본 설정의 데이터 삭제 콜백 URL 에 카드의 데이터 삭제 주소(`…/webhooks/facebook/data-deletion`)를 넣습니다. 요청을 받으면 회원이 진행 상태를 확인할 주소(`…/plugins/sirsoft-social_login/data-deletion/{확인 코드}`)를 돌려줍니다. |

### 일반 OIDC 제공자

제공자 탭의 [+ 추가]로 최대 10개(정책 탭에서 줄일 수 있음)를 더합니다. IdP 에 카드의 Redirect URI 를 그대로 등록하고, discovery 주소(`…/.well-known/openid-configuration`)를 넣으면 나머지 주소를 채웁니다. discovery 주소와 모든 엔드포인트는 `https` 여야 하며, id_token 은 RS256 서명만 받습니다.

## 3. 비밀값과 앱 키(`APP_KEY`)

- 클라이언트 비밀값과 카카오 어드민 키는 제공자 테이블에 사이트 앱 키(`APP_KEY`)로 암호화해 둡니다. 화면과 응답에는 `••••••••` 로만 보이고, 그대로 두고 저장하면 유지, 비우고 저장하면 지워집니다.
- **`APP_KEY` 를 바꾸면 저장된 비밀값을 더 이상 풀 수 없습니다.** 그 뒤 제공자 목록과 진단 화면은 열리지만 로그인과 연결 테스트는 `credentials_unreadable` 로 멈춥니다. 앱 키를 바꾼 뒤에는 제공자마다 비밀값(과 어드민 키)을 다시 저장하세요. 회원이 연결해 둔 제공자 토큰도 같은 이유로 풀리지 않으므로, 연결 해제 때 제공자 쪽 권한 회수가 실패할 수 있습니다(연결 자체는 지워집니다).
- 비밀값을 이력, 화면 캡처, 문의 글에 붙이지 마세요. 노출됐다면 제공자 콘솔에서 새로 발급하고 다시 저장합니다.

## 4. 이메일을 받을 수 없는 회원

- 제공자가 이메일을 주지 않거나 회원이 동의하지 않으면, 제공자 카드의 「이메일을 주지 않을 때」 설정대로 가입 화면에서 이메일을 직접 받거나(기본, 인증번호 확인), 로그인을 거부하거나, 대체 이메일(`…@social.invalid`)을 발급합니다. 로그인을 거부하면 회원은 로그인 화면에서 그 제공자의 [이메일 제공 다시 동의하기] 단추를 보고, 누르면 제공자 동의 화면이 다시 열립니다(제공자는 같은 사이트의 다음 로그인에 동의 화면을 스스로 다시 띄우지 않습니다).
- **이메일이 없거나 대체 이메일인 회원은 메일 2단계 인증 대상이 아닙니다.** 메일 2단계 인증을 켜 둔 사이트에서도 이 회원은 인증번호 없이 로그인합니다(인증 앱을 등록한 회원은 인증 앱 단계를 거칩니다). 2단계 인증이 꼭 필요한 사이트는 대체 이메일 발급을 고르지 말고 「직접 입력받기」로 이메일을 받으세요.
- 같은 이유로 대체 이메일 회원에게는 알림 메일, 비밀번호 찾기 메일이 가지 않습니다. 이 회원이 정보 수정이나 비밀번호 첫 설정을 할 때의 본인 재확인은 인증번호 대신 연결된 제공자로 다시 로그인하는 것으로 합니다.

## 5. 플러그인이나 제공자를 끌 때

- **플러그인을 비활성화한 동안 들어온 제공자 웹훅(연결 끊기, 연동 해제, 승인 취소, 데이터 삭제 요청)은 받지 않고 버려집니다.** 웹훅 주소가 사라져 제공자에는 404 로 응답하고, 제공자에 따라 다시 보내지 않습니다. 그 사이 제공자 쪽에서 연결을 끊은 회원은 다시 켠 뒤에도 연결이 남아 있으므로, 오래 끈 뒤에는 관리자 회원 상세의 「소셜 로그인」 탭에서 확인하세요. 진단 화면은 플러그인이 켜진 동안만 열리므로 꺼진 동안의 유실을 보여 주지 못합니다.
- 플러그인을 끄면 로그인과 가입 화면의 버튼, 마이페이지 연결 카드, 관리자 회원 화면의 탭과 필터가 사라집니다. 비밀번호 없이 소셜로만 가입한 회원은 그동안 로그인할 수 없으니 미리 비밀번호 찾기로 비밀번호를 설정하도록 안내하세요. 연결 데이터는 지워지지 않고, 다시 켜면 그대로 로그인됩니다.
- 제공자 하나를 끌 때는 카드의 [영향 보기]로 그 제공자로만 로그인하는 회원 수를 먼저 확인하세요.
- 플러그인을 삭제할 때 「데이터 삭제」를 고르지 않으면 4개 표(제공자, 연결, 시도 기록, 웹훅 기록)가 남고, 다시 설치하면 같은 연결로 로그인됩니다.
- 플러그인을 삭제하면 따로 설치한 이 플러그인의 언어팩(예: 일본어 `g7-plugin-sirsoft-social_login-ja`)은 「오류」(대상 확장 없음) 상태가 되고, 다시 설치해도 저절로 켜지지 않습니다. 다시 설치한 뒤 관리자 「언어팩 관리」에서 그 언어팩을 켜거나 `php artisan language-pack:activate g7-plugin-sirsoft-social_login-ja` 를 실행하세요. 비활성화만 했을 때는 다시 켜면 언어팩도 함께 켜집니다.

## 6. 개인정보 처리방침에 적을 항목

소셜 로그인을 켜면 아래 정보를 새로 수집하고 보관합니다. 사이트 개인정보 처리방침에 수집 항목, 목적, 보관 기간, 제3자(제공자)를 적어 두세요.

| 구분 | 항목 | 목적 | 보관 |
|---|---|---|---|
| 연결 정보 | 제공자 이름, 제공자 사용자 ID, 제공자가 준 이메일, 이름, 별명, 프로필 사진 주소, 마지막 로그인 시각 | 회원과 제공자 계정을 이어 로그인 | 연결을 끊거나 탈퇴할 때까지 |
| 제공자 토큰 | 접근 토큰, 갱신 토큰(암호화) | 연결 해제 때 제공자 쪽 권한 회수 | 연결을 끊거나 탈퇴할 때까지 |
| 원본 프로필 | 제공자가 보낸 응답 사본(토큰, 비밀값 제외, 암호화) | 문제 확인 | 정책 탭 「원본 프로필 보존」 기간(기본 14일, 0 이면 저장하지 않음) |
| 시도 기록 | 제공자, 결과, 오류 코드, IP, 브라우저 정보(User-Agent), 시각 | 통계, 장애 진단, 부정 이용 확인 | 정책 탭 「시도 기록 보존」 기간(기본 90일) |
| 웹훅 기록 | 제공자 사용자 ID, 이벤트 종류, 처리 결과(서명, 암호문 제외) | 제공자 연결 해제 요청 처리 | 정책 탭 「웹훅 기록 보존」 기간(기본 90일) |

- 제3자: 회원이 고른 제공자(카카오, 네이버, 구글, 페이스북, 사이트가 추가한 OIDC 제공자)에게서 위 정보를 받습니다. 사이트가 제공자에게 회원 정보를 보내지는 않습니다(권한 회수 요청 제외).
- 보존 기간이 지난 원본 프로필, 시도 기록, 웹훅 기록은 매일 도는 정리 배치(`sirsoft-social_login:prune`)가 지웁니다. 서버 스케줄러가 돌아야 합니다.

## 7. 상표 고지

카카오, Kakao, 네이버, NAVER, Google, Facebook 과 각 로고, 심볼은 각 소유자의 상표입니다. 이 플러그인은 로그인, 가입 버튼과 마이페이지의 연결, 본인 재확인 버튼에만 각 제공자가 로그인 버튼용으로 배포한 공식 심볼을 넣었고(인라인 SVG), 버튼 색과 문구도 각 제공자의 디자인 가이드를 따릅니다. 카카오는 문구를 「카카오 로그인」, Login with Kakao 처럼 정해진 것만 허용하므로 가입 화면과 마이페이지의 연결, 본인 재확인 버튼에서도 「카카오 로그인」으로 보입니다. 플러그인 아이콘(관리자 확장 목록)은 제공자 상표를 쓰지 않은 자체 제작입니다.

| 제공자 | 버튼 디자인 가이드 |
|---|---|
| 카카오 | https://developers.kakao.com/docs/latest/ko/kakaologin/design-guide |
| 네이버 | https://developers.naver.com/docs/login/bi/bi.md |
| 구글 | https://developers.google.com/identity/branding-guidelines |
| 페이스북 | https://developers.facebook.com/docs/facebook-login/userexperience |

버튼 모양을 바꾸는 사이트는 각 가이드가 허용하는 범위(색, 최소 크기, 문구) 안에서 바꾸세요. 가이드를 벗어난 버튼은 제공자 검수에서 반려될 수 있습니다.
