# Changelog

이 프로젝트의 모든 주요 변경사항을 기록합니다.
형식은 [Keep a Changelog](https://keepachangelog.com/ko/1.1.0/)를 따르며,
[Semantic Versioning](https://semver.org/lang/ko/)을 준수합니다.

## [1.1.0] - 2026-10-10

### Added

- 확장 아이콘을 동봉했습니다. 관리자 확장 관리 화면과 설치 마법사에 표시됩니다.
- 환경설정 화면과 주문·결제 조각 5종을 `.g7.html` 마크업 형식으로도 제공합니다. HTML 에 가까운 문법이라 화면 구조를 눈으로 따라가기 쉽고,
  기존 JSON 레이아웃도 그대로 함께 들어 있어 두 표기를 나란히 비교할 수 있습니다. 설치와 업데이트 뒤 화면 복원은 `.g7.html` 을 우선 읽으며(결과는 짝 JSON 과 같습니다), 그 파일만 고쳐도 화면에 반영됩니다.
- NHN KCP 간편결제 수단이 「환불 자동 승인 대상인지」를 쇼핑몰에 알려 줍니다. 결제취소가 즉시 처리되는 수단이므로 환불이 운영자 승인 없이 완료됩니다.
- 쇼핑몰 취소/반품/교환 신청의 추가결제(클레임 결제)를 지원합니다. 신청서의 배송비·상품 차액 결제가 주문 결제와 같은 결제창으로 진행되고, 신청 철회·반려 시 자동으로 환급됩니다.
- 가상계좌 입금 안내·영수증·부가세 내역이 주문 상세뿐 아니라 같은 결제 정보 카드를 쓰는 다른 화면(취소·반품·교환 신청서 상세 등)에서도 표시됩니다. 이미 설치된 사이트는 업데이트 시 예전 등록 정보가 정리되어 같은 안내가 두 번 표시되지 않습니다.
  - 직접 만든 템플릿은 결제 정보 카드에 `mypage_order_payment_provider_slot` 슬롯이 있어야 표시가 붙습니다.

### Changed

#### 가상계좌

- 가상계좌 계좌가 발급되면 주문한 상품을 장바구니에서 정리합니다. 종전에는 입금이 확인될 때까지 장바구니에 그대로 남아 있었습니다.

#### 환불·취소

- 에스크로 결제, 결제한 달이 지난 휴대폰 결제, 입금이 끝난 가상계좌는 취소 화면에서 「전액취소만 가능」으로 먼저 안내합니다.
- 관리자 주문취소의 계약이 바뀌었습니다. 이제 쇼핑몰이 환불신청서를 만들고, 환불이 집행되는 시점에 이 플러그인의 환불 처리가 호출됩니다.

#### 화면 조각·다국어

- 주문 상세·주문 완료·관리자 화면에 붙는 결제 안내를 모두 화면 조각이 그립니다. 종전에는 스크립트가 화면 주소와 제목·버튼 글자로
  자리를 찾아 남의 화면 글자를 고치거나 버튼을 만들어 붙였기 때문에, 다른 언어 화면이나 직접 만든 템플릿에서는 안내가 조용히 빠졌습니다.
  - 관리자 주문 상세: 간편결제로 결제한 주문은 NHN KCP 거래 정보 패널의 「간편결제」 칸에 원 수단(예: 카카오페이)이 표시됩니다.
    쇼핑몰 결제 정보 카드의 결제수단 글자는 더 이상 바꿔 쓰지 않습니다.
  - 내 주문 상세: 테스트 모드 가상계좌 모의입금 도구를 결제 정보 카드 조각이 그립니다. 로그인한 회원의 주문 상세에서만 정보를 요청합니다.
  - 관리자 쇼핑몰 설정 결제수단 목록: 이 플러그인이 브랜드 배지·애플페이 안내를 덧붙이지 않습니다. 브랜드 배지는 결제수단 정보(`brand_mark`)로,
    애플페이 iOS 전용 안내는 결제수단 설명 문구로 제공합니다.
  - 주문서: 애플페이를 iOS 기기에서만 보여 주는 일은 결제수단 정보(iOS 전용 표시)가 맡습니다. 주문 생성 요청을 가로채 막지 않습니다.
- 플러그인 업데이트 뒤 결제 화면 확장을 되살리는 처리가 사용 중단 예정인 훅(`core.plugins.updated`) 대신 정규 훅
  `core.plugins.after_update` 를 구독합니다. 업데이트가 실패로 끝나면 되살리지 않습니다.
- 플러그인 업데이트 후 화면 확장을 복원할 때, 조각 파일 이름을 그대로 조각 식별자로 넘깁니다. 종전에는 식별자 없이
  등록해 대상 화면 이름이 식별자가 됐는데, 설치 경로는 파일 이름을 쓰므로 둘이 갈리면 같은 화면에 조각 행이
  둘 생기고 그 뒤로는 복원이 어느 행인지 가리지 못해 조용히 멈췄습니다. 이제 두 경로가 같은 식별자를 씁니다.

#### 관리자·설정 화면

- 그누보드7 7.0.x 에서 올린 사이트에서 1.0.x 의 관리자 주문 목록 조각 파일이 남아 업데이트 때 다시 등록되고, 관리자 주문 목록의 열을 1.0.x 판으로 통째 덮어 「클레임」 열이 사라지고 결제수단 칸의 결제 배지 자리가 무력화되던 문제를 고쳤습니다. 업데이트가 남은 옛 조각 파일과 그 조각으로 등록된 화면 확장 행을 지웁니다.
- 관리자 주문 목록의 테스트 결제 표시가 이커머스가 결제수단 칸에 열어 둔 자리에 붙습니다. 표시 모양(주황색 「(테스트 결제)」)은 같고, 플러그인 업데이트 뒤에도 이 표시가 함께 되살아납니다.
  - 종전에는 표시 하나를 얹으려고 주문 목록 컬럼 전체를 복사해 덮었기 때문에, 이커머스가 목록을 고쳐도(부분취소 배지·적립 예정 포인트 등) 이 플러그인을 설치한 사이트에는 반영되지 않았고, 결제수단 칸이 다른 결제 플러그인의 테스트 결제 여부까지 읽었습니다.
- 간편결제로 결제한 주문의 관리자 주문 목록 결제수단 이름(예: 「PAYCO (페이코) (신용카드)」)을 화면이 따로 불러오던 표시 맵 대신 주문 목록 응답에 서버가 채워 보냅니다(이커머스 필터 훅 `sirsoft-ecommerce.order.filter_payment_method_display_label` 구독).
- 환경설정 화면의 안내 글자색(라이브 모드 경고, 결제취소 서버 IP 안내, 결제 준비 상태)을 관리자 템플릿의 클래스에 기대지 않고 플러그인이 직접 제공합니다. 관리자 템플릿이 그 클래스의 이름이나 색을 바꿔도 이 화면의 색은 따라 바뀌지 않으며, 다크 모드 색도 함께 갖춥니다.
- 설정 화면의 시스템 점검은 플러그인 설정 수정 권한으로도 볼 수 있고, 결제 모듈 실행 권한 자동 복구는 플러그인 설정 수정 권한이 있을 때만 하고, 권한이 없어 복구하지 않았을 때는 「자동 복구 실패」 대신 그 이유를 알립니다. 점검을 볼 권한이 없으면 빈 카드 대신 이유를 안내합니다.

#### 결제창·주문서

- 결제창은 주문서에서 넘긴 결제수단 또는 서버가 주문에 저장한 결제수단으로만 엽니다. 둘 다 없으면 신용카드로 대신 열지 않고 결제 오류 안내를 띄웁니다.

#### 요구 버전·연동

- 코어 최소 요구 버전을 7.1.0 으로 상향 — 화면 마크업 형식(`.g7.html`)을 읽는 기능이 이 코어부터 제공됩니다.
- sirsoft-ecommerce 최소 버전을 1.3.0 으로 상향 — 주문 목록 결제수단 칸의 표시 자리와 표시 라벨 훅이 1.3.0 에서 도입됐습니다.
- 쇼핑몰(이커머스)이 1.3.0 보다 낮으면 이 플러그인 업데이트를 멈추고 원래 버전으로 되돌립니다. 이커머스를 먼저 업데이트한 뒤 다시 업데이트하세요. 종전에는 이 플러그인만 올라가 결제 화면이 오류로 열리지 않았습니다.
- 테스트 모드 가상계좌 모의입금 정보 API 응답을 공통 형식({ success, message, data })으로 바꿨습니다. 값은 `data` 안에 있고, 조건이 맞지 않으면 종전처럼 404 가 아니라 `data.available` 이 `false` 입니다.
- 영수증 조회 API 응답을 다른 API 와 같은 공통 형식({ success, message, data })으로 바꿨습니다. 영수증 정보는 이제 `data` 안에 들어 있습니다 — 이 API 를 직접 부르던 사용자 정의 화면이나 스크립트는 `data` 에서 값을 읽도록 고쳐야 합니다.
- 결제창 복귀 기록(`g7:sirsoft-pay_nhnkcp:pendingClose`)을 개인정보 동의 플러그인에 필수 저장 항목으로 직접 제공합니다. 그 플러그인은 동의 전
  방문자의 브라우저에서 목록 밖 항목을 지우는데, 지금까지는 그 플러그인이 이 항목 이름을 대신 들고 있었습니다.
  동의 플러그인의 클래스를 참조하지 않으므로 그 플러그인이 없어도 이 플러그인은 그대로 동작합니다.

### Removed

- 관리자 주문 목록용 간편결제 표시 맵 API(`GET /api/plugins/sirsoft-pay_nhnkcp/admin/orders/easy-pay-display-map`)를 제거했습니다. 주문 목록은 이제 이커머스 주문 목록 응답의 결제수단 표시 이름(`payment.payment_method_display_label`)을 그대로 쓰므로 이 API 를 부르는 화면이 없습니다. 쓰는 곳이 없어진 화면 편집기용 데이터 이름 번역(「간편결제 표시 맵」 등)도 함께 걷어냈습니다. 이 API 를 직접 호출하던 외부 연동이 있다면 이커머스 주문 목록 응답의 같은 값을 읽도록 바꿔 주세요.

### Fixed

#### 가상계좌

- 가상계좌 계좌가 발급된 주문의 결제 상태가 「결제대기」로 남아 다른 결제사(입금대기)와 달랐던 것을 「입금대기」로 맞췄습니다. 결제창 닫힘 보고가 계좌 발급보다 늦게 도착하면 발급된 주문이 취소될 수 있던 경로도 막았습니다.
- 마이페이지 주문 상세의 「가상계좌 입금 안내」에 입금 금액이 빠져 있던 것을 보완했습니다. 입금 금액은 마일리지를 뺀 실제 입금액(결제예정금액)으로 보여 줍니다.
- 가상계좌 계좌 기한이 플러그인 설정 「입금 유효기간」으로 정해져 쇼핑몰 「주문 자동취소」 기한·주문서 안내와 따로 놀던 문제를 고쳤습니다. 이제 PC·모바일 결제창 모두 주문의 입금 기한까지로 계좌를 열고, 「입금 유효기간」 설정은 「사용 안 함」으로 표시해 주문에 입금 기한이 없는 예외 경우의 예비값으로만 씁니다.
- 가상계좌 입금 기한이 실제보다 9시간 늦게 저장되어, 주문완료·주문 상세에 기한이 다음 날 아침으로 보이고 기한 만료 처리도 그만큼 늦어지던 문제를 고쳤습니다. 결제사가 알려 주는 한국 시각의 기한을 서버 시각으로 바꾸지 않고 저장하고 있었습니다. 업데이트 전에 발급된 가상계좌의 기한은 바뀌지 않습니다.
- 내 주문 상세·신청서 상세의 결제 정보 카드에 「가상계좌 입금 안내」가 두 번 나오던 문제를 고쳤습니다. 화면 조각과 보조 스크립트가 같은 안내를 각각 그리고 있었습니다. 이제 보조 스크립트 없이 화면 조각 하나만 그립니다.
- 입금을 마친 가상계좌 주문에 「입금 기한 내에 입금하지 않으시면 주문이 자동 취소됩니다.」 경고가 계속 보이던 문제와, 입금 전에 취소한 주문에도 입금 계좌가 그대로 보이던 문제를 고쳤습니다. 이제 경고는 입금 전에만 보이고(주문 상세·신청서 상세·주문 완료), 입금 안내는 취소되지 않은 주문에만 보입니다(주문 상세·신청서 상세).
- 입금 전에 취소한 주문의 가상계좌를 결제사에서 발급 취소합니다. 이전에는 계좌가 열린 채 남아 고객이 취소 뒤에도 입금할 수 있었습니다.

#### 환불·취소

- 입금이 끝난 가상계좌 결제의 환불은 결제사로 보내지 않고 「계좌 환불로 처리해 달라」는 안내를 돌려줍니다. 이전에는 결제사가 가상계좌 취소를 거절해 원인을 알 수 없는 실패로 끝났습니다. 환불 수단을 계좌 환불로 바꾸면 처리됩니다.
- 환불 금액을 결제 통화 최소 단위로 반올림해 보냅니다. 이전에는 소수점 아래를 잘라, 다른 통화로 환산되는 주문에서 1원 적게 환불될 수 있었습니다(토스페이먼츠와 같은 규칙으로 맞췄습니다).
- 복합과세(과세·비과세 상품이 섞인 주문)로 결제한 건을 부분취소하면 과세·부가세·비과세 취소 금액을 나눠 보냅니다. 이전에는 나누지 않고 보내 결제사가 부분취소를 거절하거나 세금 내역이 어긋날 수 있었습니다.
- 부분취소를 여러 번 하면 환불 기록의 결제사 거래번호에 부분취소 일련번호가 붙어 회차별로 구분됩니다.

#### 결제창·주문서

- PC 에서 가상계좌나 계좌이체로 주문해도 NHN KCP 결제창이 신용카드로 열리던 문제를 수정했습니다. 결제창의 결제수단을 주문에 저장된 결제수단으로 정합니다.
- 비회원 주문의 주문 완료 화면에서 [매출전표 불러오기]가 열리지 않던 문제를 수정했습니다. 비회원 주문 조회 인증 정보를 함께 보냅니다.
- 주문 완료 화면에서 매출전표·현금영수증 보기 버튼을 눌러도 영수증이 열리지 않던 문제를 수정했습니다.

#### 화면 조각·다국어

- 가상계좌 발급 정보가 없어 결제를 마치지 못하고 주문서로 돌아올 때, 안내 문구가 화면 언어와 무관하게 「가상계좌 발급 정보 누락」 으로 나오던 문제를 고쳤습니다.
- KRW 외 통화 안내·애플페이 iOS 전용 안내(주문서·관리자 설정)·모바일 승인키 실패·KCP 오류 문구가 일본어 등 다른 언어 화면에서
  한국어나 영어로 나오던 것을 화면 언어로 고쳤습니다. PG 가 돌려준 오류 원문은 그대로 보여 줍니다.
- 영어·일본어 화면의 주문 완료·마이페이지에서 **영수증·현금영수증 조회 버튼과 가상계좌 입금 안내가 한국어로 나오던 문제**를 수정했습니다. 번역을 불러오기 전에도 한국어 고정 문구가 섞이지 않습니다.
- 테스트 모드의 가상계좌 모의입금 도구(입력 이름·「입금통보 테스트」 버튼·관리자 안내)가 영어·일본어 화면에서도 한국어로 나오던 문제를 수정했습니다.
- 한국어·일본어 화면의 주문 상세·주문 완료와 관리자 주문 상세에 붙는 결제수단 표시 이름(간편결제 이름 포함)이 브라우저 기본 언어로 나올 수 있던 문제를 고쳤습니다. 이 정보를 그리던 화면 스크립트의 조회에 화면 언어가 실리지 않았습니다. 이제 화면 조각이 화면 언어로 조회합니다.
- 관리자 주문 상세·마이페이지(비회원 포함) 주문 상세에서 결제수단 표시·영수증·모의입금 안내에 쓰는 결제 조회가 응답을
  기다리지 않고 수십 번 반복 호출되던 문제를 고쳤습니다(호출마다 결제대행사 API 까지 갑니다).
  - 마이페이지는 안내 블록을 하나 붙일 때마다 영수증을 다시 조회하던 것도 함께 고쳤습니다. 이제 한 화면에 들어올 때 주소마다 한 번만 조회하고,
    실패해도 다시 부르지 않으며, 다른 주문으로 옮기면 이전 조회를 멈춥니다.
  - 관리자 주문 상세의 결제수단 표시는 같은 화면이 이미 받아 둔 거래 조회 결과를 그대로 써서, 주문 상세를 열 때마다
    결제대행사 거래 조회가 두 번 나가던 것도 한 번으로 줄였습니다.
- 비회원 주문 상세에서 주문을 불러오는 도중 결제 도구가 먼저 돌아, 다른 결제대행사 주문에도 로그인 전용 모의입금 조회를 보내 401 오류가 나던 문제를 고쳤습니다. 이제 주문을 다 불러온 뒤에 판단하며, 로그인하지 않은 손님에게는 모의입금 조회를 보내지 않습니다.

#### 관리자·설정 화면

- 다른 결제 플러그인과 **함께 설치했을 때** 관리자 주문 목록의 「테스트 결제」 배지가 하나만 보이던 문제를 수정했습니다. 결제사마다 배지를 다는데 나중에 적용되는 쪽이 앞의 것을 덮어써, 우선순위가 가장 높은 한 곳의 배지만 남았습니다. 이제 설치한 결제사 수와 무관하게 각자의 배지가 함께 표시됩니다.
- 관리자 주문 목록에 테스트 결제 배지를 넣는 화면 확장이 목록의 열 전체를 복사해 덮어쓰지 않고 그 열만 덧붙이도록 바뀌었습니다. 종전에는 이 플러그인을 설치하면 쇼핑몰 모듈이 나중에 추가한 열(취소/반품/교환 열 등)이 주문 목록에서 사라졌습니다.
- 다른 결제 플러그인과 함께 설치한 사이트의 관리자 주문 목록에서 이 플러그인으로 간편결제한 주문의 결제수단 이름이 기본 이름(신용카드 등)으로 보이던 문제를 수정했습니다.
- 관리자 주문 상세의 에스크로 배송 등록이 실패하면 이유와 상관없이 「등록에 실패했습니다」만 보이던 문제를 고쳤습니다. 이제 결제대행사가 거절한 사유나 빠진 입력 항목이 그대로 표시되며, 필수 항목을 모두 채우기 전에는 등록 버튼이 눌리지 않습니다.
- 관리자 주문 상세의 결제 조회·플러그인 설정·사용자 주문 상세의 **아이콘이 빈칸으로** 보이던 것을 고쳤습니다. 간편결제
  수단의 대체 아이콘 이름도 Font Awesome 이름으로 바꿨습니다.
- 플러그인 설정의 **시스템 점검** 카드와 에스크로 배송 등록의 택배사 「기타」가 언어를 바꿔도 한국어로 나오던 것을 번역 문구로 바꿨습니다. 영어 화면의 오류·경고 건수는 「1 error」「2 warnings」처럼 개수에 맞게 표시합니다.
  - 시스템 점검 카드는 제목·오류/경고 건수·결제 경로별 동작 여부·「다시 검사」와 항목 줄(「PHP exec() 함수」·「파일 존재」 같은 항목 이름·검사 결과·조치 안내), 결제서버 IP 출처까지 화면 언어로 나옵니다.
- 환경설정을 저장하다 실패했을 때 어떤 항목이 잘못됐는지 표시되지 않던 문제를 수정했습니다. 이제 항목별 오류 안내가 나옵니다.
- 환경설정 화면에서 항목 이름·설명과 입력칸이 나란히 놓이지 않고 위아래로 쌓이던 문제와, 섹션 제목이 오류 안내처럼 붉은 작은 글자로
  보이던 문제를 수정했습니다. 저장 오류 상자의 제목과 목록 글자도 각자의 오류 안내 색으로 맞췄습니다.
- 환경설정에서 다크 모드의 입력칸 포커스 테두리와 경고 상자 안 링크의 호버 색이 적용되지 않던 문제를 수정했습니다.
- 환경설정 「결제 실패 시 이동 주소」 안내가 실제 기본값(상점 주소 설정을 따르는 `{shopBase}`)과 다르게 「상대 경로 또는 전체 URL」 로만 안내되던 문구를 바로잡았습니다.
- 플러그인 설정을 바꿀 권한이 없는 관리자에게 설정 화면이 입력할 수 있는 상태로 열려 저장할 때에야 거절되던 문제를 고쳤습니다. 이제 「읽기 전용」 안내와 함께 입력·저장 버튼이 잠깁니다.
- 관리자 주문 상세의 에스크로 배송 등록 입력·버튼이 주문 수정 권한 없이도 열려 거절되던 문제를 고쳤습니다.

#### 결제 보안

- **취소된 주문이 뒤늦은 가상계좌 입금으로 되살아나지 않습니다.** 이제 취소된 주문의 입금통보는 주문을 건드리지 않습니다.
  - 가상계좌 입금통보에 취소 확인 절차가 없어, 만료 자동취소된 주문에 뒤늦게 입금이 들어오면 그 주문이 결제완료로 되살아나면서 재고와 마일리지가 한 번 더 차감되었습니다.
  - 취소된 주문에 온 입금 통보는 기록하고 운영자에게 알립니다.
- 설정 화면의 결제 후 이동 주소(성공·실패)에 「not a url」 같은 아무 글자나 저장돼, 결제를 마친 구매자가 깨진 주소로 보내지던 문제를 고쳤습니다. 이제 `{shopBase}`·`/`·`http(s)://` 로 시작하지 않거나 공백이 있는 주소, 다른 사이트로 보내는 `//주소`·`javascript:` 는 칸별 오류로 저장되지 않습니다.

### Security

- 결제창을 닫았다는 보고를 주문한 본인만 보낼 수 있게 했습니다. 이전에는 주문번호·결제 금액·주문자 이메일과 전화번호만 알면 로그인 없이도 결제 진행 중인 남의 주문을 취소시킬 수 있었습니다. (KISA 측에서 제보해주셨습니다 — KVE-2026-2434)
  - 이제 회원 주문은 주문한 회원의 로그인으로, 비회원 주문은 주문할 때 브라우저가 받은 조회 확인값으로만 보고를 받으며, 주문자 연락처는 더 이상 보내지도 확인하지도 않습니다. 결제 실패로 돌아온 비회원 화면은 조회 확인값을 되살린 뒤 보고합니다.
  - 확인에 실패한 보고는 주문을 전혀 건드리지 않고, 결제를 끝내지 않은 주문은 종전처럼 결제 대기 만료 정리가 처리합니다.
- 결제에 실패한 주문을 같은 주문번호로 다시 결제할 수 있게 되돌리는 요청도 주문한 본인만 보낼 수 있게 했습니다. 이전에는 주문자 연락처만 알면 남의 취소된 주문을 결제 대기 상태로 되살릴 수 있었습니다. (KISA 측에서 제보해주셨습니다 — KVE-2026-2434)
- 결제 승인과 가상계좌 발급의 금액을 서버 간 승인 응답으로만 확정합니다. 브라우저가 보낸 금액과 거래번호는 더 이상 결제 확정의 근거로 쓰지 않습니다.
  - 승인 요청에 주문 청구액을 함께 보내 NHN KCP 가 결제창 금액과 대조하게 하고, 승인 응답의 금액이 청구액과 다르거나 비어 있으면 승인분을 자동으로 취소하고 결제완료로 처리하지 않습니다.
  - PC 가상계좌는 발급 금액이 맞지 않으면 발급된 계좌를 취소하고 계좌 정보를 저장하지 않습니다.
- 결제 결과 화면으로 보내는 이동 주소와 NHN KCP 에 넘기는 복귀 주소를 요청의 Host 헤더가 아니라 사이트 주소로 만듭니다. 모바일 결제 승인 요청에 담겨 온 복귀 주소는 더 이상 따르지 않고 사이트의 콜백 주소를 씁니다.
  - 결제창 폼은 NHN KCP 의 https 주소로만 제출되고, 영수증 창은 열린 창이 결제 화면을 조작하지 못하게 엽니다.
  - 가상계좌 입금통보·에스크로 공통통보에 형식이 틀린 요청이 오면 직전 화면으로 이동시키지 않고 422 오류로 응답합니다.

## [1.0.4] - 2026-09-06

### Fixed

- 비회원으로 결제하신 손님이 주문완료 화면과 비회원 주문 상세 화면에서 영수증 버튼과 결제수단 표시를 볼 수 없던 문제를 고쳤습니다. 서버는 비회원 주문을 확인해 줄 준비가 되어 있었는데 화면이 확인값을 함께 보내지 않아 조회 자체가 되지 않았고, 오류 메시지도 남지 않아 원인을 알기 어려웠습니다.

### Security

- 모바일 가상계좌 결제에서 제3자가 입금 계좌를 자기 계좌로 바꿔치기할 수 있던 문제를 수정했습니다. 모바일은 결제사가 계좌 정보를 브라우저를 거쳐 그대로 전달하는 방식이라, 주문번호만 아는 사람이 위조한 계좌 정보를 보내면 그 주문의 입금 계좌가 바뀌어 구매자가 엉뚱한 곳으로 입금할 수 있었습니다. 이제 결제창을 열 때 본인 확인을 거쳐 발급한 일회용 확인값을 결제사를 통해 되돌려 받아 대조하며, 확인값이 없거나 맞지 않는 요청은 주문을 전혀 건드리지 않고 결제 화면으로 되돌립니다. 확인값은 한 번 쓰면 소멸하므로 같은 값을 다시 보내도 통하지 않습니다. PC 결제는 종전처럼 결제사 서버 확인을 거칩니다. 업데이트를 적용하는 순간 이미 결제창이 열려 있던 모바일 가상계좌 결제 건은 확인값이 없어 실패로 처리되므로, 결제가 몰리지 않는 시간에 적용하시고 적용 직후 결제 실패 건이 있으면 확인해 주세요. (KISA 측에서 제보해주셨습니다 — KVE-2026-2019)
- 결제창 프로그램을 불러오는 주소가 NHN KCP 의 주소인지 불러오기 직전에 확인합니다. 확인되지 않는 주소면 결제를 진행하지 않고 안내를 표시합니다.
- 제3자가 남의 주문번호만 알면 결제창을 거치지 않고도 그 주문을 취소시킬 수 있던 문제를 수정했습니다. 결제 결과 콜백은 로그인도 서명 확인도 거치지 않는 경로여서, 위조한 결제 정보를 보내 승인을 일부러 실패시키면 그 주문이 결제 실패로 처리되었습니다. 이제 실제 결제 승인이 이루어진 뒤의 실패만 주문에 반영하며, 승인 전 단계의 실패는 결제 화면으로 되돌려 보내기만 합니다. 구매자가 결제창을 닫아 생기는 정상적인 결제 실패는 종전처럼 기록됩니다. (KISA 측에서 제보해주셨습니다 — KVE-2026-2018)
- 같은 결제 결과 콜백에서 가상계좌 경로를 통해서도 남의 주문을 건드릴 수 있던 문제를 수정했습니다. 결제수단을 가상계좌라고 주장하는 값을 요청에 섞으면, 카드로 주문한 건도 결제사 확인을 거치지 않는 경로로 흘러 그 주문이 취소되거나 위조된 입금 계좌가 그 주문에 기록될 수 있었습니다. 이제 결제수단은 요청에 실려 온 값이 아니라 주문에 저장된 값으로만 판단하며, 가상계좌 발급이 확인되지 않은 경우에는 주문을 그대로 두고 결제 화면으로 되돌려 보냅니다.
- 취소된 주문을 다시 결제 대기 상태로 되돌리는 처리가, 결제사 승인이 확인되기 전에 이루어지던 문제를 수정했습니다. 주문번호만 알면 남의 취소된 주문을 되살릴 수 있었습니다. 이제 승인이나 계좌 발급이 확인된 뒤에만 되돌립니다.
